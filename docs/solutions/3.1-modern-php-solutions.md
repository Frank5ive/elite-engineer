## Section 7 Retrieval practice: answers

1. At request end, the engine frees all variables, objects and static properties and closes non-persistent DB connections (shared-nothing). Another request cannot see them, and may run in a different worker process; so a permission cache must be in an external store (APCu per-host, Redis, DB) with explicit invalidation.
2. `0 == "hello"` false (PHP 8); `"1e1" == "10"` true; `null == 0` true; `"abc" == "ABC"` false; `[] == false` true (all run; the first, third and fifth lines of the lesson table agree). Dangerous in auth: the numeric-string and null/false cases (`"0e..." == "0e..."`, `null == 0`, `[] == false`), since attacker-controlled values can collapse into equal "falsy/numeric" values.
3. Scalar parameter, return and typed-property declarations are no longer coerced for calls made from that file (`int` accepted for `float`); violations throw `TypeError`. It does not change `==`, array-key normalization or string interpolation, and does not make the callee's own file strict. It must be the first statement in the file (before `namespace`).
4. `src/Repo/SqlRepository.php`. Failure reasons: wrong case in file name on Linux; `composer.json` prefix missing trailing `\\`; autoloader not required (`vendor/autoload.php`); namespace line in the file differs from the directory; `dump-autoload` not run after changing `composer.json`.
5. Prints `23`, then `bool(true)`: arrays copy on assignment (copy-on-write) while object assignment copies the handle.
6. `from` throws `ValueError` on an unknown value; `tryFrom` returns `null`. Use `from` where invalid data indicates a bug or corruption (reading from the DB), `tryFrom` when invalid input is expected and you will produce a validation message.
7. Readonly is shallow. `final class A { public function __construct(public readonly ArrayObject $o) {} }` then `$a->o['x'] = 1;` mutates the held object without touching the property. (The lesson's own example would be an `ArrayObject` or any mutable object.)
8. Placeholders bind values, not identifiers or keywords. Choose the column from an allowlist map in code (`['name' => 'name', 'date' => 'created_at']`) and interpolate only the mapped literal; restrict direction to `ASC`/`DESC` by comparison.
9. `htmlspecialchars($v, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`. Inside `<script>` the browser parses JS, not HTML entities: a value must be serialized with `json_encode` (with `JSON_HEX_*` flags) and `</script>` sequences neutralized; HTML-escaping gives wrong data and still permits injection in some positions.
10. `switch` compares loosely and falls through unless `break`; `match` compares strictly, is an expression, has no fall-through and throws `UnhandledMatchError` when no arm matches.
11. `^2.3` means `>=2.3.0 <3.0.0`; `~2.3.0` means `>=2.3.0 <2.4.0`.
12. `install` installs exactly what `composer.lock` records; `update` re-resolves constraints and rewrites the lock. CI runs `install` for reproducibility.

## Section 8 Independent challenge: reference solution

Run with `php -d zend.assertions=1 -d assert.exception=1 challenge.php` (executed; prints `ok`).

```php
<?php
declare(strict_types=1);

namespace Drill;

use InvalidArgumentException;

enum Role: string
{
    case Student = 'student';
    case Teacher = 'teacher';
    case Admin = 'admin';

    public function canGrade(): bool
    {
        return match ($this) {
            self::Teacher, self::Admin => true,
            self::Student => false,
        };
    }
}

final class User
{
    public function __construct(
        public readonly int $id,
        public readonly string $name,
        public readonly Role $role,
    ) {
        if (trim($name) === '') {
            throw new InvalidArgumentException('name must not be empty');
        }
    }
}

interface Clock
{
    public function now(): int;
}

final class FixedClock implements Clock
{
    public function __construct(private int $t) {}
    public function now(): int { return $this->t; }
}

final class Session
{
    public function __construct(private readonly Clock $clock, private readonly int $ttl) {}

    public function issue(User $u): string
    {
        return bin2hex(random_bytes(16)); // 32 hex chars; $u would be bound server-side in a real store
    }

    public function verify(string $token, string $candidate): bool
    {
        return hash_equals($token, $candidate);
    }

    public function isExpired(int $issuedAt): bool
    {
        return $this->clock->now() - $issuedAt >= $this->ttl;
    }
}

function render(string $name): string
{
    $e = htmlspecialchars($name, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
    return '<p class="name" title="' . $e . '">' . $e . '</p>';
}

// proofs
$s = new Session(new FixedClock(1000), 60);
assert(!$s->verify('0e462097431906509019562988736854', '0e830400451993494058024219903391'));
assert(strlen($s->issue(new User(1, 'A', Role::Student))) === 32);
assert(!str_contains(render('<script>alert(1)</script>'), '<script'));
try { new User(1, '  ', Role::Student); assert(false); } catch (InvalidArgumentException) {}
try { Role::from('root'); assert(false); } catch (\ValueError) {}
assert($s->isExpired(900) && !$s->isExpired(950));
assert(render('" onmouseover="x') === '<p class="name" title="&quot; onmouseover=&quot;x">&quot; onmouseover=&quot;x</p>');
echo "ok\n";
```

Trade-offs and alternatives:
- `canGrade` uses `match` so adding a case without handling it fails loudly. Alternative: a constant set of roles; shorter but not exhaustive.
- Token storage is intentionally absent: `verify` compares a presented token to the stored one. A real design stores a hash of the token server-side (so a DB leak does not leak live sessions) and compares `hash_equals(hash('sha256', $given), $storedHash)`. Mention of this in your answer earns the "senior" mark.
- `render` escapes once and reuses the same escaped string in the attribute and body; this is correct because both contexts are HTML-with-quoted-attribute. A URL attribute (`href`) would need a different treatment (scheme allowlist plus encoding); say so.
- `isExpired` uses `>=` so a token is dead at exactly the TTL boundary; whichever you choose, test the boundary.

Scoring: five requirements x 2 points, four proofs x 2 points, explanation 2 points (20 total; pass 16).

## Section 9 Project: reference approach

Layout: `src/{Grade,Status,GradeRepository,PdoGradeRepository,GradeNotFound,HtmlSummary}.php`, `tests/*Test.php`. The lesson's worked example contains executable versions of `Grade`, `Status`, `GradeRepository`, `PdoGradeRepository` (the `save`/`findByStudent` flow was run on PHP 8.4.27 with SQLite). Remaining pieces:

```php
// publish(): idempotent by decision: publishing an already published grade succeeds with no change.
public function publish(int $id): void
{
    try {
        $st = $this->pdo->prepare("UPDATE grades SET status = :s WHERE id = :id");
        $st->execute(['s' => Status::Published->value, 'id' => $id]);
        if ($st->rowCount() === 0 && !$this->exists($id)) {
            throw new GradeNotFound("grade $id not found");
        }
    } catch (\PDOException $e) {
        throw new \RuntimeException('could not publish grade', 0, $e);
    }
}

private function exists(int $id): bool
{
    $st = $this->pdo->prepare('SELECT 1 FROM grades WHERE id = :id');
    $st->execute(['id' => $id]);
    return $st->fetchColumn() !== false;
}
```

Why `exists()`: an UPDATE that sets the same value reports 0 affected rows on some engines (MySQL reports changed rows by default), so `rowCount() === 0` alone cannot distinguish "missing" from "unchanged". This is exactly the kind of engine-dependent behavior to document in `DECISIONS.md` (php.net's pdo_mysql page lists `PDO::MYSQL_ATTR_FOUND_ROWS` (its effect on `rowCount()` is not described on that page, so read the Pdo\Mysql::ATTR_FOUND_ROWS docs); SQLite, which I ran, reports 1 for an unchanged matching row. Confirm on your target DB).

```php
public function countByStatus(): array
{
    $out = [];
    foreach ($this->pdo->query('SELECT status, COUNT(*) AS n FROM grades GROUP BY status') as $r) {
        $out[Status::from($r['status'])->value] = (int) $r['n'];
    }
    return $out;
}
```

`HtmlSummary::row` should build `<tr><td>` cells from `htmlspecialchars` outputs and format percent with `number_format($g->percent(), 1)`; test with an exact expected string.

Alternatives: (a) Doctrine DBAL instead of raw PDO: a dependency; justify only if the team already uses it. (b) Public readonly properties vs getters: properties are simpler and sufficient with `readonly`. (c) Storing floats for percent: rejected; derive.

Rubric scoring notes (100): deduct 10 immediately for any concatenated SQL (also a critical failure), 10 for a missing XSS test, 5 for tests using `assertEquals` where `assertSame` fits, 5 for missing README commands. A solution that passes all tests but has unexplained `DECISIONS.md` loses up to 10.
