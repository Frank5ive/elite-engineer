## Retrieval practice answers

1. Monitoring watches known failure conditions and alerts; observability is being able to ask new questions of a running system from its telemetry. (a) A metric (latency histogram over time, compare to yesterday). (b) Logs (the request's structured lines by request id), possibly plus its trace. (c) A trace (spans per downstream call show which dominates).
2. Each distinct label value is a separate time series; the raw path embeds ids. For `/users/{id}` with 100,000 users, 100,000 series *per metric per status per method* (and a histogram multiplies by its bucket count, e.g. 100,000 x 11 buckets for one latency histogram, before the other labels). The metrics backend runs out of memory or the bill explodes, and attackers can create unbounded series with random paths. Use the route template; map unmatched to one label.
3. RED: Rate, Errors, Duration, for request-driven services. USE: Utilization, Saturation, Errors, for resources. Names: `http_requests_total{method,route,status}` (rate and errors by filtering status) and `http_request_duration_seconds` histogram. USE examples: DB pool connections checked out / pool size (utilization) and number of callers waiting for a connection (saturation); also outbox backlog age, threadpool in-use, event-loop lag.
4. Averages hide the tail: 99 requests at 50 ms and one at 10 s averages ~150 ms while one user in a hundred is suffering. Alert on a high percentile (p95 or p99) of the latency histogram against the SLO, and on error ratio, over a window (ideally as burn-rate against an error budget).
5. Failing liveness: the orchestrator kills and restarts the container. Failing readiness: the instance is removed from the load balancer's endpoints, not killed. If liveness checks the DB, a DB outage makes every replica fail and be restarted simultaneously, adding a restart storm and thundering reconnect to an already-sick dependency while fixing nothing; that check belongs in readiness.
6. (1) Mark not-ready so new traffic stops; wait briefly for the LB to notice; (2) stop accepting new connections; (3) let in-flight requests finish up to a bound; (4) drain background work and close pools/clients/log handlers; (5) exit before the platform's grace period ends. Readiness first because the load balancer still sends traffic to an instance until it observes not-ready; if the server stops accepting first, those requests get connection errors.
7. Shell form (`CMD uvicorn ...`) runs `/bin/sh -c "uvicorn ..."`; the shell is PID 1 and (for many shells) does not forward `SIGTERM` to its child, so uvicorn never starts graceful shutdown and gets `SIGKILL` after the grace period. Exec form makes uvicorn PID 1 so it receives the signal. (Shell-dependent; confirm with `ps` inside the container.)
8. A module global is shared by every request, so concurrent requests overwrite each other. A `ContextVar` has a value per execution context: each asyncio task gets a copy of the context at creation, and AnyIO's thread dispatch copies it into the worker thread, so each request's id stays its own. (Exercise 8.1 demonstrates the cases.)
9. CLOSED (calls pass; N consecutive failures open it), OPEN (calls fail immediately; after the cooldown it becomes half-open), HALF-OPEN (one probe is allowed; success closes, failure reopens and restarts the cooldown). Count timeouts/connection errors/5xx because they indicate dependency trouble; a 400 means the caller sent a bad request, and counting it would let a buggy client trip the breaker for everyone.
10. Any three: closed-loop generator suffers coordinated omission, understating tail latency; generator and server share a laptop's CPU and network stack; the data size, DB, caches, network path and instance class differ from production; no warm-up discarded; one run (no variance); instrumentation/logging config differs; a single endpoint with identical requests is cache-friendly and unrealistic; 40 clients is not a realistic arrival process (open-loop arrivals matter).
11. Percentiles are not additive: the p99 of the union is not the mean of per-replica p99s (replicas may carry different traffic volumes and distributions). Export histograms with the same bucket boundaries, sum bucket counts across replicas, then compute the quantile (in Prometheus: `histogram_quantile(0.99, sum by (le) (rate(..._bucket[5m])))`, the form shown in the Prometheus histogram docs).

(The lesson has ten questions; answer 11 above is a bonus matching the percentile aggregation point.)

```python
def bg_sync(): SEEN["bg_sync"] = request_id_var.get()
async def bg_async(): SEEN["bg_async"] = request_id_var.get()

@app.get("/x")
async def x(bt: BackgroundTasks, _=Depends(sync_dep)):
```

Findings: the id is visible in a sync dependency (AnyIO copies the context into the worker thread), in `asyncio.create_task` children (a task copies the current context when created), and in `BackgroundTasks` (they run inside the ASGI call after the response is sent, so the middleware's `finally` has not yet reset the var). Where it is lost: raw `threading.Thread`/`concurrent.futures` pools you create yourself (copy the context explicitly with `contextvars.copy_context().run`); tasks that outlive the request and are created after reset; separate processes; and background work started on a different loop. Using `BaseHTTPMiddleware` can break contextvars propagation (stated in the Starlette middleware docs); this is one reason the lesson uses a pure ASGI middleware.

## Exercise 8.2: readiness with real dependencies (reference)

```python
import asyncio, time
from collections.abc import Awaitable, Callable
from fastapi import FastAPI, Request, Response

Check = Callable[[], Awaitable[None]]      # raises on failure

class Readiness:
    def __init__(self, critical: dict[str, Check], optional: dict[str, Check],
                 timeout: float = 1.0, ttl: float = 2.0, clock: Callable[[], float] = time.monotonic):
        self.critical, self.optional, self.timeout, self.ttl, self.clock = critical, optional, timeout, ttl, clock
        self._lock = asyncio.Lock(); self._cached: tuple[float, dict] | None = None

    async def _run(self, name: str, fn: Check) -> dict:
        t0 = time.perf_counter()
        try:
            await asyncio.wait_for(fn(), self.timeout); ok = True
        except Exception:
            ok = False
        return {"name": name, "ok": ok, "ms": round((time.perf_counter() - t0) * 1000, 1)}

    async def report(self) -> dict:
        async with self._lock:                         # one probe does the work; the herd reuses it
            if self._cached and self.clock() - self._cached[0] < self.ttl:
                return self._cached[1]
            crit = await asyncio.gather(*[self._run(n, f) for n, f in self.critical.items()])
            opt = await asyncio.gather(*[self._run(n, f) for n, f in self.optional.items()])
            rep = {"ready": all(c["ok"] for c in crit), "critical": crit, "optional": opt}
            self._cached = (self.clock(), rep)
            return rep

def install(app: FastAPI, readiness: Readiness) -> None:
    @app.get("/readyz")
    async def readyz(request: Request, response: Response):
        if not getattr(request.app.state, "ready", False):
            response.status_code = 503
            return {"ready": False, "reason": "starting or shutting down"}
        rep = await readiness.report()
        if not rep["ready"]: response.status_code = 503
        return rep
```

```python
import asyncio, httpx
from fastapi import FastAPI
from ready import Readiness, install

def build(db_check, opt_check=None):
    app = FastAPI(); app.state.ready = True
    r = Readiness({"db": db_check}, {"cache": opt_check} if opt_check else {}, timeout=0.2)
    install(app, r); return app

async def get(app):
    async with httpx.AsyncClient(transport=httpx.ASGITransport(app=app), base_url="http://t") as c:
        return await asyncio.gather(*[c.get("/readyz") for _ in range(50)])

async def test_cache_limits_db_checks():
    n = 0
    async def db(): 
        nonlocal n; n += 1
    rs = await get(build(db)); assert all(r.status_code == 200 for r in rs) and n == 1

async def test_slow_db_times_out():
    async def db(): await asyncio.sleep(5)
    rs = await get(build(db)); assert rs[0].status_code == 503 and rs[0].json()["critical"][0]["ok"] is False

async def test_optional_failure_does_not_fail():
    async def ok(): pass
    async def bad(): raise RuntimeError
    r = (await get(build(ok, bad)))[0]
    assert r.status_code == 200 and r.json()["optional"][0]["ok"] is False

async def test_503_when_shutting_down():
    async def ok(): pass
    app = build(ok); app.state.ready = False
    assert (await get(app))[0].status_code == 503
```

Design notes: the lock means 50 concurrent probes trigger one check run; the cache TTL bounds DB load to one check per 2 s regardless of probe frequency; `wait_for` bounds each check; optional checks are reported but never fail readiness; `app.state.ready` handles startup/shutdown. Trade-off: a cached "ready" can be up to 2 s stale, which is acceptable for a probe. Alternative: a background task updates a status variable on an interval and the endpoint only reads it (probes become O(1) and never touch dependencies; but a stuck updater makes the status stale, so include the timestamp and treat staleness as not-ready).

```python
"""Shutdown drill. Usage: python drill.py slow:app   (module:app exposing GET /slow taking 3 s)"""
import signal, subprocess, sys, threading, time, urllib.request, urllib.error

def main(target: str, port: int = 8777) -> int:
    proc = subprocess.Popen([sys.executable, "-m", "uvicorn", target, "--port", str(port),
                             "--timeout-graceful-shutdown", "10", "--log-level", "warning"])
    base = f"http://127.0.0.1:{port}"
    for _ in range(50):
        try: urllib.request.urlopen(base + "/openapi.json", timeout=1); break
        except Exception: time.sleep(0.2)
    result: dict = {}
    def inflight():
        try: result["status"] = urllib.request.urlopen(base + "/slow", timeout=20).status
        except Exception as e: result["status"] = repr(e)
    t = threading.Thread(target=inflight); t.start()
    time.sleep(1); t0 = time.time(); proc.send_signal(signal.SIGTERM)
    time.sleep(0.5)
    try: urllib.request.urlopen(base + "/openapi.json", timeout=1); new = "accepted"
    except Exception as e: new = "refused/failed: " + type(e).__name__
    t.join(); code = proc.wait(timeout=15)
    print(f"in-flight={result['status']} new-after-SIGTERM={new} exit={code} drained_in={time.time()-t0:.1f}s")
    return 0 if result["status"] == 200 and code in (0, -signal.SIGTERM) else 1   # uvicorn re-raises SIGTERM after draining

if __name__ == "__main__":
    sys.exit(main(sys.argv[1]))
```

Observed on my machine with uvicorn 0.54.0: the in-flight request returned 200, a new connection after `SIGTERM` was refused, and the process ended with Python `returncode == -15`, i.e. uvicorn drained and then re-terminated itself with the signal (so "exit 0" is not what this version reports on the host; re-run confirmed `-15`, while under `docker stop` the container exit code was 0; decide what your orchestrator treats as success; Kubernetes records a non-zero termination but it does not matter once the pod is being deleted). For the shell-form comparison, wrap launch in `sh -c "python -m uvicorn ..."`: whether the shell forwards the signal depends on the shell (some `exec` the last command automatically); observe `ps` output and write what you saw rather than what I predicted.

```python
# Python 3.12+, fastapi, prometheus-client
from __future__ import annotations
import contextvars, json, logging, sys, time, uuid
from contextlib import asynccontextmanager
from fastapi import FastAPI, Request, Response
from prometheus_client import CONTENT_TYPE_LATEST, Counter, Histogram, generate_latest
from starlette.types import ASGIApp, Message, Receive, Scope, Send

request_id_var: contextvars.ContextVar[str] = contextvars.ContextVar("request_id", default="-")

class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        doc = {"ts": self.formatTime(record, "%Y-%m-%dT%H:%M:%S"), "level": record.levelname,
               "logger": record.name, "msg": record.getMessage(), "request_id": request_id_var.get()}
        extra = getattr(record, "fields", None)
        if extra: doc.update(extra)
        if record.exc_info: doc["exc"] = self.formatException(record.exc_info)
        return json.dumps(doc)

def configure_logging(level: str = "INFO") -> None:
    h = logging.StreamHandler(sys.stdout); h.setFormatter(JsonFormatter())
    root = logging.getLogger(); root.handlers[:] = [h]; root.setLevel(level)

log = logging.getLogger("app")

REQS = Counter("http_requests_total", "Requests", ["method", "route", "status"])
LAT = Histogram("http_request_duration_seconds", "Latency", ["method", "route"],
                buckets=(0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5))

class RequestContextMiddleware:
    """Pure ASGI middleware: request id, access log, RED metrics."""
    def __init__(self, app: ASGIApp) -> None: self.app = app
    async def __call__(self, scope: Scope, receive: Receive, send: Send) -> None:
        if scope["type"] != "http":
            return await self.app(scope, receive, send)
        headers = dict(scope["headers"])
        rid = headers.get(b"x-request-id", b"").decode()[:64] or uuid.uuid4().hex
        token = request_id_var.set(rid)
        status = 500; start = time.perf_counter()
        async def send_wrapper(message: Message) -> None:
            nonlocal status
            if message["type"] == "http.response.start":
                status = message["status"]
                message["headers"] = [*message["headers"], (b"x-request-id", rid.encode())]
            await send(message)
        try:
            await self.app(scope, receive, send_wrapper)
        finally:
            dur = time.perf_counter() - start
            route = scope.get("route")
            tmpl = getattr(route, "path", "unmatched")   # template, NOT raw path: bounded cardinality
            REQS.labels(scope["method"], tmpl, str(status)).inc()
            LAT.labels(scope["method"], tmpl).observe(dur)
            log.info("request", extra={"fields": {"method": scope["method"], "path": scope["path"],
                     "route": tmpl, "status": status, "duration_ms": round(dur * 1000, 2)}})
            request_id_var.reset(token)

@asynccontextmanager
async def lifespan(app: FastAPI):
    configure_logging()
    app.state.ready = True
    yield
    app.state.ready = False          # shutdown: stop advertising readiness first
    log.info("shutting down")

app = FastAPI(lifespan=lifespan)
app.add_middleware(RequestContextMiddleware)

@app.get("/healthz")                 # liveness: process is not wedged. No dependency checks.
def healthz(): return {"status": "ok"}

@app.get("/readyz")                  # readiness: can I serve traffic right now?
def readyz(request: Request, response: Response):
    if not request.app.state.ready:
        response.status_code = 503; return {"status": "not ready"}
    return {"status": "ready"}

@app.get("/items/{item_id}")
def item(item_id: int):
    log.info("fetching item", extra={"fields": {"item_id": item_id}})
    return {"id": item_id}

@app.get("/metrics")
def metrics(): return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)
```

Circuit breaker and tests:

```python
import time
from collections.abc import Callable

class CircuitOpen(Exception): ...

class CircuitBreaker:
    """closed -> open (after N consecutive failures) -> half-open (after cooldown) -> closed/open."""
    def __init__(self, failure_threshold: int = 5, cooldown: float = 10.0,
                 clock: Callable[[], float] = time.monotonic) -> None:
        self.threshold, self.cooldown, self.clock = failure_threshold, cooldown, clock
        self.failures, self.opened_at, self.probing = 0, None, False

    def before_call(self) -> None:
        if self.opened_at is None: return
        if self.clock() - self.opened_at < self.cooldown: raise CircuitOpen
        if self.probing: raise CircuitOpen          # only one probe in half-open
        self.probing = True

    def on_success(self) -> None:
        self.failures, self.opened_at, self.probing = 0, None, False

    def on_failure(self) -> None:
        self.failures += 1; self.probing = False
        if self.failures >= self.threshold or self.opened_at is not None:
            self.opened_at = self.clock()
```

```python
import pytest
from breaker import CircuitBreaker, CircuitOpen

class Clock:
    t = 0.0
    def __call__(self): return self.t

def test_cycle():
    clk = Clock(); b = CircuitBreaker(3, 10, clk)
    for _ in range(3): b.before_call(); b.on_failure()
    with pytest.raises(CircuitOpen): b.before_call()
    clk.t = 11; b.before_call()                       # half-open probe allowed
    with pytest.raises(CircuitOpen): b.before_call()  # second concurrent probe refused
    b.on_failure()                                    # probe failed -> open again
    with pytest.raises(CircuitOpen): b.before_call()
    clk.t = 22; b.before_call(); b.on_success()
    b.before_call()                                   # closed again
```

Load generator (closed-loop; for learning only; accepts `URL [concurrency] [seconds]`):

```python
"""Tiny closed-loop load generator. Python 3.12+, httpx. Usage: python load.py URL [concurrency] [seconds]"""
import asyncio, sys, time, statistics, httpx

async def worker(client, url, deadline, lat, errors):
    while time.perf_counter() < deadline:
        t0 = time.perf_counter()
        try:
            r = await client.get(url)
            if r.status_code >= 500: errors.append(r.status_code)
        except httpx.HTTPError as e:
            errors.append(type(e).__name__)
        lat.append(time.perf_counter() - t0)

async def main(url, conc=10, secs=5):
    lat, errors = [], []
    async with httpx.AsyncClient(timeout=5, limits=httpx.Limits(max_connections=conc)) as c:
        deadline = time.perf_counter() + secs
        await asyncio.gather(*[worker(c, url, deadline, lat, errors) for _ in range(conc)])
    q = statistics.quantiles(lat, n=100)          # q[49]=p50, q[94]=p95, q[98]=p99
    print(f"requests={len(lat)} errors={len(errors)} rps={len(lat)/secs:.0f}")
    print(f"p50={q[49]*1000:.1f}ms p95={q[94]*1000:.1f}ms p99={q[98]*1000:.1f}ms max={max(lat)*1000:.1f}ms")

if __name__ == "__main__":
    a = sys.argv
    asyncio.run(main(a[1], int(a[2]) if len(a) > 2 else 10, float(a[3]) if len(a) > 3 else 5))
```

## Project 2.7 reference notes

- **Logging:** one module `app/observability.py` holding the formatter, context var, middleware and metric objects; startup log prints version/SHA and non-secret settings. Sanitize inbound ids with a regex (`^[A-Za-z0-9._-]{1,64}$`; otherwise generate a fresh id) to cover empty, huge and newline-containing values; test all three.
- **Outbound propagation:** an `httpx.AsyncClient` event hook (`event_hooks={"request": [add_request_id]}`) sets `X-Request-ID` from the context var.
- **USE gauges:** a pool gauge via `Gauge.set_function(lambda: engine.pool.checkedout())` (`QueuePool` method, checked; for async engines call it on `async_engine.sync_engine.pool`; note prometheus-client multiprocess mode does not support `set_function` gauges) and an outbox-age gauge computed from a query run at scrape time with a short cache.
- **Disconnects:** if the client disconnects mid-response Starlette may raise; your status variable defaults to 500, which will count as an error; decide whether to record 499-style statuses, and document it.
- **Docker/compose:** `compose.yaml` with `postgres` (healthcheck `pg_isready`), the service `depends_on: condition: service_healthy`, env from `.env` that is git-ignored, and `stop_grace_period` matching `--timeout-graceful-shutdown` plus a margin. Test: `docker compose up -d`, curl `/readyz`, `docker compose stop postgres` and confirm `/readyz` 503 with `/healthz` 200 (Compose v5 on the authoring machine; `depends_on: condition: service_healthy` is supported by current Compose).
- **Load report skeleton:** environment (CPU, RAM, instance type, Python/uvicorn versions, workers), dataset size, tool and version, arrival model (closed vs open), warm-up discarded, ramp steps, per-step table (offered rate, achieved rate, p50/p95/p99, error rate), saturation observation (what hit its limit: pool, CPU, threads), limitations, one change made and re-measured. Numbers must come from your runs.
- **Runbook example (alert: p99 above SLO for 10 min):** check recent deploy; check per-route breakdown; check DB pool saturation and slow queries (2.3 EXPLAIN); check dependency breaker state; rollback criteria; escalation.
