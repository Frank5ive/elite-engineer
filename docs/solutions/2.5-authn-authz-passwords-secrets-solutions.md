## Retrieval practice answers

1. **401** = authentication missing or invalid ("who are you?"); prefer it for absent/invalid credentials and send `WWW-Authenticate`. **403** = authenticated but not permitted; prefer it for capability checks the user may legitimately know exist (admin-only route) and for clear UX. **404** = hide existence; prefer for per-object access where confirming that id 17 exists leaks information (BOLA enumeration). Whatever you choose, apply it consistently so "missing" and "forbidden" are indistinguishable where hiding is the goal.
2. (a) A salt stops precomputation and shared-hash detection but not *speed*: SHA-256 is designed to be fast, so a GPU tests enormous numbers of guesses per second; the work factor is the defense. (b) SHA-256 has no memory hardness or tunable cost, so you cannot raise the cost as hardware improves; no embedded parameters, so no migration path. (Also: hand-rolled salting schemes are easy to get wrong.)
3. Otherwise an unknown user returns faster than a known user with a wrong password (no hashing done), letting an attacker enumerate valid usernames by response time. Verifying against a dummy hash equalizes the work. Pair with identical response bodies.
4. If the verifier derives the algorithm from the token header, an attacker can switch an RS256 token to HS256 and sign with the server's *public* key (known) as the HMAC secret; the verifier then uses the public key as an HMAC key and the forged signature validates. Prevention: `algorithms=["RS256"]` (a fixed list) on `jwt.decode`.
5. The user can use admin privileges for up to 5 more minutes if the role is trusted from the token. Reduce by: loading role from the DB each request (a lookup you probably do anyway for `active`); shorter TTL; a deny-list keyed by `jti`/user version number checked on each request; or refresh-token indirection so revocation happens at refresh.
6. With no `algorithms=` PyJWT 2.x refuses to decode (it raises `DecodeError`: "It is required that you pass in a value for the algorithms argument" checked on PyJWT 2.15.1: `DecodeError: It is required that you pass in a value for the "algorithms" argument when calling decode().`). The fix is `jwt.decode(token, public_key, algorithms=["RS256"], audience=..., issuer=...)`; also pass `options={"require": [...]}`.
7. **False.** Each hash call generates a fresh random salt, so outputs differ. You cannot compare hashes with `==`; you call `hasher.verify(password, stored_hash)`, which extracts the salt and parameters from the stored string and compares in constant time.
8. App creates a random `code_verifier` and sends `code_challenge = SHA256(verifier)` and a random `state` in the authorization redirect; the user authenticates at the IdP; the IdP redirects back with a `code` and the same `state`; the app checks `state` equals what it stored, then POSTs `code` + `code_verifier` to the token endpoint, and the IdP verifies SHA256(verifier) equals the earlier challenge. `state` protects against CSRF on the redirect (forged callbacks). `code_verifier` (PKCE) protects against authorization-code interception: a stolen code is useless without the verifier.
9. RBAC answers "may this role perform this kind of action", not "may this subject touch this particular object". `GET /notes/{id}` is allowed for role `user`, and the check passes for every user, but note 17 belongs to someone else. Authorization must also include a per-object ownership/relationship predicate.
10. State is per instance (N instances multiplies the limit and clients can spread across them); state is lost on restart/deploy; behind a proxy all requests may share one source IP unless you handle forwarded headers correctly (and trusting them blindly lets attackers spoof); memory grows with distinct keys unless evicted; no shared view for global limits. Use gateway limits or a shared store.

## Exercise 8.1: scoped repository (reference)

Approach: the actor travels with every call; the predicate is part of the SQL; a single exception type covers missing and forbidden; `update_note` uses a conditional `UPDATE ... WHERE id AND owner_id` and checks `rowcount` so there is no read-then-write race and the admin edit rule is explicit.

```python
from __future__ import annotations
from dataclasses import dataclass
from sqlalchemy import ForeignKey, String, create_engine, select, update
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column

class Base(DeclarativeBase): pass

class Note(Base):
    __tablename__ = "notes"
    id: Mapped[int] = mapped_column(primary_key=True)
    owner_id: Mapped[str] = mapped_column(String(36), index=True)
    text: Mapped[str]

@dataclass(frozen=True)
class Actor:
    id: str
    role: str = "user"

class NotFound(Exception):
    """Raised for both 'missing' and 'not yours' so callers cannot tell them apart."""

def get_note(s: Session, actor: Actor, note_id: int) -> Note:
    q = select(Note).where(Note.id == note_id)
    if actor.role != "admin":
        q = q.where(Note.owner_id == actor.id)            # scoped IN SQL
    note = s.scalars(q).one_or_none()
    if note is None:
        raise NotFound
    return note

def list_notes(s: Session, actor: Actor, limit: int = 50, after_id: int = 0) -> list[Note]:
    q = select(Note).where(Note.id > after_id).order_by(Note.id).limit(min(limit, 100))
    if actor.role != "admin":
        q = q.where(Note.owner_id == actor.id)
    return list(s.scalars(q))

def update_note(s: Session, actor: Actor, note_id: int, text: str) -> None:
    # admin may read everything but edit only their own notes: explicit rule
    res = s.execute(update(Note).where(Note.id == note_id, Note.owner_id == actor.id).values(text=text))
    if res.rowcount != 1:
        raise NotFound
```

Trade-offs and alternatives:

- Alternative 1: load then check (`if note.owner_id != actor.id: raise`). Simpler to read and lets you return 403 vs 404, but the row is loaded and a missed check leaks it; weaker by construction.
- Alternative 2: PostgreSQL Row-Level Security with a per-request `SET LOCAL app.user_id`. Enforcement at the database even if a developer forgets a predicate; costs operational complexity, connection-pool care (the setting must be transaction-scoped) and testing in a real PostgreSQL. Read the PostgreSQL Row Security Policies docs before adopting (table owners and superusers bypass RLS unless forced).
- Alternative 3: a query-builder helper `owned_by(actor, Note)` returning a base `select`; reduces repetition. Good once you have more than three models.
- Scoring notes (10 points): scoping in SQL 3; same exception for missing/forbidden 2; admin read-not-write rule explicit and tested 2; all-pairs parametrized test 2; limit cap / cursor pagination 1. Deduct heavily if any method accepts a raw id without actor.

## Exercise 8.2: password policy (reference)

```python
def validate_password(pw: str, username: str, breached: frozenset[str] = frozenset()) -> list[str]:
    if len(pw) > 128:
        return ["too_long"]                    # return before any further work or hashing
    v = []
    if len(pw) < 12: v.append("too_short")
    if pw.lower() == username.lower(): v.append("equals_username")
    if pw in breached: v.append("breached")
    return v
```

Key point: the length cap returns *before* anything else so a 10,000-character body never reaches the hasher. Tests are in the combined file below. Alternative: enforce the cap in the Pydantic model (`Field(max_length=128)`) so FastAPI rejects it with 422 before your handler runs; do both (defense in depth). Breached-password check: in production use a k-anonymity range query (Have I Been Pwned Pwned Passwords range API; checked: `GET https://api.pwnedpasswords.com/range/<first 5 SHA-1 hex chars>` answers 200 without a key; read the current terms before relying on it) or an offline list; never send full passwords or full hashes to a third party.

## Exercise 8.3: key rotation (reference)

```python
import jwt
class KeyRing:
    def __init__(self, keys: dict[str, str], current: str):
        self.keys, self.current = keys, current
    def sign(self, claims: dict) -> str:
        return jwt.encode(claims, self.keys[self.current], algorithm="HS256", headers={"kid": self.current})
    def verify(self, token: str, **kw) -> dict:
        kid = jwt.get_unverified_header(token).get("kid")
        key = self.keys.get(kid) if kid else None
        if key is None:
            raise jwt.InvalidTokenError("unknown kid")     # missing/unknown kid: reject, never try all keys
        return jwt.decode(token, key, algorithms=["HS256"], **kw)
```

```python
import pytest, jwt, time
from rot import KeyRing
from policy import validate_password

C = {"sub": "u", "exp": int(time.time()) + 60}
def test_rotation():
    old = KeyRing({"k1": "a" * 32}, "k1"); t = old.sign(C)
    ring = KeyRing({"k1": "a" * 32, "k2": "b" * 32}, "k2")
    assert ring.verify(t)["sub"] == "u"                  # retired-but-listed key still verifies
    assert jwt.get_unverified_header(ring.sign(C))["kid"] == "k2"
    ring.keys.pop("k1")
    with pytest.raises(jwt.InvalidTokenError): ring.verify(t)
def test_missing_kid():
    t = jwt.encode(C, "a" * 32, algorithm="HS256")
    with pytest.raises(jwt.InvalidTokenError): KeyRing({"k1": "a" * 32}, "k1").verify(t)
@pytest.mark.parametrize("pw,exp", [("a"*11,["too_short"]),("a"*12,[]),("a"*128,[]),("a"*129,["too_long"]),("Alice-Alice",["too_short"]),("x"*10000,["too_long"])])
def test_policy(pw, exp): assert validate_password(pw, "bob") == exp
def test_policy_username(): assert "equals_username" in validate_password("Administrator1", "administrator1")
```

Decisions: unknown or missing `kid` is rejected (never "try every key", which makes verification cost and confusion unbounded and blurs trust); the algorithm is still fixed; signing always uses `current`; retiring = removing from the map after the longest token TTL has elapsed. The `kid` is untrusted input used only as a dictionary key. Alternative: asymmetric keys with a JWKS document and `PyJWKClient`-style caching, needed when other services verify.

## Token bucket reference

```python
import time
from collections.abc import Callable

class TokenBucket:
    def __init__(self, rate: float, capacity: int, clock: Callable[[], float] = time.monotonic):
        self.rate, self.capacity, self.clock = rate, capacity, clock
        self.tokens, self.last = float(capacity), clock()
    def allow(self, cost: float = 1.0) -> bool:
        now = self.clock()
        self.tokens = min(self.capacity, self.tokens + (now - self.last) * self.rate)
        self.last = now
        if self.tokens >= cost:
            self.tokens -= cost; return True
        return False
```

`app25.py`:

```python
# Python 3.12+, fastapi, pyjwt, pwdlib[argon2]
from __future__ import annotations
import os, time, uuid
from typing import Annotated
import jwt
from fastapi import Depends, FastAPI, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from pwdlib import PasswordHash

JWT_SECRET = os.environ["JWT_SECRET"]          # fail at startup if missing
JWT_ALG = "HS256"
ACCESS_TTL = 15 * 60

hasher = PasswordHash.recommended()            # Argon2id by default
# Pre-computed hash used to equalize timing when the user does not exist.
DUMMY_HASH = hasher.hash("not-a-real-password")

# "database": replaced by SQLAlchemy in the project
USERS: dict[str, dict] = {}
NOTES: dict[int, dict] = {}

def create_token(user_id: str, role: str) -> str:
    now = int(time.time())
    claims = {"sub": user_id, "role": role, "iat": now, "exp": now + ACCESS_TTL,
              "jti": uuid.uuid4().hex, "iss": "elite-api", "aud": "elite-web"}
    return jwt.encode(claims, JWT_SECRET, algorithm=JWT_ALG)

oauth2 = OAuth2PasswordBearer(tokenUrl="/token")

def current_user(token: Annotated[str, Depends(oauth2)]) -> dict:
    try:
        claims = jwt.decode(
            token, JWT_SECRET,
            algorithms=[JWT_ALG],                      # never read alg from the token
            audience="elite-web", issuer="elite-api",
            options={"require": ["exp", "sub", "iss", "aud"]},
        )
    except jwt.PyJWTError:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "invalid token",
                            headers={"WWW-Authenticate": "Bearer"})
    user = USERS.get(claims["sub"])
    if user is None or not user["active"]:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "invalid token",
                            headers={"WWW-Authenticate": "Bearer"})
    return user                                        # role comes from DB, not the token

CurrentUser = Annotated[dict, Depends(current_user)]

def require_role(*roles: str):
    def dep(user: CurrentUser) -> dict:
        if user["role"] not in roles:
            raise HTTPException(status.HTTP_403_FORBIDDEN, "forbidden")
        return user
    return dep

app = FastAPI()

@app.post("/token")
def login(form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    user = USERS.get(form.username)
    stored = user["pw"] if user else DUMMY_HASH
    ok = hasher.verify(form.password, stored)
    if not (user and ok and user["active"]):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "bad credentials")
    return {"access_token": create_token(user["id"], user["role"]), "token_type": "bearer"}

def get_note_for(user: dict, note_id: int) -> dict:
    note = NOTES.get(note_id)
    # 404, not 403, so we do not confirm that other users' ids exist
    if note is None or (note["owner"] != user["id"] and user["role"] != "admin"):
        raise HTTPException(status.HTTP_404_NOT_FOUND, "note not found")
    return note

@app.get("/notes/{note_id}")
def read_note(note_id: int, user: CurrentUser):
    return get_note_for(user, note_id)

@app.delete("/admin/users/{uid}", dependencies=[Depends(require_role("admin"))])
def delete_user(uid: str):
    USERS.pop(uid, None)
    return {"deleted": uid}
```

## Project 2.5 reference notes

Not a full implementation; the design the rubric expects:

- **Schema:** `users(id uuid pk, email citext unique, pw_hash text, role text check in ('user','admin'), active bool, created_at)`, `notes(id, owner_id fk, text, ...)`, `note_shares(note_id fk, grantee_id fk, unique(note_id, grantee_id))`, `refresh_tokens(id, user_id fk, family_id uuid, token_hash char(64) unique, used_at, revoked_at, expires_at)`, `auth_events(id, user_id null, kind, ip, ts, detail jsonb)`.
- **Refresh rotation:** token = `secrets.token_urlsafe(32)`; store `sha256` hex (a fast hash is acceptable because the input has 256 bits of entropy; passwords need slow hashing because they have low entropy). On refresh: `UPDATE refresh_tokens SET used_at = now() WHERE token_hash = :h AND used_at IS NULL AND revoked_at IS NULL AND expires_at > now()`; `rowcount == 1` means success, then insert a new token in the same family. If the hash exists but `used_at` is set, that is reuse: revoke the family (`UPDATE ... SET revoked_at = now() WHERE family_id = :f`) and write an `auth_events` row. Concurrent double-refresh: exactly one wins; the loser is indistinguishable from reuse, which is why many systems allow a short grace window; document your choice.
- **Sharing:** read access query is `owner_id = :uid OR EXISTS (share)`; write access owner-only; test A08 and A09.
- **Share-to-nonexistent-user:** returning the same 204 for both avoids user enumeration but confuses legitimate users; a defensible choice is to require email-verified invitations. Document either.
- **Rate limiting tests:** inject the clock; assert the 6th attempt within the window gets 429 with `Retry-After`; assert a different IP+username has an independent bucket.
- **Startup check:** `JWT_SECRET` length >= 32 and not in a deny-list; test by running `Settings()` with env cleared.
- **Repo scan test:** a pytest that walks tracked files (via `git ls-files`) and regex-matches `(?i)(secret|password|api[_-]?key)\s*=\s*['"][^'"]{8,}['"]` outside test fixtures; allow-list known test constants explicitly rather than skipping directories.
