## Section 7: Retrieval practice answers

1. **Safe**: the client does not request or expect a change in server state (GET, HEAD, OPTIONS, TRACE). **Idempotent**: N identical requests have the same intended effect on server state as one. PUT is idempotent but not safe. POST is neither (and PATCH is not guaranteed idempotent).
2. Yes, it is idempotent. The guarantee is about resulting server state, not the response: after one or two calls item 9 is absent. The differing status is allowed, though some teams return 204 both times so a retrying client cannot misread a 404.
3. After a read timeout the client does not know whether the server processed the request. For a non-idempotent POST, a retry may duplicate the effect (double charge). Make it retry-safe with an idempotency key: the client sends a unique `Idempotency-Key`; the server stores key plus request fingerprint plus result, and replays the stored response for a repeat (Lesson 2.6).
4. (a) 401 + `WWW-Authenticate`. (b) 403. (c) 412 (and 428 if the header was absent and you require it). (d) 409 (conflict with existing state); 422 is a defensible alternative only if you declare it for validation-style uniqueness; document whichever. (e) 422 with problem+json naming `limit` (or clamp to 100 and document; rejecting is more explicit). (f) 405 + `Allow: GET, POST`.
5. `no-cache` allows storing but requires revalidation with the origin before reuse. `no-store` forbids storing the response at all. Use `no-store` for sensitive data.
6. `Location` is missing. The client cannot discover the new resource's URI without guessing or parsing the body, and generic HTTP tooling cannot follow it.
7. `304 Not Modified`, no body, and the response must still carry the validators (`ETag`, and `Cache-Control` if relevant).
8. The envelope can grow (`next_cursor`, `total`, `warnings`) without breaking clients, whereas changing a top-level array into an object is a breaking change.
9. Compatible: add an optional response field; add a new endpoint; add an optional request field with a default that preserves behaviour. Breaking: rename or remove a field; change a field's type or units; make an optional request field required (or tighten validation); change default sort/page size; change a status code.
10. `type`, `title`, `status`, `detail`, `instance`. Branch on `type` (or `status` when type is `about:blank`), never on `detail`.
11. (i) Concurrent insert/delete shifts rows between pages: a row is skipped or seen twice. Fix: keyset pagination on a total order. (ii) Non-deterministic order when `created_at` ties: rows with identical timestamps may swap positions between requests. Fix: add a unique tiebreaker (`ORDER BY created_at, id`). (A third: deep offsets get slow; fix is keyset.)
12. PUT supplies the complete representation for a specific URI, so repeating it converges on the same state. `POST /items` asks the server to create *a new* resource each time; the second call creates a second resource (unless an idempotency mechanism intervenes).

## Section 4/8: Challenge reference solution (`loans_server.py`)

Tested with Python 3.13 and with the `conformance.sh` below (`ALL PASSED`).

Reference approach and why:

- One `_dispatch` for every method. It first resolves the route, then checks method membership in `allow` to produce a route-specific `Allow` header (the common bug is a single global Allow list).
- `_read_json` always drains the body *before* checking content type; if you return early without reading, a keep-alive connection is left with unread bytes and the next request parses garbage.
- Validation rejects `bool` for int fields explicitly, since `isinstance(True, int)` is `True` in Python.
- Cursors encode `{"id": last_id}`; because ordering is by unique `id`, the cursor needs no tiebreaker. An invalid cursor yields 422.
- PUT is "replace existing only" (404 if absent) because the spec says PUT requires `If-Match`, which presupposes an existing version. Alternative: allow PUT-create with `If-None-Match: *`. Both are valid; the choice must be documented.
- Order of PUT checks: 415/400 first (cannot read request), then 404, then 428/412 (precondition on current state), then 422 validation. Alternative ordering (validate before preconditions) is defensible; RFC 9110 section 13.2.2 describes when preconditions are evaluated relative to other checks, VERIFY if you need to cite it. Document your order.

```python
"""Reference solution, Lesson 2.1 challenge. Python 3.12+, stdlib only."""
import base64
import hashlib
import json
import re
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

LOANS: dict[int, dict] = {i: {"id": i, "book_id": 100 + i, "member": f"m{i}"} for i in range(1, 26)}
NEXT_ID = 26
ITEM_RE = re.compile(r"^/loans/(\d+)$")
FIELDS = {"book_id": int, "member": str}
MAX_LIMIT, DEFAULT_LIMIT = 50, 10


def is_valid_value(value, typ) -> bool:
    return isinstance(value, typ) and not (typ is int and isinstance(value, bool))


def validate_loan(data) -> list[dict]:
    if not isinstance(data, dict):
        return [{"loc": ["body"], "msg": "must be a JSON object"}]
    errs = [{"loc": ["body", k], "msg": "missing or wrong type"}
            for k, t in FIELDS.items() if k not in data or not is_valid_value(data[k], t)]
    errs += [{"loc": ["body", k], "msg": "unknown field"} for k in data if k not in FIELDS]
    return errs


def etag_of(item: dict) -> str:
    return '"' + hashlib.sha256(json.dumps(item, sort_keys=True).encode()).hexdigest()[:16] + '"'


def parse_query(qs: str) -> dict[str, str]:
    out = {}
    for part in filter(None, qs.split("&")):
        k, _, v = part.partition("=")
        out[k] = v
    return out


class Handler(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"

    def log_message(self, *a):  # quiet
        pass

    def _send(self, status, payload=None, headers=None, ctype="application/json"):
        body = b"" if payload is None else json.dumps(payload).encode()
        self.send_response(status)
        if payload is not None:
            self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(body)))
        for k, v in (headers or {}).items():
            self.send_header(k, v)
        self.end_headers()
        if self.command != "HEAD":
            self.wfile.write(body)

    def _problem(self, status, title, detail=None, headers=None, **extra):
        body = {"type": "about:blank", "title": title, "status": status, "instance": self.path}
        if detail:
            body["detail"] = detail
        body.update(extra)
        self._send(status, body, headers, ctype="application/problem+json")

    def _read_json(self):
        """Return (ok, data). Writes the error response itself when not ok."""
        ctype = self.headers.get("Content-Type", "").split(";")[0].strip().lower()
        length = int(self.headers.get("Content-Length") or 0)
        raw = self.rfile.read(length)           # always drain the body to keep the connection usable
        if ctype != "application/json":
            self._problem(415, "Unsupported Media Type", "Use application/json")
            return False, None
        try:
            return True, json.loads(raw)
        except json.JSONDecodeError:
            self._problem(400, "Malformed JSON")
            return False, None

    def _route(self):
        path, _, qs = self.path.partition("?")
        if path == "/loans":
            return "collection", None, parse_query(qs), "GET, HEAD, POST"
        m = ITEM_RE.match(path)
        if m:
            return "item", int(m.group(1)), {}, "GET, HEAD, PUT"
        return None, None, {}, ""

    def _dispatch(self):
        kind, lid, query, allow = self._route()
        if kind is None:
            return self._problem(404, "Not Found", "No such route")
        if self.command not in allow.replace(" ", "").split(","):
            return self._problem(405, "Method Not Allowed", headers={"Allow": allow})
        getattr(self, f"_{kind}_{self.command.lower()}")(lid, query)

    do_GET = do_HEAD = do_POST = do_PUT = do_DELETE = do_PATCH = do_OPTIONS = _dispatch

    # ---- collection
    def _collection_head(self, _, query):
        self._collection_get(_, query)

    def _collection_get(self, _, query):
        errs, limit, last_id = [], DEFAULT_LIMIT, 0
        if "limit" in query:
            if re.fullmatch(r"\d+", query["limit"]) and 1 <= int(query["limit"]) <= MAX_LIMIT:
                limit = int(query["limit"])
            else:
                errs.append({"loc": ["query", "limit"], "msg": f"integer 1..{MAX_LIMIT}"})
        if query.get("after"):
            try:
                last_id = int(json.loads(base64.urlsafe_b64decode(query["after"]))["id"])
            except Exception:
                errs.append({"loc": ["query", "after"], "msg": "invalid cursor"})
        if errs:
            return self._problem(422, "Validation failed", errors=errs)
        rows = [r for r in sorted(LOANS.values(), key=lambda r: r["id"]) if r["id"] > last_id]
        page = rows[:limit]
        nxt = None
        if len(rows) > limit:
            nxt = base64.urlsafe_b64encode(json.dumps({"id": page[-1]["id"]}).encode()).decode()
        self._send(200, {"items": page, "next_cursor": nxt}, {"Cache-Control": "no-store"})

    def _collection_post(self, _, __):
        global NEXT_ID
        ok, data = self._read_json()
        if not ok:
            return
        errs = validate_loan(data)
        if errs:
            return self._problem(422, "Validation failed", errors=errs)
        loan = {"id": NEXT_ID, **data}
        LOANS[NEXT_ID] = loan
        NEXT_ID += 1
        self._send(201, loan, {"Location": f"/loans/{loan['id']}", "ETag": etag_of(loan)})

    # ---- item
    def _item_head(self, lid, q):
        self._item_get(lid, q)

    def _item_get(self, lid, _):
        loan = LOANS.get(lid)
        if loan is None:
            return self._problem(404, "Not Found", "No such loan")
        tag = etag_of(loan)
        hdrs = {"ETag": tag, "Cache-Control": "private, no-cache"}
        if self.headers.get("If-None-Match") == tag:
            return self._send(304, None, hdrs)
        self._send(200, loan, hdrs)

    def _item_put(self, lid, _):
        ok, data = self._read_json()
        if not ok:
            return
        current = LOANS.get(lid)
        if current is None:
            return self._problem(404, "Not Found", "No such loan")   # this API does not create via PUT
        sent = self.headers.get("If-Match")
        if sent is None:
            return self._problem(428, "Precondition Required", "Send If-Match with the current ETag")
        if sent != etag_of(current):
            return self._problem(412, "Precondition Failed", "The loan changed; re-read it")
        errs = validate_loan(data)
        if errs:
            return self._problem(422, "Validation failed", errors=errs)
        LOANS[lid] = {"id": lid, **data}
        self._send(200, LOANS[lid], {"ETag": etag_of(LOANS[lid])})


if __name__ == "__main__":
    ThreadingHTTPServer(("127.0.0.1", 8082), Handler).serve_forever()
```

`conformance.sh`:

```bash
#!/usr/bin/env bash
# usage: ./conformance.sh [base_url]
BASE=${1:-http://127.0.0.1:8082}
expect() { local want=$1; shift; local got
  got=$(curl -s -o /dev/null -w '%{http_code}' "$@")
  [ "$got" = "$want" ] || { echo "FAIL want $want got $got: $*"; exit 1; }
  echo "ok $want $*"; }
header() { curl -s -D - -o /dev/null "${@:2}" | tr -d '\r' | grep -i "^$1:" | cut -d' ' -f2-; }
J='Content-Type: application/json'
expect 200 "$BASE/loans"
expect 200 "$BASE/loans?limit=50"
expect 422 "$BASE/loans?limit=0"
expect 422 "$BASE/loans?limit=51"
expect 422 "$BASE/loans?limit=abc"
expect 422 "$BASE/loans?after=@@@"
expect 404 "$BASE/nope"
expect 404 "$BASE/loans/9999"
expect 405 -X DELETE "$BASE/loans/1"
[ "$(header allow -X DELETE "$BASE/loans/1")" = "GET, HEAD, PUT" ] || { echo "FAIL Allow on item"; exit 1; }
[ "$(header allow -X DELETE "$BASE/loans")" = "GET, HEAD, POST" ] || { echo "FAIL Allow on collection"; exit 1; }
expect 201 -X POST -H "$J" -d '{"book_id":1,"member":"zed"}' "$BASE/loans"
expect 422 -X POST -H "$J" -d '{"book_id":true,"member":"zed"}' "$BASE/loans"
expect 422 -X POST -H "$J" -d '{"book_id":1,"member":"zed","extra":1}' "$BASE/loans"
expect 422 -X POST -H "$J" -d '{"member":"zed"}' "$BASE/loans"
expect 400 -X POST -H "$J" -d '{bad' "$BASE/loans"
expect 415 -X POST -d 'book_id=1' "$BASE/loans"
LOC=$(header location -X POST -H "$J" -d '{"book_id":2,"member":"y"}' "$BASE/loans")
[ -n "$LOC" ] || { echo "FAIL no Location"; exit 1; }
TAG=$(header etag "$BASE$LOC")
expect 304 -H "If-None-Match: $TAG" "$BASE$LOC"
expect 428 -X PUT -H "$J" -d '{"book_id":3,"member":"q"}' "$BASE$LOC"
expect 412 -X PUT -H "$J" -H 'If-Match: "stale"' -d '{"book_id":3,"member":"q"}' "$BASE$LOC"
expect 200 -X PUT -H "$J" -H "If-Match: $TAG" -d '{"book_id":3,"member":"q"}' "$BASE$LOC"
expect 412 -X PUT -H "$J" -H "If-Match: $TAG" -d '{"book_id":4,"member":"q"}' "$BASE$LOC"
# pagination walk: total rows seen must be unique
SEEN=0; CUR=""
while :; do
  R=$(curl -s "$BASE/loans?limit=7${CUR:+&after=$CUR}")
  N=$(echo "$R" | python3 -c 'import sys,json;print(len(json.load(sys.stdin)["items"]))')
  SEEN=$((SEEN+N)); CUR=$(echo "$R" | python3 -c 'import sys,json;print(json.load(sys.stdin)["next_cursor"] or "")')
  [ -z "$CUR" ] && break
done
[ "$SEEN" -ge 27 ] || { echo "FAIL pagination saw $SEEN"; exit 1; }
echo "ALL PASSED"
```

## Section 9: Project reference approach

You are graded on judgement, so this is a model decision set rather than the only valid answer.

**Status code table (excerpt).**

| Operation | Success | Errors (with problem+json) |
|---|---|---|
| GET /books | 200 | 422 (bad limit/cursor) |
| GET /books/{id} | 200, 304 | 404 |
| POST /loans | 201 + Location | 422 (body), 404 (nonexistent `book_id` is in the body: choose 422 with field error; document), 409 (book already on loan), 415, 400 |
| POST /loans/{id}/return | 200 | 404, 409 (already returned: but see idempotency below) |
| DELETE /members/{id} | 204 | 409 (active loans), 404 or 204 on repeat per policy |

**Reference decisions with reasons.**

- Nonexistent referenced entity in a body: 422 with a field error, because the URL is valid and the *value* is wrong; 404 is for the target URL. Some teams choose 409; consistency is what matters.
- Returning a book: model as `POST /loans/{id}/return` that is idempotent in effect: second call returns 200 with the same final state (not 409). Reason: a kiosk that times out will retry. 409 is reserved for conflicts that a retry cannot fix.
- Lists: `/books` (read-mostly, searched by title) use offset or cursor? Offset is acceptable for a small catalogue that staff browse by page number; `/loans` (append-heavy, consumed by a nightly job) use cursor ordered by `id`. Justify with write rate and consumer type.
- Caching: `/books/{id}` `private, no-cache` plus ETag; `/loans*` `no-store` (personal data about members); no `public` anywhere without an explicit written reason.
- Idempotency: GET/PUT/DELETE inherently; `POST /loans` accepts `Idempotency-Key` (24 h retention; same key + same body replays the original response; same key + different body gives 422 or 409, state which). VERIFY the current header draft before citing it as a standard.
- Versioning: `/v1` prefix; additive-only changes; deprecation via announced sunset date; `/v2` only for breaking changes, both live for one full billing/term cycle.
- Fees (if included): integer cents field `fee_cents`.

**Breaking-change drill (model classification).**

| Proposed change | Class | Reason |
|---|---|---|
| Add optional `notes` to Loan response | compatible | Clients ignoring unknown fields are unaffected (state that expectation in the policy) |
| Rename `member` to `member_id` | breaking | Consumers read the old name |
| Change `limit` default 10 to 50 | breaking (soft) | Behaviour and payload size change for consumers that omit it |
| Add new status `lost` to Loan.status enum | breaking unless contract says clients tolerate unknown enum values | Switch statements in clients |
| Make `member` required on a currently optional request field | breaking | Existing callers get 422 |
| Allow longer `title` (max 200 to 400) | compatible for requests; may break clients with fixed columns for responses | Direction matters |
| Return 404 instead of 410 for retired items | breaking for clients that act on 410 | Status codes are part of the contract |
| Add `GET /loans/overdue` | compatible | New endpoint |

**Rubric scoring notes.** Award contract correctness points only if the spec validates with a named validator. Deduct 5 from "status code precision" for each operation whose declared responses omit its plausible 4xx codes. For the "policies justified" criterion, require that each choice cites a workload property (write rate, consumer, sensitivity), not a preference.
