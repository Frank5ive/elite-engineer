## Section 8.B: Code challenge reference

Reference additions to `probsim.py` (all take an explicit `random.Random` or a seed):

```python
def conditional_prob(sampler, event, given, n: int, seed: int):
    rng = random.Random(seed)
    accepted = hits = 0
    for _ in range(n):
        o = sampler(rng)
        if given(o):
            accepted += 1
            hits += 1 if event(o) else 0
    if accepted < 2:
        raise ValueError("no (or too few) samples satisfied the condition; increase n")
    p = hits / accepted
    return Estimate(p, math.sqrt(p * (1 - p) / accepted), accepted), accepted

def uniform(r, a, b):
    if not a < b: raise ValueError("need a < b")
    return a + (b - a) * r.random()

def running_mean_trace(draw, n, checkpoints, seed):
    cps = set(checkpoints); rng = random.Random(seed); s = 0.0; out = {}
    for k in range(1, n + 1):
        s += draw(rng)
        if k in cps: out[k] = s / k
    return out

def clt_experiment(m, trials, seed):
    import bisect
    rng = random.Random(seed); mu, sd = m / 2, math.sqrt(m / 12)
    zs = sorted((sum(rng.random() for _ in range(m)) - mu) / sd for _ in range(trials))
    return max(abs(bisect.bisect_right(zs, t) / trials - normal_cdf(t)) for t in (-2, -1, 0, 1, 2))
```

Design notes. `conditional_prob`: the standard error uses the accepted count (see 3.2). Binomial standard error `sqrt(p(1-p)/accepted)` is the analytic one; if p-hat = 0 or 1 it reports 0, a known weakness (alternative: Wilson or Clopper-Pearson intervals; 6.3 introduces intervals). Returning the accepted count lets callers warn when it is tiny. `clt_experiment`: sorted standardized values plus `bisect_right` give the empirical CDF in O(n log n); the maximum over five points is a crude Kolmogorov-style distance. Alternative: compute `sum(z <= t)` per point (O(5n), simpler, no import).

Measured with this reference code (seed 3, 100,000 trials): maximum deviation from Normal CDF at the five points is 0.0538 for m = 1 (a single uniform), 0.0177 for m = 2, 0.00670 for m = 5, 0.00145 for m = 30. The sampling noise on each empirical CDF value is at most sqrt(0.25/100000) = 0.0016, so m = 30 is indistinguishable from normal at these five points, while m = 5 is still visibly off (about 4 SE). Suggested tests: `clt_experiment(30, 100_000, 3) < 0.005` and `clt_experiment(1, 100_000, 3) > 0.01` (the second proves the test can fail). Two-dice conditional with 400,000 trials, seed 5: 0.09088 with SE 0.00082 from 122,220 accepted, truth 1/11 = 0.09091.

Extra tests in the reference suite: `conditional_prob` consistent with 1/11 and acceptance fraction in (0.29, 0.32) around the true 11/36 = 0.3056; `conditional_prob` raising on an impossible condition; `uniform(r, 2, 6)` mean consistent with 4.0 and `uniform(r, 1, 1)` raising; `running_mean_trace` within 4 x 1.7078/sqrt(100,000) of 3.5 (1.7078 = sqrt(35/12) is the die standard deviation). With these, 14 tests passed in 2.2 s.

Mutation check. Replace `rng = random.Random(seed)` in `estimate` by constructing `random.Random(seed)` inside the loop and drawing from that. Result on my run: 6 failed, 8 passed (the two-dice, binomial, both Poisson, normal and uniform tests failed; tests that do not depend on varied draws, such as parameter validation and same-seed reproducibility, still passed - exactly the blind spot described in section 6). If your suite stays green under this mutation, add a test that asserts the standard error is positive and the estimate is not exactly 0 or 1 for a non-degenerate event, and one comparing against the analytic value.

Trade-offs and alternatives: a class-based `Engine` holding the `Random` instance would remove the seed from every call, at the cost of hidden mutable state; the function style used here is easier to test and to parallelize with per-task seeds (numpy's `SeedSequence.spawn`, 6.3). Vectorized numpy sampling is 10-100x faster in my experience but I did not benchmark it here - MEASURE before relying on that.

## Section 9: Project reference notes and rubric guidance

Derivation target (item a). Posterior = s b / (s b + f (1 - b)). With s = 0.9, f = 0.05 (computed):

| b | P(event | fire) |
|---|---|
| 0.001 | 0.0177 |
| 0.01 | 0.1538 |
| 0.1 | 0.6667 |
| 0.5 | 0.9474 |

(0.1: 0.09 / (0.09 + 0.045) = 0.6667; 0.5: 0.45 / 0.475 = 0.9474. All four rows were also produced by code.) Interpretation: the same alert is nearly useless at b = 0.001 and strong at b = 0.5. The alert's quality is not a property of the alert alone.

Rejection cells. At b = 0.001 and s = 0.9 the expected fraction of trials that fire is 0.9 x 0.001 + 0.05 x 0.999 = 0.0508, so 1,000,000 trials give about 50,800 fires and a posterior SE of sqrt(0.0177 x 0.9823 / 50800) = 0.00058. At 100,000 trials: about 5,080 fires, SE 0.0018 (10% of the value). Students should show this calculation to justify N.

Poisson part (item b). With lambda = 3 (an assumption; justify yours): P(0) = e^-3 = 0.0498; P(count >= 5) = 1 - sum_{k=0}^{4} P(k). Compute it with `poisson_pmf` (for lambda = 3 it is 0.1847) and compare with simulation; do not trust a hard-coded number from this file because your lambda may differ. For lambda = 3 the simulation test in the lesson (P(0), seed 3, N = 200,000) agreed with 0.0498 within 4 SE.

Two fires (item e). Independent formula: apply Bayes twice: 0.1538 -> 0.7660 for the stated parameters (computed). Common-cause model: with probability 0.5 the two fires are driven by a shared factor so their conditional independence fails; the correct posterior is lower than 0.7660 because the second fire carries less new information. The size depends on how you model the shared factor; the grader checks that (1) the model is stated explicitly, (2) the simulated posterior is below 0.7660, and (3) the explanation says repeated alerts from one root cause are not independent evidence. Do not accept a specific numeric target without the model; mark VERIFY if your own number cannot be reproduced by a second implementation.

Rubric scoring notes (100):
- Derivations 25: 8 for Bayes formula and table, 6 for Poisson derivation, 6 for the two-fire formula, 5 for stated assumptions. Deduct 5 if any derivation is quoted without working.
- Engine 20: explicit RNG (6), `Estimate` with SE (5), validation (4), clear oracle/sampler separation (5).

Critical-failure triggers: any conclusion that says "the signal is 90% accurate so 90% of fires are real"; tolerances like `abs(a - b) < 0.01` with no SE reasoning; shared seed.

Extension notes. Importance sampling for b = 1e-4: sample the event indicator from a proposal with probability q >> b (e.g. q = 0.5) and weight each draw by (b/q) or ((1-b)/(1-q)). The weighted estimator is unbiased; its variance is far lower for the rare event. A common mistake is forgetting the weights. Compare SE at equal N, then at equal run time.
