## A. Retrieval practice answers

1. A cache line is the unit of transfer between memory levels, commonly 64 bytes on x86-64 (`getconf LEVEL1_DCACHE_LINESIZE` printed 64 on the test machine; check yours). Spatial locality: nearby addresses are used together (a line brings neighbours). Temporal locality: the same address is reused soon. A linked list loses spatial locality (and defeats prefetching since the next address depends on the current load). It may not lose it if nodes were allocated sequentially and are traversed in allocation order (a freshly built list can behave well; a sorted or churned list typically does not).
2. SoA wins when a loop reads one or two fields of many elements (unused fields would waste cache lines and bandwidth) and for vectorization. AoS wins when whole elements are used together or accessed randomly by index, and when insert/erase must stay simple. SoA costs: parallel arrays to keep in sync, harder insertion/erasure, less natural code.
3. Examples (accept others): unused results deleted (consume via barrier); constant inputs folded (runtime-derived data); cold start (warm-up); single run (repeat, median and spread); `-O0` or sanitizers (release flags); size fits one cache level only (sweep sizes); frequency scaling and other processes (pin, governor, quiet machine; `taskset`, `cpupower`); comparing different outputs (cross-check).
4. If the result is never observed, the optimizer may delete the work, so the benchmark times nothing. `asm volatile("" ::: "memory")` is a compiler barrier: the compiler may not cache memory values across it or reorder memory accesses over it. It emits no instruction, gives no atomicity or CPU ordering between threads, and does not stop the CPU from reordering.
5. `deallocate` is a no-op; memory returns only when the resource is destroyed or `release()` is called. Failure modes: unbounded growth in a long loop (nothing reused); use of an object after the resource's lifetime ended (dangling); sharing between threads (not thread-safe); mixing resources across containers on move/swap (allocator propagation rules).
6. The predicate protects against spurious wakeups (a wait can return without a notify) and against notifications sent before the waiter started waiting (the predicate is already true). The mutex makes "check condition then sleep" atomic with respect to changes: `wait` unlocks and sleeps atomically. A spurious wakeup is a return from `wait` with no corresponding notification; the standard allows it.
7. Two conflicting accesses (same location, at least one write) from different threads, at least one non-atomic, not ordered by happens-before. Undefined because the compiler optimizes each thread assuming no other thread touches the variable: it may hoist the load out of the loop, so the loop never ends (observed at `-O2`; at `-O0` the loop ended after about 6x10^7 spins). It is not "an old value", it is any behaviour.
8. Stop flag with no other data published: `relaxed` suffices (default `seq_cst` also fine). Publishing a struct through an atomic pointer: `release` store, `acquire` load (the consumer must see the struct's fields). Statistics counter read after join: `relaxed` increments. Reference-count decrement: `acq_rel` on `fetch_sub` (the last decrementer must see all prior writes to the object before destroying it; libstdc++ 14 implements the decrement as an `__ATOMIC_ACQ_REL` fetch-add in `ext/atomicity.h` plus an acquire/acq_rel fence on the last-use path; read your library's source for others). Anything unjustified: `seq_cst`.
9. If an acquire-load reads the value written by a release-store, then everything that happened before the store (in the writer thread) happens before everything after the load (in the reader). `relaxed` gives atomicity and a modification order for that one variable only; it orders nothing else, so it cannot publish other data.
10. Different variables in one cache line written by different cores make the line bounce (coherence traffic) though the program logic shares nothing. Fixes: `alignas(64)` padding between hot per-thread data; per-thread (local) accumulation merged after the work. Cost of padding: memory (here 8 bytes became 64) and worse density for sequential scans.
11. Destroying a joinable `std::thread` calls `std::terminate`. An exception escaping a thread's function also calls `std::terminate`. `std::jthread` joins in its destructor; `packaged_task`/`async` capture exceptions into the future.
12. Which operations are thread-safe concurrently; the guarded data and the lock (or protocol) for each; invariants; lifecycle (construction, shutdown, destruction while in use); lock order; whether user code runs under a lock; blocking behaviour; exception behaviour; ownership of resources passed in.

## C. Challenge 1: arena-backed parse (reference)

Hypotheses to write first, examples: the default-resource build performs about one allocation per token plus vector growth (observed count below confirms the count, not the speed); the arena build is faster in median; the gap is larger when tokens are short; the spread of the default build is wider. Then measure.

```cpp
// file: arena_parse.cpp  (C++20)  Build -O2. Measures; asserts only equality of contents.
#include <cstdio>
#include <memory_resource>
#include <string>
#include <vector>

#include "bench.hpp"

class CountingResource : public std::pmr::memory_resource {
    std::pmr::memory_resource* up_;
public:
    std::size_t allocs = 0;
    explicit CountingResource(std::pmr::memory_resource* up) : up_(up) {}
private:
    void* do_allocate(std::size_t n, std::size_t a) override { ++allocs; return up_->allocate(n, a); }
    void do_deallocate(void* p, std::size_t n, std::size_t a) override { up_->deallocate(p, n, a); }
    bool do_is_equal(const std::pmr::memory_resource& o) const noexcept override { return this == &o; }
};

constexpr int kTokens = 100000;
static std::string token(int i) { return "token-number-" + std::to_string(i) + "-padding-to-avoid-sso"; }

// Builds the vector in the given resource and returns a checksum of its contents.
static std::size_t build(std::pmr::memory_resource* r) {
    std::pmr::vector<std::pmr::string> v{r};
    for (int i = 0; i < kTokens; ++i) v.emplace_back(token(i));
    std::size_t h = 0;
    for (const auto& s : v) h = h * 31 + s.size() + static_cast<unsigned char>(s.back());
    return h;
}

int main() {
    CountingResource plain(std::pmr::new_delete_resource());
    const auto h1 = build(&plain);
    CountingResource up(std::pmr::new_delete_resource());
    std::size_t h2;
    {
        std::pmr::monotonic_buffer_resource arena(&up);  // grows from upstream in geometrically larger chunks
        h2 = build(&arena);
    }
    if (h1 != h2) { std::puts("MISMATCH"); return 1; }
    std::printf("allocations: default %zu, arena upstream %zu\n", plain.allocs, up.allocs);
    const auto a = measure([] { std::size_t h = build(std::pmr::new_delete_resource()); do_not_optimize(h); });
    const auto b = measure([] { std::pmr::monotonic_buffer_resource arena; std::size_t h = build(&arena); do_not_optimize(h); });
    std::printf("default: min %.0f median %.0f max %.0f us\n", a.min_ns / 1e3, a.median_ns / 1e3, a.max_ns / 1e3);
    std::printf("arena:   min %.0f median %.0f max %.0f us\n", b.min_ns / 1e3, b.median_ns / 1e3, b.max_ns / 1e3);
}
```

Observed: `allocations: default 100018, arena upstream 23` (100,000 string buffers plus vector growth steps and a few more, versus 23 chunk requests by the arena). Both builds returned the same checksum. Timing output depends on your machine; the program prints min/median/max. Safety by construction: the arena is a local in the same scope as the vector's creation function, so nothing built from it escapes (the function returns a checksum, not the container). If you must return the container, return the arena with it (or use a resource owned by the caller) - document the lifetime.

Alternatives: a hand-written bump allocator class (less general, no `pmr` plumbing); `reserve` plus `std::string` SSO-sized tokens (removes most allocations without a resource); `unsynchronized_pool_resource` when frees must be recycled.

## D. Challenge 2: SPSC ring buffer (reference)

```cpp
// file: spsc.hpp  (C++20)
#pragma once
#include <atomic>
#include <cstddef>
#include <optional>
#include <vector>

// SPSC: exactly one producer thread calls push(), exactly one consumer thread calls pop(). Capacity is a power of two.
// Invariant: 0 <= tail - head <= N (indices increase monotonically, wrap by masking).
// head_ is written only by the consumer, tail_ only by the producer.
// Happens-before: producer writes slot, then tail_.store(release); consumer tail_.load(acquire) sees the slot write.
//   Symmetrically consumer finishes reading the slot, head_.store(release); producer head_.load(acquire) may then reuse it.
template <class T, std::size_t N>
class SpscQueue {
    static_assert((N & (N - 1)) == 0 && N > 0, "N must be a power of two");
    alignas(64) std::atomic<std::size_t> head_{0};
    alignas(64) std::atomic<std::size_t> tail_{0};
    alignas(64) std::vector<T> buf_ = std::vector<T>(N);  // requires default-constructible T (simplification)
public:
    bool push(T v) {
        const auto t = tail_.load(std::memory_order_relaxed);        // own index: no ordering needed
        if (t - head_.load(std::memory_order_acquire) == N) return false;  // full
        buf_[t & (N - 1)] = std::move(v);
        tail_.store(t + 1, std::memory_order_release);
        return true;
    }
    std::optional<T> pop() {
        const auto h = head_.load(std::memory_order_relaxed);
        if (h == tail_.load(std::memory_order_acquire)) return std::nullopt;  // empty
        T v = std::move(buf_[h & (N - 1)]);
        head_.store(h + 1, std::memory_order_release);
        return v;
    }
};
```

Argument: the producer writes the slot, then `tail_.store(release)`; the consumer's `tail_.load(acquire)` that sees the new tail therefore sees the slot contents. The consumer moves out the slot, then `head_.store(release)`; the producer's `head_.load(acquire)` seeing it knows the slot can be overwritten. Each side reads its own index relaxed (only it writes it). Not safe with two producers: both read the same `tail_`, write the same slot, and publish with a plain store, so an item is lost or overwritten; MPMC queues need CAS loops on the indices plus per-slot sequence numbers.

```cpp
// file: spsc_test.cpp  (C++20)
#include <cstdio>
#include <cstdlib>
#include <thread>

#include "spsc.hpp"

#define CHECK(c) do { if (!(c)) { std::fprintf(stderr, "%s:%d CHECK failed: %s\n", __FILE__, __LINE__, #c); std::abort(); } } while (0)

int main() {
    SpscQueue<int, 4> q;
    CHECK(!q.pop().has_value());
    for (int i = 0; i < 4; ++i) CHECK(q.push(i));
    CHECK(!q.push(99));  // full
    int next_in = 4;
    for (int round = 0; round < 10; ++round) {  // wrap-around: always pop the oldest, push a new one
        CHECK(*q.pop() == round);
        CHECK(q.push(next_in++));
    }
    SpscQueue<int, 1024> big;
    constexpr int kN = 2'000'000;
    long long sum = 0;
    std::thread cons([&] {
        int expect = 0;
        while (expect < kN) if (auto v = big.pop()) { CHECK(*v == expect); sum += *v; ++expect; }
    });
    for (int i = 0; i < kN; ++i) while (!big.push(i)) std::this_thread::yield();
    cons.join();
    CHECK(sum == static_cast<long long>(kN) * (kN - 1) / 2);
    std::puts("spsc tests passed");
}
```

Both ran clean under TSan and under ASan+UBSan (observed, `-O1`; 2 million items). Review points: `buf_` requires default-constructible `T` (simplification; a production queue uses raw storage); indices as `size_t` are monotonic and wrap by masking, which relies on `N` being a power of two (static_assert); the `alignas(64)` constants assume a 64-byte line (true on the test machine; check your target). Alternative: a mutex+deque queue (the 3.9 `BlockingQueue`) is simpler and often adequate; choose SPSC only for a measured need.

## E. Project reference: `ThreadPool`

Design decisions: one mutex and one condition variable; tasks are `std::function<void()>`; because `std::function` needs copyable callables and `packaged_task` is move-only, each task is held by `shared_ptr` (C++23 `std::move_only_function` would avoid this; available in libstdc++ 14 with `-std=c++23`, absent in libc++ 18); tasks run outside the lock; destructor = `shutdown()`: set `stopping_` under the lock, notify all, join; workers exit only when stopping and the queue is empty, so queued work is **drained**. A discard policy would clear the queue in `shutdown()`; document whichever you choose. Self-submission from a task works unless the pool is stopping; destroying the pool from one of its own tasks self-joins (undefined/deadlock) and is documented as forbidden. Alternatives: lock-free or work-stealing queues (higher complexity, measure first), `std::jthread` with `stop_token` for cancellation.

```cpp
// file: thread_pool.hpp  (C++20)
#pragma once
#include <condition_variable>
#include <cstddef>
#include <functional>
#include <future>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <vector>

// THREAD SAFETY: submit() and shutdown() may be called from any thread. Tasks run on worker threads
//   in FIFO start order; completion order is unspecified. A task's exception is stored in its future.
// LIFECYCLE: the destructor calls shutdown(): already queued tasks are run to completion, then workers join.
//   submit() after shutdown() throws std::runtime_error. Do not call shutdown()/destroy from a task of this pool (self-join).
// INVARIANT (guarded by m_): stopping_ is false -> true only; workers exit only when stopping_ && q_.empty().
class ThreadPool {
    std::mutex m_;
    std::condition_variable cv_;
    std::queue<std::function<void()>> q_;  // std::function needs copyable callables; we wrap move-only tasks in shared_ptr
    std::vector<std::thread> workers_;
    bool stopping_ = false;

    void worker() {
        for (;;) {
            std::function<void()> job;
            {
                std::unique_lock lk(m_);
                cv_.wait(lk, [&] { return stopping_ || !q_.empty(); });
                if (q_.empty()) return;  // stopping_ and drained
                job = std::move(q_.front());
                q_.pop();
            }
            job();  // outside the lock; packaged_task catches exceptions
        }
    }

public:
    explicit ThreadPool(std::size_t n) {
        if (n == 0) throw std::invalid_argument("ThreadPool: need at least one thread");
        workers_.reserve(n);
        for (std::size_t i = 0; i < n; ++i) workers_.emplace_back([this] { worker(); });
    }
    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;
    ~ThreadPool() { shutdown(); }

    template <class F>
    auto submit(F f) -> std::future<std::invoke_result_t<F>> {
        using R = std::invoke_result_t<F>;
        auto task = std::make_shared<std::packaged_task<R()>>(std::move(f));
        auto fut = task->get_future();
        {
            std::lock_guard lk(m_);
            if (stopping_) throw std::runtime_error("ThreadPool: submit after shutdown");
            q_.push([task] { (*task)(); });
        }
        cv_.notify_one();
        return fut;
    }
    void shutdown() {  // idempotent
        {
            std::lock_guard lk(m_);
            stopping_ = true;
        }
        cv_.notify_all();
        for (auto& t : workers_) if (t.joinable()) t.join();
    }
};
```

```cpp
// file: pool_test.cpp  (C++20)  Run under -fsanitize=thread and under address,undefined.
#include <atomic>
#include <cstdio>
#include <cstdlib>
#include <numeric>
#include <stdexcept>
#include <vector>

#include "thread_pool.hpp"

#define CHECK(c) do { if (!(c)) { std::fprintf(stderr, "%s:%d CHECK failed: %s\n", __FILE__, __LINE__, #c); std::abort(); } } while (0)

int main() {
    {
        ThreadPool pool(4);
        std::vector<std::future<long>> fs;
        for (int i = 0; i < 1000; ++i) fs.push_back(pool.submit([i] { return static_cast<long>(i) * i; }));
        long total = 0;
        for (auto& f : fs) total += f.get();
        long want = 0;
        for (int i = 0; i < 1000; ++i) want += static_cast<long>(i) * i;
        CHECK(total == want);
    }
    {  // exception travels through the future
        ThreadPool pool(2);
        auto f = pool.submit([]() -> int { throw std::runtime_error("boom"); });
        bool caught = false;
        try { f.get(); } catch (const std::runtime_error&) { caught = true; }
        CHECK(caught);
    }
    {  // destructor drains queued work
        std::atomic<int> done{0};
        {
            ThreadPool pool(2);
            for (int i = 0; i < 500; ++i) pool.submit([&] { done.fetch_add(1); });
        }
        CHECK(done.load() == 500);
    }
    {  // submit after shutdown is rejected
        ThreadPool pool(1);
        pool.shutdown();
        bool threw = false;
        try { pool.submit([] { return 1; }); } catch (const std::runtime_error&) { threw = true; }
        CHECK(threw);
        pool.shutdown();  // idempotent
    }
    {  // concurrent submitters
        ThreadPool pool(4);
        std::atomic<int> n{0};
        std::vector<std::thread> subs;
        for (int s = 0; s < 4; ++s)
            subs.emplace_back([&] { for (int i = 0; i < 1000; ++i) pool.submit([&] { n.fetch_add(1); }); });
        for (auto& t : subs) t.join();
        pool.shutdown();
        CHECK(n.load() == 4000);
    }
    std::puts("thread pool tests passed");
}
```

Observed: the test passed under TSan and under ASan+UBSan (g++ 14.2).
