## Retrieval practice answers

1. In `async def`, the handler runs on the event loop's single thread; `time.sleep(1)` holds that thread so no other coroutine (other requests, health checks, timeouts) runs for 1 s. A `def` handler runs in a worker thread from the threadpool, so the loop thread stays free and only that one thread is occupied.
2. With a sync `Session`/driver every DB call blocks, so `def` handlers are correct (FastAPI runs them in the threadpool). Also pick `def` when calling any sync library (hashing, `requests`, file I/O) and you do not want to manage `to_thread` yourself. Use `async def` only when everything awaited inside is non-blocking (async driver, `httpx.AsyncClient`).
3. `min(cap, base * 2**3) = min(5.0, 1.6) = 1.6` seconds; the actual sleep is `uniform(0, 1.6)`. Jitter de-synchronizes many clients so retries do not arrive in coordinated waves that re-crash a recovering dependency.
4. Not by default: a timeout means *unknown outcome*. It is safe only if the operation is idempotent: the method is idempotent by semantics (PUT/DELETE) or the request carries an idempotency key the provider honors, or you can query the provider to learn the outcome before retrying.
5. Two requests both run the SELECT before either INSERT, both see "none", both insert (time-of-check/time-of-use race). A unique constraint moves the arbitration into the database, which serializes conflicting inserts: exactly one succeeds, the others get `IntegrityError` and read the winner's record.
6. If the key and the effect commit together, either both exist or neither does, so a retry after a crash sees a consistent state. With Redis: crash after DB commit but before Redis write loses the key (duplicate on retry); crash after Redis write but before DB commit leaves a key for an effect that never happened (retry replays a response for nothing, or is rejected). Two stores cannot be made atomic without extra protocol.
7. `422` (or `409`), error message naming the misuse. Replaying the stored response would return a result for a *different* request and silently mask a client bug (or an attack on the key space). Storing a hash of the canonical body enables the check.
8. Timeline: (1) `db.commit()` of the order succeeds; (2) process crashes before `broker.publish`; the order exists and no event is ever sent. Reverse order: publish succeeds, commit fails, event announces a non-existent order. Outbox: insert the event row in the same transaction as the order; a worker publishes after commit and marks sent. Crash anywhere leaves the row pending (or sent but unmarked), so delivery is *at-least-once*; consumers must be idempotent.
9. (a) `BackgroundTasks`: losable, cheap, no retry needed. (b) A reset email must not be silently lost but a duplicate is tolerable (and tokens expire): an outbox or RQ job with retries; a brief loss on restart is not acceptable for the user, so not `BackgroundTasks`. (c) Charging a card: the DB outbox (or a broker) *plus* an idempotency key to the provider, because it must be durable and duplicates are costly; RQ alone gives retry but not the transactional link to the checkout commit.
10. Thread A updates the row and calls `cache.delete(key)`; before A commits, thread B reads the key: miss, loads the *old* row from the DB (A is uncommitted), and writes it to the cache; A then commits. The cache now holds stale data until TTL. Fix: invalidate after commit (and keep a TTL as backstop; optionally versioned keys).

## Exercise 8.1: idempotent endpoint with in-progress state (reference)

Design: phase 1 inserts the key row as `in_progress` and commits (this claims the key; a unique constraint arbitrates races). Phase 2 calls the provider using `scope:key` as the provider's own idempotency key, outside any DB transaction. Phase 3 marks `done` with the provider reference. A duplicate that arrives meanwhile sees `in_progress` and gets 409 + `Retry-After`. A timeout returns 504 and leaves the row `in_progress` (outcome unknown). The reaper asks the provider by key and resolves rows either to `done` (it did charge) or `failed` (it did not).

```python
"""Exercise 8.1 reference: two-phase idempotency with an external provider."""
from __future__ import annotations
import hashlib, json
from dataclasses import dataclass
from sqlalchemy import String, UniqueConstraint, create_engine, select, update
from sqlalchemy.exc import IntegrityError
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column

class Base(DeclarativeBase): pass

class Charge(Base):
    __tablename__ = "charges"
    __table_args__ = (UniqueConstraint("scope", "key"),)
    id: Mapped[int] = mapped_column(primary_key=True)
    scope: Mapped[str] = mapped_column(String(64))
    key: Mapped[str] = mapped_column(String(128))
    request_hash: Mapped[str] = mapped_column(String(64))
    status: Mapped[str] = mapped_column(String(16))          # in_progress | done | failed
    provider_ref: Mapped[str | None] = mapped_column(String(64), default=None)

class Provider:
    """Fake provider: idempotent by key. `fail_after_charge` simulates a lost response."""
    def __init__(self): self.charges: dict[str, str] = {}; self.fail_after_charge = False
    def charge(self, key: str, amount: int) -> str:
        ref = self.charges.setdefault(key, f"ch_{len(self.charges)+1}")
        if self.fail_after_charge: raise TimeoutError("response lost")
        return ref
    def lookup(self, key: str) -> str | None: return self.charges.get(key)

@dataclass
class Outcome:
    code: int
    body: dict

def fp(amount: int) -> str: return hashlib.sha256(json.dumps({"amount": amount}).encode()).hexdigest()

def create_charge(s: Session, p: Provider, scope: str, key: str, amount: int) -> Outcome:
    h = fp(amount)
    row = Charge(scope=scope, key=key, request_hash=h, status="in_progress")
    s.add(row)
    try:
        s.commit()                                           # phase 1: claim the key
    except IntegrityError:
        s.rollback()
        row = s.scalars(select(Charge).where(Charge.scope == scope, Charge.key == key)).one()
        if row.request_hash != h: return Outcome(422, {"error": "key reused with different body"})
        if row.status == "done": return Outcome(201, {"ref": row.provider_ref, "replayed": True})
        if row.status == "in_progress": return Outcome(409, {"error": "in progress", "retry_after": 1})
        return Outcome(502, {"error": "previous attempt failed"})
    try:
        ref = p.charge(f"{scope}:{key}", amount)             # phase 2: external call, our key reused
    except TimeoutError:
        return Outcome(504, {"error": "unknown outcome, retry with same key"})   # row stays in_progress
    s.execute(update(Charge).where(Charge.id == row.id).values(status="done", provider_ref=ref))
    s.commit()                                               # phase 3
    return Outcome(201, {"ref": ref})

def reap(s: Session, p: Provider) -> int:
    n = 0
    for row in s.scalars(select(Charge).where(Charge.status == "in_progress")).all():
        ref = p.lookup(f"{row.scope}:{row.key}")
        row.status, row.provider_ref = ("done", ref) if ref else ("failed", None)
        n += 1
    s.commit(); return n
```

Trade-offs and alternatives:
- Production would wrap this in a FastAPI route and add a lease timestamp on `in_progress` rows so the reaper only touches rows older than the provider timeout plus a margin (otherwise it can mark a live request `failed`). I left that out for clarity; mention it in your defense.
- Alternative: hold a PostgreSQL advisory lock keyed by hash(scope, key) for the duration; simpler to reason about, but ties a DB connection to a slow external call and does not survive a crash cleanly.
- Alternative: skip `in_progress` and let duplicates call the provider with the same key, relying on the provider to dedupe. Fine if the provider is strictly idempotent; you lose your own record and visibility.
- A `failed` row replayed as 502 forever is a design choice; many systems let the client retry with a *new* key after a definitive failure.
- Scoring (10): claim-before-call 3; provider key reuse 2; 409 on in-progress 2; reaper resolves via lookup 2; tests cover all three required cases 1.

## Exercise 8.2: resilient client (reference)

```python
import asyncio, random, time
from collections.abc import Awaitable, Callable
import httpx

SAFE = {"GET", "HEAD", "PUT", "DELETE", "OPTIONS"}
RETRY_STATUS = {429, 502, 503, 504}

class DeadlineExceeded(Exception): ...

class ResilientClient:
    def __init__(self, client: httpx.AsyncClient, *, attempts=4, base=0.2, cap=5.0, deadline=10.0,
                 max_concurrency=20, clock: Callable[[], float] = time.monotonic,
                 sleep: Callable[[float], Awaitable[None]] = asyncio.sleep, rng: random.Random | None = None):
        self.c, self.attempts, self.base, self.cap, self.deadline = client, attempts, base, cap, deadline
        self.clock, self.sleep, self.rng = clock, sleep, rng or random.Random()
        self.sem = asyncio.Semaphore(max_concurrency)

    async def request(self, method: str, url: str, **kw) -> httpx.Response:
        retryable = method.upper() in SAFE or "Idempotency-Key" in (kw.get("headers") or {})
        per_try = kw.pop("timeout", None)
        start = self.clock()
        for attempt in range(self.attempts):
            remaining = self.deadline - (self.clock() - start)
            if remaining <= 0: raise DeadlineExceeded
            delay = None
            try:
                async with self.sem:
                    r = await self.c.request(method, url, timeout=min(remaining, per_try or remaining), **kw)
                if r.status_code not in RETRY_STATUS or not retryable or attempt == self.attempts - 1:
                    return r
                ra = r.headers.get("Retry-After")
                delay = float(ra) if ra and ra.replace(".", "", 1).isdigit() else None
            except (httpx.TimeoutException, httpx.TransportError):
                if not retryable or attempt == self.attempts - 1: raise
            if delay is None:
                delay = self.rng.uniform(0, min(self.cap, self.base * 2 ** attempt))
            if delay > self.deadline - (self.clock() - start): raise DeadlineExceeded
            await self.sleep(delay)
        raise AssertionError("unreachable")
```

Notes: retryability = safe method or an `Idempotency-Key` header; the per-attempt timeout is capped by the remaining deadline; `Retry-After` (seconds form only here) overrides jitter and is refused if it exceeds the remaining deadline (RFC 9110 section 10.2.3: the value is either an HTTP-date or a number of delay-seconds; handle both for real use); `sleep` and `rng` are injected. Alternatives: use a library such as `tenacity` (actively maintained: recent GitHub activity, October 2026) for the loop, but you still own the policy (what to retry, deadlines). The semaphore limits concurrency per client instance only.

## Exercise 8.3: single-flight cache (reference)

```python
import asyncio, random, time
from collections.abc import Awaitable, Callable
from typing import Any

class SingleFlightCache:
    def __init__(self, clock: Callable[[], float] = time.monotonic, rng: random.Random | None = None):
        self._data: dict[str, tuple[float, Any]] = {}
        self._inflight: dict[str, asyncio.Future] = {}
        self._clock, self._rng = clock, rng or random.Random()

    async def get_or_load(self, key: str, loader: Callable[[], Awaitable[Any]], ttl: float) -> Any:
        hit = self._data.get(key)
        if hit and hit[0] > self._clock():
            return hit[1]
        fut = self._inflight.get(key)
        if fut is not None:
            return await asyncio.shield(fut)          # waiters share the leader's outcome
        fut = asyncio.get_running_loop().create_future()
        self._inflight[key] = fut
        try:
            value = await loader()
        except BaseException as e:
            fut.set_exception(e)
            fut.exception()                           # mark retrieved: no "never retrieved" warning if no waiters
            raise
        else:
            self._data[key] = (self._clock() + ttl * self._rng.uniform(0.9, 1.1), value)
            fut.set_result(value)
            return value
        finally:
            del self._inflight[key]
```

```python
import asyncio, pytest
from sflight import SingleFlightCache

async def test_one_load_for_100_callers():
    calls = 0
    async def loader():
        nonlocal calls; calls += 1; await asyncio.sleep(0.05); return "v"
    c = SingleFlightCache()
    rs = await asyncio.gather(*[c.get_or_load("k", loader, 10) for _ in range(100)])
    assert rs == ["v"] * 100 and calls == 1

async def test_failure_propagates_and_not_cached():
    calls = 0
    async def bad():
        nonlocal calls; calls += 1; await asyncio.sleep(0.01); raise RuntimeError("x")
    c = SingleFlightCache()
    rs = await asyncio.gather(*[c.get_or_load("k", bad, 10) for _ in range(5)], return_exceptions=True)
    assert all(isinstance(r, RuntimeError) for r in rs) and calls == 1
    async def good(): return "ok"
    assert await c.get_or_load("k", good, 10) == "ok"

async def test_expiry_reloads():
    t = [0.0]; calls = 0
    async def loader():
        nonlocal calls; calls += 1; return calls
    c = SingleFlightCache(clock=lambda: t[0])
    assert await c.get_or_load("k", loader, 10) == 1
    assert await c.get_or_load("k", loader, 10) == 1
    t[0] = 20; assert await c.get_or_load("k", loader, 10) == 2
```

Notes: the leader runs the loader; followers `await asyncio.shield(fut)` so cancelling one waiter does not cancel the shared future; failure is delivered to all waiters and nothing is stored; the `finally` clears the in-flight entry so the next call retries. TTL jitter is applied at store time. Weakness to mention: if the leader is cancelled (client disconnect), followers receive `CancelledError`; production code would detach the load into its own task. Alternative: `functools.lru_cache` on a sync function (no TTL, no stampede control); `cachetools.TTLCache` for TTL (does not coalesce loads).

Idempotency endpoint and tests (`idem.py`, `test_idem.py`):

```python
# Python 3.12+, SQLAlchemy 2.x, FastAPI
from __future__ import annotations
import hashlib, json
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException, Response
from pydantic import BaseModel, Field
from sqlalchemy import JSON, String, UniqueConstraint, create_engine, select
from sqlalchemy.exc import IntegrityError
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, sessionmaker
import os, tempfile

class Base(DeclarativeBase): pass

class Payment(Base):
    __tablename__ = "payments"
    id: Mapped[int] = mapped_column(primary_key=True)
    account: Mapped[str] = mapped_column(String(40))
    amount_cents: Mapped[int]

class IdempotencyRecord(Base):
    __tablename__ = "idempotency_keys"
    __table_args__ = (UniqueConstraint("scope", "key", name="uq_idem_scope_key"),)
    id: Mapped[int] = mapped_column(primary_key=True)
    scope: Mapped[str] = mapped_column(String(64))        # e.g. user id
    key: Mapped[str] = mapped_column(String(128))
    request_hash: Mapped[str] = mapped_column(String(64))
    response_code: Mapped[int]
    response_body: Mapped[dict] = mapped_column(JSON)

DB_PATH = os.path.join(tempfile.mkdtemp(), "idem.db")   # file DB: real concurrent connections
engine = create_engine(f"sqlite:///{DB_PATH}", connect_args={"timeout": 15})
Base.metadata.create_all(engine)
SessionLocal = sessionmaker(engine, expire_on_commit=False)

def get_db():
    with SessionLocal() as s:
        yield s

class PaymentIn(BaseModel):
    account: str = Field(min_length=1, max_length=40)
    amount_cents: int = Field(gt=0)

def fingerprint(body: BaseModel) -> str:
    canonical = json.dumps(body.model_dump(mode="json"), sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(canonical.encode()).hexdigest()

app = FastAPI()

def _replay(db: Session, scope: str, key: str, h: str, response: Response):
    rec = db.scalars(select(IdempotencyRecord).where(
        IdempotencyRecord.scope == scope, IdempotencyRecord.key == key)).one()
    if rec.request_hash != h:
        raise HTTPException(422, "Idempotency-Key reused with a different request body")
    response.status_code = rec.response_code
    response.headers["Idempotent-Replayed"] = "true"
    return rec.response_body

@app.post("/payments", status_code=201)
def create_payment(body: PaymentIn, response: Response,
                   db: Annotated[Session, Depends(get_db)],
                   idempotency_key: Annotated[str, Header(min_length=8, max_length=128)]):
    scope, h = "demo-user", fingerprint(body)       # scope comes from auth in real code
    try:
        # business effect and the key record commit together, or not at all
        pay = Payment(account=body.account, amount_cents=body.amount_cents)
        db.add(pay); db.flush()
        result = {"id": pay.id, "account": pay.account, "amount_cents": pay.amount_cents}
        db.add(IdempotencyRecord(scope=scope, key=idempotency_key, request_hash=h,
                                 response_code=201, response_body=result))
        db.commit()
        return result
    except IntegrityError:
        db.rollback()                               # lost the race, or a retry
        return _replay(db, scope, idempotency_key, h, response)
```

## Project 2.6 reference notes

- **Tables:** `accounts(id, balance int CHECK (balance >= 0))`, `transfers(id, scope, key, request_hash, from_id, to_id, amount, status, response_body jsonb, UNIQUE(scope, key))`, `outbox(id bigserial, topic, payload jsonb, status, attempts int, next_attempt_at timestamptz, lease_until timestamptz, last_error text)`.
- **Transfer transaction:** insert `transfers` row (unique violation means replay path); `UPDATE accounts SET balance = balance - :a WHERE id = :f AND balance >= :a` and require `rowcount == 1` (else 422 recorded in the idempotency row); credit; insert `outbox` row; commit. Lock accounts in a consistent order (lowest id first) to avoid deadlocks (2.4).
- **Worker loop:** transaction 1: `SELECT ... WHERE (status = 'pending' AND next_attempt_at <= now()) OR (status = 'in_flight' AND lease_until < now()) ORDER BY id LIMIT 10 FOR UPDATE SKIP LOCKED` (checked on PostgreSQL 18: two sessions each claiming `LIMIT 2` got disjoint rows, and rows locked by a rolled-back session became claimable again), set `status='in_flight', lease_until=now()+interval`, commit. Then deliver each row outside the transaction with `Idempotency-Key = outbox.id`. Transaction 2 per row: `sent` on success; on failure increment `attempts`, set `next_attempt_at = now() + jittered backoff`, or `dead` past N. Use the DB clock for all comparisons.
- **Crash test:** monkeypatch the mark-sent step to raise once after the provider call; the lease expires, a second pass redelivers, and the fake provider reports one effect and one deduplicated duplicate.
- **Graceful shutdown:** signal handler sets an `asyncio.Event`; the loop checks it between rows; the finally block closes the client and engine.
- **Concurrency test (PostgreSQL):** 16 threads posting the same key. Expect one transfer, 15 replays with identical bodies. Run it 50 times in CI to catch flakiness rather than once.
