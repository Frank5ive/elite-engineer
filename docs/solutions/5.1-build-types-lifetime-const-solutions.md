# Solutions: Lesson 5.1 (Build, Types, Lifetime, References, Const)

Read only after attempting. All code below was compiled with GCC 14.2.0, `-std=c++20 -Wall -Wextra -Wpedantic` (the challenge also with `-Wconversion -Wshadow`) and run under `-fsanitize=address,undefined`. Clang 18 was used for Clang-specific statements.

## Section 6: Failure laboratory

Predictions that score full marks:

- Program A: two warnings (`-Wreturn-local-addr` for `counter`, `-Wdangling-reference` for `pick` on GCC 13+), and UB on both uses. A prediction of "prints alpha then 0" is a failed prediction: it is UB, not "probably fine". Root cause: a returned reference is not a lifetime-extending initializer; the temporaries die at the end of the full expression.
- Program B: `d` heap-use-after-free (ASan), `o` heap-buffer-overflow (ASan), `i` signed overflow (UBSan runtime error). Without sanitizers: unpredictable by definition.
- Scoring note: award credit for naming the lifetime fact ("X ended at line N, Y used at line M"), not for guessing the sanitizer text.

## Section 7: Retrieval answers

1. Preprocess (expanded TU `.ii`), compile (assembly `.s`), assemble (object `.o`), link (executable). `undefined reference` is reported by the linker.
2. Each TU gets its own definition of `limit()`; the link fails with `multiple definition of 'limit()'` (linker stage). Fixes: declare in the header and define in one `.cpp`; mark `inline`; make it `constexpr` (implicitly inline); or give internal linkage (`static`/unnamed namespace; each TU gets a private copy, rarely wanted).
3. Guards prevent the same header being pasted twice into one TU (compile error `redefinition`). The ODR governs definitions across TUs (link error or silent IFNDR). A guard does not prevent multiple definitions across TUs, and `inline` does not prevent redefinition inside one TU.
4. Multiple identical definitions in different TUs are permitted (and the address is the same program-wide). Inlining is a separate optimizer decision.
5. `int n{3.0};` is a constant expression whose value fits, so it is not narrowing (allowed). `int n{d};` with a non-constant `double` is narrowing: the standard requires a diagnostic; GCC emits a warning (`-Wnarrowing`), an error with `-pedantic-errors`.
6. Local `int x;`: indeterminate, reading is UB (pre-C++26). Global/static `int x;`: zero-initialized. `int x{};` local: 0.
7. `const std::string& r = f_returning_ref_to_local();` or `int* p; { int x = 1; p = &x; } *p;` : `p` is in scope, `x` is dead.
8. `const int*`: may reseat, may not modify pointee. `int* const`: may modify pointee, may not reseat. `const int* const`: neither.
9. Returns a view into a temporary `std::string` destroyed at the end of the return statement; use is UB. Length matters only for whether it appears to work: short strings sit inside the dead object (SSO, implementation detail), long ones are heap-freed. Both are UB.
10. `0`/false: the signed `-1` converts to `unsigned` (a huge value), so `-1 < 1u` is false (verified).
11. Signed overflow: UB. Unsigned overflow: defined, wraps. `v[v.size()]`: UB. Conversion to `int32_t` in C++20: defined, modular (verified `-1294967296`).
12. `struct` for plain data without invariants, `class` when a constructor establishes an invariant guarded by private data. `explicit` on single-argument constructors unless implicit conversion is intended.

## Section 8: `argcheck` reference solution

`argv_util.hpp`

```cpp
#ifndef ARGV_UTIL_HPP
#define ARGV_UTIL_HPP
#include <span>
namespace au {
enum class ParseStatus { ok, no_args, invalid_number, out_of_range };
struct ParseResult {
    ParseStatus status = ParseStatus::ok;
    long long value = 0;
};
// args excludes argv[0]. Does not retain the pointers.
ParseResult parse_count(std::span<char* const> args) noexcept;
}  // namespace au
#endif
```

`argv_util.cpp`

```cpp
#include "argv_util.hpp"
#include <charconv>
#include <string_view>
#include <system_error>

namespace au {
ParseResult parse_count(std::span<char* const> args) noexcept {
    if (args.empty()) return {ParseStatus::no_args, 0};
    if (args.size() > 1 || args[0] == nullptr) return {ParseStatus::invalid_number, 0};
    const std::string_view text{args[0]};
    if (text.empty()) return {ParseStatus::invalid_number, 0};
    long long v = 0;
    const char* first = text.data();
    const char* last = first + text.size();
    const auto [ptr, ec] = std::from_chars(first, last, v);
    if (ec == std::errc::result_out_of_range) return {ParseStatus::out_of_range, 0};
    if (ec != std::errc{} || ptr != last) return {ParseStatus::invalid_number, 0};
    if (v < 0 || v > 1'000'000) return {ParseStatus::out_of_range, 0};
    return {ParseStatus::ok, v};
}
}  // namespace au
```

Test helper (builds `char*` from `std::string` words, so `data()` gives a mutable, NUL-terminated buffer):

```cpp
static au::ParseResult run(std::vector<std::string> words) {
    std::vector<char*> ptrs;
    for (auto& w : words) ptrs.push_back(w.data());
    return au::parse_count(std::span<char* const>(ptrs.data(), ptrs.size()));
}
```

Verified expectations (all passed under ASan+UBSan, clean at `-Wconversion -Wshadow`): `{}` -> `no_args`; `""` -> `invalid_number`; `"0"` -> ok 0; `"1000000"` -> ok; `"1000001"` -> `out_of_range`; `"-1"` -> `out_of_range` (it parses, then fails the range check; documented choice); `"12x"`, `" 12"`, `"+5"`, `"-"` -> `invalid_number`; `"99999999999999999999"` -> `out_of_range` (`from_chars` reports `result_out_of_range`); two arguments -> `invalid_number`.

Design notes and trade-offs:
- Conversions: `char*` to `std::string_view` (null-terminated constructor; null checked first); `std::string_view` data pointers to `const char*` (no conversion); no integer narrowing at all. That is the answer to "list every conversion".
- `-1` is classified `out_of_range` because it is a valid number outside `[0, 1'000'000]`; classifying it `invalid_number` is a defensible alternative if the spec says "digits only". Either is correct if documented and tested; the rubric rewards the documentation.
- Alternative: hand-written digit loop with an overflow check (`v > (max - d) / 10`); more code, no `<charconv>` dependency, easier to get wrong.
- Handling `argc == 0`: `main` builds `std::span(argv, argc)` and calls `parse_count(span.subspan(std::min<size_t>(1, span.size())))` so an empty span is never over-subspanned.
- CMake: the same shape as the lesson's `textstats` (library + test executable + `TS_SANITIZE`-style option).

## Section 9: Project reference approach and scoring notes

Architecture:
- `Analyzer` class: members `std::size_t lines_, words_, bytes_; bool in_word_; char last_byte_; bool any_ = false;`. `feed(std::string_view chunk) noexcept` loops once; `finish()` applies the last-line rule (`any_ && last_byte_ != '\n'` adds a line) and returns `Stats`. The whole-text `analyze` becomes `Analyzer a; a.feed(t); return a.finish();`.
- Chunk-boundary test: split `"ab cd"` at every position 0..5, feed the two halves, and assert identical results to the single feed. Include splits inside a word, between a word and a space, and at a newline.
- Reading: `std::ifstream` + `read(buf.data(), buf.size())` with a fixed `std::array<char, 64*1024>` and `gcount()`; stop when `gcount() == 0`; distinguish `bad()` from `eof()`. Memory stays at one buffer.
- `--top N`: the same `feed` loop also pushes words into a carry-over `std::string` (a word crossing the chunk boundary is completed on the next chunk), lower-cases ASCII with an explicit function (not `std::tolower` on negative `char`), increments an `unordered_map<std::string, size_t>`. At the end copy to a vector and sort by (count desc, word asc). A pathological single word of 1 GiB would grow the carry string: document a maximum word length or truncate with a stated policy.
- Mid-way change (`--delimiter C`): the only function that changes is the predicate `is_separator(char)`. Strong designs inject it as a template parameter or a small struct member; weak designs scatter `is_space` calls. Score the cost of the change: 1 function + tests = full marks on that rubric line.
- Memory measurement: `/usr/bin/time -v ./textstats -l -w -c big.txt` and read "Maximum resident set size". Accept only a number the learner actually measured; reject estimated numbers. Do not state a target result here; it depends on the machine and allocator.
- `wc` comparison: `wc -l` counts newline characters only, so a file without trailing newline differs by one from this tool's rule unless the learner adopts wc's rule. Either is acceptable if documented.

Rubric scoring notes (100): Build/CMake 15 (library + executable + test + options + out-of-source; deduct 5 for flags set globally in a way that leaks to consumers); correctness 25 (5 per cluster: option parsing, counting, multi-file/total, stdin, exit codes); streaming 15 (10 for design, 5 for measurement shown); tests 15 (must include boundary splits and error paths; tests with no failing possibility score 0); const/lifetime/UB audit 15 (the audit must name each view/reference and its owner); warnings and sanitizers 5; README/commits/failure log 10.

Common deductions: `using namespace std` in a header; `std::isspace(char)` on negative values; `std::stoi` for `--top` without error handling; reading the whole file in streaming mode (critical failure); `argv[1]` access without `argc` check (critical failure).

## Section 11: Mastery gate notes

A passing closed-book `analyze` + CMake re-implementation takes 20 minutes if the learner holds the model; failing on header guards or the `target_link_libraries` visibility keyword indicates remediation in section 3.2/3.3 concepts, which the remedial five-bug program addresses.

## Alternatives worth discussing in the defense

- `#pragma once` vs guards; `std::span<const std::string_view>` for arguments (building the view vector is an allocation); `std::from_chars` vs `strtol` (the latter uses `errno` and locale); `-Werror` placement (CI only).

## Checked with Clang 18 (Ubuntu 24.04)

- `-Wdangling-gsl` (enabled by default) warned on `std::string_view sv = std::string("...")`: "object backing the pointer will be destroyed at the end of the full-expression".
- `a = a` on a class with a user-written `operator=` warned with `-Wself-assign-overloaded` under `-Wall`.
- `argc == 0` is allowed by [basic.start.main]; Linux 6.12 `execve` with an empty `argv` still gave `argc == 1` (kernel adds an empty argument), so it cannot be reproduced there.
- C++26 erroneous behavior for uninitialized reads (P2795) is not exercised here; read your compiler's release notes before relying on it.
