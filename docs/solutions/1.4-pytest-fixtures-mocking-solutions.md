## Section 7: Retrieval answers

1. pytest rewrites `assert` statements at import time (an import hook on test modules and registered helpers), capturing sub-expressions so failures can show both sides.
2. `@pytest.mark.parametrize("year, expected", [(1999, False), (2000, True), (1900, False), (2024, True), (2023, False), (2100, False), (1600, True)], ids=["ordinary", "400-rule", "century", "div-by-4", "plain", "century-2", "400-rule-2"])`.
3. Yes: code after `yield` runs even when the test fails (pytest treats it as finalization). If the fixture raises before `yield`, the test errors (reported as ERROR, not FAIL), the test does not run, and teardown for that fixture does not run, so acquire resources in a way that cleans up on partial failure (try/finally or `request.addfinalizer` right after acquisition).
4. `session` or `module` scope, because creation is expensive. Each test must run in its own transaction rolled back at the end (or truncate tables) so no data leaks; the schema itself is treated as immutable.
5. `mock.patch("a.sleep")` for `from time import sleep` (patch the name in `a`'s namespace). For `import time; time.sleep(5)` patch `"a.time.sleep"` (or `"time.sleep"`, which is the same attribute on the shared module object, but then it affects everything; prefer the narrower form). Better: inject a `sleep` parameter.
6. `autospec=True` makes the mock enforce the real signature: calling it with the wrong number or names of arguments raises `TypeError`, so a test breaks when the real function's signature changes (shown in `test_autospec_catches_wrong_signature`). A plain `return_value` mock accepts any call.
7. Stub: returns canned answers. Spy: records calls for later assertions. Fake: working lightweight implementation. Mock: pre-programmed with expectations, failing if unmet (in practice `unittest.mock.Mock` is used for any of these). `FakeGateway` is a fake (it keeps state and declines configured users).
8. Without parentheses it is just attribute access: nothing is asserted, so a missing call goes unnoticed. On 3.13.5 `assert_called_once_wiht` raises `AttributeError` (verified), as does `called_once_with`; older versions could silently create a child mock, so do not rely on it. Linters and `spec` help.
9. Injection: pass a `Clock` returning a fixed datetime (preferred: no patching, explicit contract, works with Protocols). Patching: `monkeypatch.setattr` on the lookup site with a fake `datetime` class, or a time-freezing library (VERIFY). Patching `datetime.now` is awkward because `datetime` is a C type whose attributes cannot be set directly.
10. Properties: output contains only digits and an optional leading `+`; `normalize_phone(normalize_phone(s)) == normalize_phone(s)` (idempotence); formatting variants of the same number normalize equally. Keep example tests for known real-world formats, and for the rejected inputs and error messages.
11. Resolutions: (a) the function raises `ValueError` for `lo > hi` and the property assumes `lo <= hi`; (b) define the result for `lo > hi` (for example swap) and change the property; (c) constrain the strategy to valid inputs and document the precondition. The question to answer first: what is the contract, who calls it, and do they ever pass inverted bounds?
12. First step: find or create a seam and write characterization tests, not refactor. A characterization test asserts the current result even when you believe it is a bug, labelled as such, so the refactor can be shown to preserve behavior; the fix comes in a separate commit with its own test.

## Section 8: Challenge reference approach

```python
# notify.py (refactored; behavior of the old wrapper preserved)
from __future__ import annotations
import smtplib
import time
from collections.abc import Callable, Sequence
from datetime import datetime
from typing import Protocol

class Mailer(Protocol):
    def send(self, sender: str, to: str, message: str) -> None: ...   # raises smtplib.SMTPException

class Clock(Protocol):
    def now(self) -> datetime: ...

class SmtpMailer:
    def send(self, sender: str, to: str, message: str) -> None:
        with smtplib.SMTP("mail.internal") as s:
            s.sendmail(sender, [to], message)

class SystemClock:
    def now(self) -> datetime:
        return datetime.now()

def build_message(stamp: str, items: Sequence[str]) -> str:
    return f"Digest {stamp}\n\n" + "\n".join(f"- {i}" for i in items)

def send_digest(user_email, items, *, mailer: Mailer | None = None, clock: Clock | None = None,
                sleep: Callable[[float], None] = time.sleep) -> bool:
    if not items:
        return False
    mailer, clock = mailer or SmtpMailer(), clock or SystemClock()
    message = build_message(clock.now().strftime("%Y-%m-%d"), items)
    for attempt in range(3):
        try:
            mailer.send("noreply@example.com", user_email, message)
            return True
        except smtplib.SMTPException:
            sleep(2 ** attempt)
    return False
```

(The `send_digest` function above was exercised with a fake mailer: two failures then success gives sleeps `[1, 2]`; five failures give `False` with sleeps `[1, 2, 4]`.)

Characterization tests (before the refactor) patch `notify.smtplib.SMTP` with `autospec=True` and `notify.time.sleep`; assert sleeps `[1, 2]` after two failures then success, and `[1, 2, 4]` with `False` after three failures, noting that the original sleeps after the final failure too (a characterized oddity: the last `sleep(4)` is wasted time and arguably a bug; the reference keeps it). The test that fails if `2 ** attempt` becomes `attempt` is the sleep-sequence test (`[0, 1, 2]` differs). After the refactor a `FakeMailer` with `fail_times: int` replaces the patches: assert outcome `True/False`, `mailer.sent` and the list collected by an injected `sleep`. Property: items without newlines produce exactly `len(items)` lines starting with `- `; decision for items containing newlines: either reject or document that bullets split (the current code does not escape), and test the chosen behavior with `@example`.

Trade-offs: parameters with defaults keep old callers working; alternatively a class `DigestSender(mailer, clock, sleep)` wired at the composition root, which is cleaner if more collaborators appear. Alternative to a fake mailer: `mock.create_autospec(Mailer)` with `side_effect=[SMTPException, None]`, good for scripting failure sequences.

Reference conftest snippets:

```python
import pytest, inventory

@pytest.fixture(autouse=True)
def fresh_state(monkeypatch):
    monkeypatch.setattr(inventory, "STOCK", {"A1": 10, "B2": 0, "C3": 5})
    monkeypatch.setattr(inventory, "_reservations", [])
    monkeypatch.setattr(inventory.time, "time", lambda: 1_700_000_000.0)

@pytest.fixture(autouse=True)
def no_network(monkeypatch):
    def refuse(*a, **k):
        raise RuntimeError("network access in test")
    monkeypatch.setattr("socket.socket.connect", refuse)
```

(`monkeypatch.setattr(inventory.time, "time", ...)` patches the shared `time` module's attribute for the test's duration and is undone afterwards; the cleaner solution is the clock seam the project requires. VERIFY the socket patch against your Python version.) A property test: `@given(st.integers(0, 50), st.integers(1, 50))`: `restock("A1", n)` then `reserve("A1", m)` leaves stock `10 + n - m` when `m <= 10 + n`, and returns `False` with stock unchanged otherwise. Note `monkeypatch` is function-scoped and Hypothesis reuses a function-scoped fixture across generated examples; for that reason reset state inside the test body (Hypothesis's health check warns about this; VERIFY in the Hypothesis docs).

### Rubric scoring notes

- Characterization (20): deduct 2 per unpinned branch; award for labelled surprises.
- Determinism (15): any real clock use or order dependence is a critical failure.
- Bug tests (15): require pasted failing output from the old code.
- Mutations (10): 3 mutations with failing test names recorded.
- Common failure: pinning against a shared global that other tests mutated, so results depend on execution order.

### Alternatives

- Snapshot/approval tests for `report()` output; fewer lines, weaker intent.
- `unittest.TestCase` style: works under pytest but loses fixtures and parametrization ergonomics.
- Real SQLite in-memory store as the "fake" for repository seams, when SQL behavior matters.
