## Retrieval answers

1. An expectation derived independently stops you from accepting the program's own output as truth. Concrete case: you compute 3 x 19.99 = 59.97 by hand, so a printed 59.94 is visibly wrong; if you had only looked at the output, 59.94 looks plausible.
2. Read the last line (exception type and message) first, then the last frame in your own code. The defect is often one or two frames above the raising line (the caller that did not validate, or the producer of the data).
3. "The above exception was the direct cause" is explicit chaining (`raise X from Y`); "During handling of the above exception, another exception occurred" means a new error was raised inside an `except` block, implicitly chained. Read the first (root) one first.
4. `f(1)` returns `[1]`, `f(2)` returns `[1, 2]`. The default list is created once at function definition and shared by all calls that omit `acc`.
5. Not guaranteed. String hashes are randomised per process, so set iteration order can differ; `PYTHONHASHSEED` fixes the seed.
6. (a) Shared module-level state or mutable defaults: run the test after one predecessor at a time to find the polluter. (b) Leftover external state (database rows, files): inspect and reset between tests, rerun with a clean store. (c) Order or time dependence: run in reverse/random order, inject the clock.
7. Need `0.9^k <= 0.05`, k >= ln(0.05)/ln(0.9) = 28.4, so 29 consecutive passes.
8. About log2(1000), i.e. 10 steps. The check must be deterministic and test only the symptom (and exit 125 for untestable commits).
9. Log: the order id, which branch or rule was taken, counts in and out (also the exception with traceback). Never log: secrets/tokens, personal data such as names with grades or emails.
10. A debugger is best for inspecting state you do not yet know to ask about, interactively. Logging is best for production, races, and history after the fact.
11. The f-string is formatted eagerly even if INFO is disabled; the `%d` form defers formatting until the record is emitted, and keeps the message template constant for grouping.
12. Symptom, Expectation, Evidence, Hypotheses, Root cause, Fix, How detected, Prevention, Time lost.

## Challenge reference (Section 8)

Design points: pass the seed through `env={**os.environ, "PYTHONHASHSEED": str(seed)}` for the child only; catch `subprocess.TimeoutExpired` and return `"timeout"`; `halve` is a simplified ddmin. Worst-case calls: the half-splitting phase costs O(log n) per successful shrink, and the single-element removal pass costs at most n calls per pass; repeating passes until no removal succeeds is O(n^2) worst case, and a single pass is O(n). State which one you implemented. The result is locally minimal (no single element can be dropped) but another, smaller failing subset may exist.

```python
from __future__ import annotations

import os
import subprocess
import sys
from collections.abc import Callable
from pathlib import Path


def seed_sweep(test_id: str, seeds: range, cwd: Path, timeout: float = 30.0) -> dict[int, str]:
    out: dict[int, str] = {}
    for seed in seeds:
        env = {**os.environ, "PYTHONHASHSEED": str(seed)}
        try:
            r = subprocess.run([sys.executable, "-m", "unittest", test_id], cwd=cwd, env=env,
                               capture_output=True, timeout=timeout)
            out[seed] = "pass" if r.returncode == 0 else "fail"
        except subprocess.TimeoutExpired:
            out[seed] = "timeout"
    return out


def halve(items: list, fails: Callable[[list], bool]) -> list:
    """Return a locally minimal failing sublist. Empty input: returned unchanged (nothing to shrink)."""
    if not items:
        return []
    if not fails(items):
        raise ValueError("fails(items) must be true for the input")
    current = list(items)
    changed = True
    while changed and len(current) > 1:
        changed = False
        mid = len(current) // 2
        for part in (current[:mid], current[mid:]):
            if part and fails(part):
                current, changed = part, True
                break
        if changed:
            continue
        for i in range(len(current)):
            candidate = current[:i] + current[i + 1:]
            if candidate and fails(candidate):
                current, changed = candidate, True
                break
    return current
```

This `halve` restarts after each success, so its worst case is O(n^2) predicate calls; a single left-to-right removal pass would be O(n) but may leave removable elements behind. Either is acceptable if the bound is stated correctly. Test ideas: predicate "contains 3 and 7" must return `[3, 7]` (in original order); predicate that is never true must raise; a timeout test using a generated test file containing `time.sleep(5)` with `timeout=0.5`.

## Project: the five defects (diagnosis reference)

| # | Symptom | Root cause (mechanism) | Fix |
|---|---|---|---|
| D1 | `parse_price_cents("19.99")` returns 1998; A-100 prints 59.94 not 59.97; 0.29 gives 28 | Decimal string converted through binary float; `float("19.99") * 100` is just below 1999 and `int()` truncates toward zero | Parse with `decimal.Decimal`; reject sub-cent input (spec says at most two decimals) |
| D2 | `primary_tag` is not stable across runs (fails under some `PYTHONHASHSEED` values) | `next(iter(set))` depends on string hash order, which is randomised per process | `min(tags, default="none")` per the spec (alphabetically first) |
| D3 | A note for order B contains order A's note; a test passes alone, fails after another | Mutable default argument `notes=[]` shared across calls, and stored under every order id | Look up or create a per-order list in `NOTES` |
| D4 | `page(items, 1, 3)` returns the second page | 1-based page number used as a 0-based offset | `start = (page_number - 1) * size`; reject page < 1 |
| D5 | `python3 shop.py orders.json` dies with `KeyError: 'lines'` and a traceback, no order named | `parse_order` assumes every record has `lines`; no validation or context at the boundary | Catch `KeyError` in `parse_order`, raise `ValueError` naming the order; `main` logs the error to stderr, returns non-zero, prints nothing partial |

Two things to credit in diagnoses. First, the original test `test_total` expects 6026 (3 x 1999 + 29), which is correct; it fails because of D1 (the program yields 6022). The tests in the original file are right here; a reader who "fixes" the assertion has weakened a test (critical failure). Second, D2 and D3 are the intermittent and order-dependent ones: the evidence is the seed sweep and the isolate-versus-suite comparison, not the code reading. Design alternative for D1: `round(float(price) * 100)` makes the listed prices pass but keeps binary floats for decimal money and silently rounds 0.001; acceptable only if the requirement explicitly says rounding is wanted. Alternative for D5: skip bad records and report them; that contradicts the spec ("no partial stdout"), so it needs a requirement change.

Reference fixed module (stdlib only):

```python
"""shop.py - tiny order summariser. Python 3.12+. Reference-fixed version (Lesson 0.3 solutions)."""
from __future__ import annotations

import json
import logging
import sys
from decimal import Decimal
from dataclasses import dataclass, field

log = logging.getLogger("shop")

NOTES: dict[str, list[str]] = {}


@dataclass
class Order:
    order_id: str
    lines: list[tuple[str, int, str]]  # (sku, quantity, unit price as decimal string)
    tags: set[str] = field(default_factory=set)


def parse_price_cents(price: str) -> int:
    """Exact conversion; prices with sub-cent precision are rejected, not rounded."""
    cents = Decimal(price) * 100
    if cents != cents.to_integral_value():
        raise ValueError(f"price has sub-cent precision: {price!r}")
    return int(cents)


def order_total_cents(order: Order) -> int:
    return sum(qty * parse_price_cents(price) for _sku, qty, price in order.lines)


def primary_tag(order: Order) -> str:
    """The tag shown first on the packing slip."""
    return min(order.tags, default="none")


def add_note(order_id: str, note: str) -> list[str]:
    notes = NOTES.setdefault(order_id, [])
    notes.append(f"{order_id}: {note}")
    return notes


def page(items: list, page_number: int, size: int) -> list:
    """Return the 1-based page_number-th page of items."""
    if page_number < 1 or size < 1:
        raise ValueError("page_number and size must be >= 1")
    start = (page_number - 1) * size
    return items[start : start + size]


def parse_order(record: dict) -> Order:
    try:
        lines = [(l["sku"], int(l["qty"]), l["price"]) for l in record["lines"]]
        return Order(record["id"], lines, set(record.get("tags", [])))
    except KeyError as exc:
        raise ValueError(f"bad order {record.get('id', '<no id>')}: missing field {exc}") from exc


def load_orders(text: str) -> list[Order]:
    return [parse_order(r) for r in json.loads(text)]


def summarise(text: str) -> list[str]:
    out = []
    for order in load_orders(text):
        total = order_total_cents(order)
        out.append(f"{order.order_id} {total / 100:.2f} [{primary_tag(order)}]")
    return out


def main(argv: list[str]) -> int:
    logging.basicConfig(level=logging.INFO)
    with open(argv[1], encoding="utf-8") as fh:
        try:
            lines = summarise(fh.read())
        except ValueError as exc:
            log.error("cannot summarise %s: %s", argv[1], exc)
            return 1
    for line in lines:
        print(line)
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv))
```

Reference regression tests (run these against the original `shop.py` to confirm fail-before):

```python
import json
import unittest

import shop


class ShopTests(unittest.TestCase):
    def setUp(self):
        shop.NOTES.clear()

    def test_price_parsing_exact(self):
        for price, cents in [("19.99", 1999), ("0.29", 29), ("0.58", 58), ("1", 100), ("1.10", 110)]:
            with self.subTest(price=price):
                self.assertEqual(shop.parse_price_cents(price), cents)

    def test_sub_cent_price_rejected(self):
        with self.assertRaises(ValueError):
            shop.parse_price_cents("0.001")

    def test_total(self):
        o = shop.Order("X", [("pen", 3, "19.99"), ("ink", 1, "0.29")])
        self.assertEqual(shop.order_total_cents(o), 5997 + 29)

    def test_primary_tag_alphabetical_for_every_hash_seed_independent_input(self):
        o = shop.Order("X", [], {"priority", "gift", "fragile"})
        self.assertEqual(shop.primary_tag(o), "fragile")
        self.assertEqual(shop.primary_tag(shop.Order("Y", [])), "none")

    def test_notes_are_per_order(self):
        self.assertEqual(shop.add_note("A", "call customer"), ["A: call customer"])
        self.assertEqual(shop.add_note("B", "leave at door"), ["B: leave at door"])
        self.assertEqual(shop.add_note("A", "again"), ["A: call customer", "A: again"])

    def test_pages(self):
        items = list(range(10))
        self.assertEqual(shop.page(items, 1, 3), [0, 1, 2])
        self.assertEqual(shop.page(items, 4, 3), [9])
        self.assertEqual(shop.page(items, 5, 3), [])
        with self.assertRaises(ValueError):
            shop.page(items, 0, 3)

    def test_summarise_single_order(self):
        text = json.dumps([{"id": "A", "lines": [{"sku": "s", "qty": 1, "price": "1.00"}]}])
        self.assertEqual(shop.summarise(text), ["A 1.00 [none]"])

    def test_malformed_record_names_the_order(self):
        text = json.dumps([{"id": "A-102", "tags": ["x"]}])
        with self.assertRaisesRegex(ValueError, "A-102.*lines"):
            shop.summarise(text)


if __name__ == "__main__":
    unittest.main()
```

Extension (first tag as listed, duplicates removed): sets cannot carry order, so `Order.tags` becomes `list[str]` deduplicated at parse time with `list(dict.fromkeys(tags))` (dicts preserve insertion order, a language guarantee since Python 3.7), `primary_tag` becomes `order.tags[0] if order.tags else "none"`, and the alphabetical test is replaced by an order-preserving test. The hash-seed sweep becomes unnecessary for this function, but keep it as evidence.
