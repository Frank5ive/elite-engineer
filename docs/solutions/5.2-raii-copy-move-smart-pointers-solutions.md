## Section 7: Retrieval answers

1. Destructors of all fully constructed automatic objects run during unwinding, so the resource is released on every exit path. `with` is a block-scoped feature of one construct; C++ RAII attaches release to the object and so also covers members, containers, temporaries and early returns without caller cooperation.
2. Copy duplicates the pointer, giving two owners: double free at destruction; and an edit through one object changes the other (aliasing). Also leaks on copy assignment (the old array is lost).
3. Zero: write no special members when members manage themselves. Three: custom destructor/copy constructor/copy assignment come together. Five: add move constructor and move assignment. Aim for zero.
4. It casts to an rvalue reference; it moves nothing itself. On a `const std::string` the result is `const std::string&&`, which cannot bind to `string(string&&)`, so the copy constructor is chosen: a silent copy.
5. No. `return local;` allows copy elision (NRVO, permitted not guaranteed for named locals) or an implicit move; `std::move` blocks elision and triggers `-Wpessimizing-move`/`-Wredundant-move`. For a prvalue (`return T{};`) C++17 guarantees elision.
6. Destroy it or assign to it. Reading its value is allowed but yields an unspecified value for standard types (GCC's `std::string` becomes empty; do not rely on that).
7. `std::vector` uses `std::move_if_noexcept` on reallocation: if the move constructor can throw and the type is copyable, it copies every element to keep the strong guarantee (a performance loss); if not copyable, it moves anyway and loses the guarantee.
8. `unique_ptr`: exclusive ownership, typically pointer-sized, no atomic operations, clear lifetime. `shared_ptr` costs a control block, atomic reference counts, two pointers, and obscures lifetime. Use `shared_ptr` only for genuinely shared lifetime.
9. Nodes own `next` via `shared_ptr` and `prev` via `shared_ptr`: each pair keeps the other alive; all nodes leak. Make `prev` a `weak_ptr` (or use raw non-owning back pointers with a documented invariant).
10. `push_back` that reallocates; `insert` at or before the element's position even without reallocation (elements shift); `erase` at or before it. `std::map::insert` invalidates nothing; `erase` invalidates only the erased element.
11. `push_back` then a throwing log: the vector already changed, so basic guarantee (it is not undone). `swap`: no-throw. Three member assignments with the second possibly throwing: basic at best (first member already changed); use copy-and-swap to get strong.
12. `Noisy a{"a"}` prints `ctor a`; `Noisy b = a` prints `copy a`; `Noisy c = std::move(a)` prints `move`; at scope end destructors run in reverse order c, b, a: names are `a` (moved-to `c`), `a` (copy `b`), and `''` (moved-from `a`, size 0 on GCC, unspecified in general).
13. When failure is an expected outcome the caller branches on (parse errors, validation) and you want it in the type. C++23. Prefer exceptions when failures are rare and cannot be handled locally, or where constructors must fail.

## Section 8: `Stack` reference solution (verified under ASan+UBSan)

```cpp
#pragma once
#include <cstddef>
#include <stdexcept>
#include <string>
#include <utility>

class Stack {
public:
    Stack() noexcept = default;
    Stack(const Stack& o)
        : data_{o.size_ ? new std::string[o.size_] : nullptr}, size_{o.size_}, cap_{o.size_} {
        try {
            for (std::size_t i = 0; i < size_; ++i) data_[i] = o.data_[i];
        } catch (...) { delete[] data_; throw; }
    }
    Stack(Stack&& o) noexcept
        : data_{std::exchange(o.data_, nullptr)}, size_{std::exchange(o.size_, 0)},
          cap_{std::exchange(o.cap_, 0)} {}
    Stack& operator=(Stack o) noexcept { swap(o); return *this; }
    ~Stack() { delete[] data_; }
    void swap(Stack& o) noexcept {
        std::swap(data_, o.data_); std::swap(size_, o.size_); std::swap(cap_, o.cap_);
    }
    void push(const std::string& s) { std::string tmp = s; push(std::move(tmp)); }
    void push(std::string&& s) {
        if (size_ == cap_) grow();
        data_[size_] = std::move(s);
        ++size_;
    }
    std::string pop() {
        if (size_ == 0) throw std::out_of_range("Stack::pop");
        std::string out = std::move(data_[size_ - 1]);
        --size_;
        return out;
    }
    const std::string& top() const {
        if (size_ == 0) throw std::out_of_range("Stack::top");
        return data_[size_ - 1];
    }
    std::size_t size() const noexcept { return size_; }
    bool empty() const noexcept { return size_ == 0; }
private:
    void grow() {
        const std::size_t ncap = cap_ ? cap_ * 2 : 4;
        std::string* nd = new std::string[ncap];
        try {
            for (std::size_t i = 0; i < size_; ++i) nd[i] = std::move_if_noexcept(data_[i]);
        } catch (...) { delete[] nd; throw; }
        delete[] data_;
        data_ = nd;
        cap_ = ncap;
    }
    std::string* data_ = nullptr;
    std::size_t size_ = 0, cap_ = 0;
};
```

Exception-safety table: default ctor, move ctor, move/copy assignment (by value), swap, destructor, `size`, `empty`: no-throw (copy assignment's copy happens in the caller's argument construction, before the body, so assignment itself provides the strong guarantee for the target). Copy constructor: strong (nothing observable exists if it throws; the catch frees the array). `push`: strong only when element moves are `noexcept` (`std::string` moves are); with a throwing-move element type, `move_if_noexcept` falls back to copies so the old array stays intact until commit. `push(const&)` copies first, so a throwing copy leaves the stack unchanged. `pop`: strong for `std::string` (move constructor is noexcept; the size decrements after the move). `top`: throws `out_of_range`, no state change.

Caveat to state in a defense: `new std::string[n]` default-constructs `n` strings, which is wasteful (a real implementation uses raw storage and placement new or `std::vector`). Also `pop` leaves a moved-from string in the dead slot, overwritten at the next push.

Tests to include (the lesson required these): a `Throwy` element type with a static countdown that throws on copy, asserting the stack size and contents unchanged after a failed `push` growth; a counting element asserting constructions equal destructions; self-assignment; reuse after move; 10,000 pushes.

Alternative: store `std::unique_ptr<std::string[]>`: the rule of zero then needs only the copy operations written by hand (or deleted), and the leak-on-exception catch blocks disappear. State this trade-off.

## Section 9: Project reference solution (verified)

`Matrix` (verified under ASan+UBSan with the tests described below):

```cpp
class Matrix {
public:
    Matrix() noexcept = default;
    Matrix(std::size_t rows, std::size_t cols) : rows_{rows}, cols_{cols} {
        if (cols != 0 && rows > static_cast<std::size_t>(-1) / cols / sizeof(double))
            throw std::length_error("Matrix: size overflow");
        const std::size_t n = rows * cols;
        data_ = n ? new double[n]() : nullptr;
    }
    Matrix(const Matrix& o) : Matrix(o.rows_, o.cols_) {
        std::copy(o.data_, o.data_ + rows_ * cols_, data_);
    }
    Matrix(Matrix&& o) noexcept
        : data_{std::exchange(o.data_, nullptr)}, rows_{std::exchange(o.rows_, 0)},
          cols_{std::exchange(o.cols_, 0)} {}
    Matrix& operator=(const Matrix& o) { Matrix tmp(o); swap(tmp); return *this; }
    Matrix& operator=(Matrix&& o) noexcept { Matrix tmp(std::move(o)); swap(tmp); return *this; }
    ~Matrix() { delete[] data_; }
    void swap(Matrix& o) noexcept { std::swap(data_, o.data_); std::swap(rows_, o.rows_); std::swap(cols_, o.cols_); }
    std::size_t rows() const noexcept { return rows_; }
    std::size_t cols() const noexcept { return cols_; }
    double& at(std::size_t r, std::size_t c) { check(r, c); return data_[r * cols_ + c]; }
    const double& at(std::size_t r, std::size_t c) const { check(r, c); return data_[r * cols_ + c]; }
private:
    void check(std::size_t r, std::size_t c) const { if (r >= rows_ || c >= cols_) throw std::out_of_range("Matrix::at"); }
    double* data_ = nullptr;
    std::size_t rows_ = 0, cols_ = 0;
};
```

(Includes: `<algorithm> <cstddef> <stdexcept> <utility>`.) Invariant: `data_ == nullptr` iff `rows_ * cols_ == 0`; otherwise it points to exactly `rows_ * cols_` doubles owned solely by the object. Note: with `rows_ = 0, cols_ = 5`, `data_` is null and `cols_` is 5 (a 0x5 matrix); the moved-from state is 0x0. The overflow check `rows > SIZE_MAX / cols / sizeof(double)` is the division form that avoids overflowing the multiplication itself. Verified the constructor throws `std::length_error` for `Matrix(SIZE_MAX/2, 4)`.

`UniqueFd` (POSIX; verified, including a test that the descriptor is closed after scope exit via `fcntl(fd, F_GETFD) == -1`):

```cpp
class UniqueFd {
public:
    UniqueFd() noexcept = default;
    explicit UniqueFd(int fd) noexcept : fd_{fd} {}
    UniqueFd(const UniqueFd&) = delete;
    UniqueFd& operator=(const UniqueFd&) = delete;
    UniqueFd(UniqueFd&& o) noexcept : fd_{std::exchange(o.fd_, -1)} {}
    UniqueFd& operator=(UniqueFd&& o) noexcept {
        if (this != &o) { reset(); fd_ = std::exchange(o.fd_, -1); }
        return *this;
    }
    ~UniqueFd() { reset(); }
    int get() const noexcept { return fd_; }
    bool valid() const noexcept { return fd_ >= 0; }
    [[nodiscard]] int release() noexcept { return std::exchange(fd_, -1); }
    void reset(int fd = -1) noexcept { if (fd_ >= 0) ::close(fd_); fd_ = fd; }
private:
    int fd_ = -1;
};
```

Test highlights: `static_assert(std::is_nothrow_move_constructible_v<Matrix>)`, `static_assert(!std::is_copy_constructible_v<UniqueFd>)`; copy independence; moved-from is 0x0; self-assignment; `at` out of range; `vector<Matrix>` with 50 `emplace_back`s; open `/dev/null`, move the owner, confirm still open, leave scope, confirm closed.

Mid-way change (`resize`): allocate a new `Matrix tmp(r, c)`, copy the overlapping region (`min(rows)`, `min(cols)`), `swap` (strong guarantee because the only throwing step is the allocation).

Injecting a throwing allocation: replace global `operator new` in the test binary with a version that throws when a static counter hits zero (use `std::malloc` inside; remember the matching `operator delete`), then assert that after a failed copy assignment the target is unchanged. Alternative that needs no replacement: construct with an absurd size (throws `length_error`) as the failing step. Note that replacing `operator new` interacts with sanitizers (ASan intercepts it); verify on your compiler (`VERIFY`).

Known limitation to mention in the design note: `UniqueFd::reset` ignores `close` errors. For descriptors where a late write error matters, add an explicit `int close()` that returns `-1`/`errno`, leaving the destructor as a safety net.

Rubric scoring notes (100): rule of five and invariants 25 (5 each: copy ctor, copy assign, move ctor, move assign, destructor); tests 20 (moved-from, self-assign, throwing path, vector storage); sanitizer-clean 10; overflow validation 10; exception-safety table 10 (accuracy: marking copy assignment "no-throw" is a 5-point deduction); `UniqueFd` 10; `DESIGN.md` 10; clarity/const/warnings 5.

Extension (rule of zero): with `std::unique_ptr<double[]> data_`, only the copy constructor/assignment need writing (deep copy) and the move operations default; `static_assert` the nothrow-move traits still hold (they do, since `unique_ptr`'s moves are `noexcept`). Lost: nothing observable; gained: roughly half the code and no leak window in constructors.
