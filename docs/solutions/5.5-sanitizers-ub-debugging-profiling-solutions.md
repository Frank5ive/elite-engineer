## A. Retrieval practice answers

1. Undefined: no requirement at all (`INT_MAX + 1`, null dereference, data race). Unspecified: the standard allows a set of outcomes, implementation need not document which (order of evaluation of function arguments, the address returned by `new`). Implementation-defined: the implementation must document its choice (`sizeof(int)`, signedness of plain `char`, right shift of negative values before C++20). Only UB removes all guarantees.
2. The optimizer reasons over the whole program under the assumption "UB never happens"; it may therefore move, merge or delete earlier operations (a check that is only ever true on a UB path, a store whose value is used only after UB). Example from the lesson: `deref_then_check` loses its null test because the dereference precedes it.
3. `mov eax, 1; ret`: always true. Signed overflow is UB, so `x + 1 > x` cannot be false. Observed also at `-O0` for GCC (constant folding in the front end). With `-fwrapv` or unsigned arithmetic the answer changes.
4. The accessed address is immediately past the end of the allocation: an off-by-one (index == size) or a loop bound `<=`. Use-after-free report stacks: (1) the faulting access, (2) where the memory was freed, (3) where it was allocated.
5. Both reserve and manage shadow memory and intercept allocation/synchronization in incompatible ways; the runtimes cannot coexist. For a failing multithreaded test: TSan (races), and separately ASan+UBSan for memory errors; run them as separate jobs.
6. `-fno-sanitize-recover=undefined` (compile time). Observed exit code 1 on the first report. Without it, UB reports scroll by while CI stays green.
7. Signed overflow: UBSan, then `-ftrapv` (VERIFY semantics) or review with `__builtin_add_overflow`. `v[v.size()]`: ASan (heap), then `-D_GLIBCXX_ASSERTIONS`. Uninitialized read: MSan on clang or valgrind memcheck (VERIFY; neither available when written), then `-Wmaybe-uninitialized` at `-O2` and `-fanalyzer`. Data race: TSan, then review of shared state with a lock/atomic discipline. Dangling `string_view` of a temporary: ASan (heap-use-after-free when the string is beyond the small-string buffer), then `-Wdangling-gsl`-style warnings where the compiler has them (VERIFY).
8. Reaching a use of a variable along a path where it was not assigned requires data-flow analysis, which GCC only performs when the optimizer runs (observed: warning at `-O2`, none at `-O0`). In CI, compile with warnings at your release optimization level, not only at `-O0`.
9. gprof: compile-time instrumentation (`-pg`) records call counts at function entry plus a 0.01 s sampling timer; coarse, ignores shared-library time, perturbs inlining. perf (VERIFY): kernel-assisted statistical sampling of the instruction pointer (and optionally call stacks and hardware counters) with low overhead and no recompile except for good stacks; blind spots: needs frame pointers or DWARF for call graphs, sampling skid, off-CPU time not shown by default.
10. At `-O0` nothing is inlined, so tiny abstractions look hot; the optimized build removes most of that cost. Profile the build you ship (`-O2 -g`).
11. gdb: `watch var` (hardware watchpoint if available) stops when it is written; `gdb ./prog core.<pid>` then `bt`, `frame N`, `info locals` (VERIFY). The binary must match the one that crashed.
12. `-fwrapv` redefines `int` overflow as wraparound for this translation unit: a non-standard dialect, not portable to other compilers or flags, and it hides the lack of a precondition check while preventing optimizations. It is defensible for legacy code that is relied on wrapping and where hardening is documented; better is unsigned arithmetic or explicit checked arithmetic.

## B. Autopsies of the six programs (reference)

Template used: Symptom | Class | Tool and command | Evidence | Root cause ("X assumed Y, but Z") | Fix | Regression test | Why it seemed to work.

| Bug | Class | Tool | Evidence (observed) | Root cause | Fix | Why it seemed to work |
|---|---|---|---|---|---|---|
| 1 off by one | heap bounds | ASan | `heap-buffer-overflow`, `READ of size 4`, `0 bytes after 32-byte region`, line 8 | the loop assumed `i <= size()` was a valid index range, but valid indexes end at `size()-1` | range-for | the extra byte often exists in the allocator's slack, so the read returns garbage without a crash |
| 2 invalidated reference | lifetime | ASan | `heap-use-after-free`, three stacks: access line 10, freed line 9 (inside `push_back`), allocated line 7 | the code assumed a reference into the vector stays valid, but `push_back` at size == capacity reallocated | take the reference after the last mutation, or keep an index | freed memory is rarely reused immediately, so the stale bytes still look right |
| 3 overflow check | UB, optimizer | UBSan; assembly | UBSan `signed integer overflow: 2147483647 + 1`; plain builds printed 0 | assumed `int` wraps, but signed overflow is UB so `x + 1 < x` is false by assumption | `x == INT_MAX` | on a "wrapping" mental model the code reads correctly; the optimizer disagrees |
| 4 uninitialized | indeterminate value | `-Wmaybe-uninitialized` (-O2), `-fanalyzer`; MSan or valgrind (VERIFY) | warning at `-O2`, none at `-O0`; output 32753 vs 0 in different builds | assumed `result` was assigned on all paths, but `n <= 0` skips the assignment | initialize (or return `std::optional`) | stack garbage is often zero, so tests passed |
| 5 race | data race | TSan | `WARNING: ThreadSanitizer: data race`, read and previous write at line 8; ASan build printed 137354 and 100000 on different runs | assumed `++counter` is atomic, but it is a non-atomic read-modify-write on shared memory | `std::atomic<int>` or a mutex | small iteration counts rarely overlap |
| 6 comparator | contract violation | ASan | `heap-buffer-overflow` in `__unguarded_partition` | assumed `<=` is a valid ordering, but the algorithm requires a strict weak ordering | `<` | the same program returned normally at `-O2` without sanitizers |

Regression tests: bug 1: call `fix1` with the exact vector and compare, built in the ASan variant; bug 2: run under ASan (the test is the sanitizer plus the program); bug 3: test `fix3(INT_MAX)` true and `fix3(0)` false in a UBSan build; bug 4: call `fix4(0)` and compare to 0 (and compile with `-ftrivial-auto-var-init=pattern` to make an old bug loud); bug 5: run `fix5()` 20 times under TSan and assert 200000 each time; bug 6: sort 1000 equal elements under ASan.

Fixed versions, verified clean under ASan+UBSan, under TSan, and at `-O2`:

```cpp
// file: fixed_all.cpp  (C++20)  Fixed versions of bugs 1-6.
#include <algorithm>
#include <atomic>
#include <climits>
#include <cstdio>
#include <string>
#include <thread>
#include <vector>

int fix1(const std::vector<int>& v) {            // bug 1: iterate exactly the valid range
    int sum = 0;
    for (int x : v) sum += x;
    return sum;
}
char fix2() {                                    // bug 2: do not hold a reference across a mutation
    std::vector<std::string> names{std::string(40, 'a')};
    names.push_back(std::string(40, 'b'));
    const std::string& first = names[0];         // take the reference AFTER the last push_back
    return first[0];
}
bool fix3(int x) { return x == INT_MAX; }        // bug 3: test the precondition, not the wrapped result
int fix4(int n) {                                // bug 4: every path initializes
    int result = 0;
    if (n > 0) result = n * 2;
    return result;
}
int fix5() {                                     // bug 5: atomic counter (a mutex also works)
    std::atomic<int> counter{0};
    auto work = [&counter] { for (int i = 0; i < 100000; ++i) counter.fetch_add(1, std::memory_order_relaxed); };
    std::thread a(work), b(work);
    a.join();
    b.join();
    return counter.load();
}
std::size_t fix6() {                             // bug 6: strict weak ordering
    std::vector<int> v(1000, 7);
    std::sort(v.begin(), v.end(), [](int a, int b) { return a < b; });
    return v.size();
}

int main() {
    int fails = 0;
    auto check = [&](bool ok, const char* what) { if (!ok) { std::printf("FAIL %s\n", what); ++fails; } };
    check(fix1(std::vector<int>(8, 1)) == 8, "fix1");
    check(fix2() == 'a', "fix2");
    check(fix3(INT_MAX) && !fix3(0), "fix3");
    check(fix4(0) == 0 && fix4(3) == 6, "fix4");
    check(fix5() == 200000, "fix5");
    check(fix6() == 1000, "fix6");
    std::puts(fails ? "FAILED" : "all fixed versions pass");
    return fails;
}
```

Alternatives for bug 5: a mutex around the increment (simple, correct, slower under contention); per-thread partial sums combined after `join` (no sharing at all, usually the best design; see 5.6); relaxed `fetch_add` is sufficient here because only the final value after `join` is observed (`join` synchronizes).

## C. Challenge 1: sanitizer matrix

```cpp
// file: matrix.cpp  (C++20)  usage: ./matrix <1-7>
#include <climits>
#include <cstdio>
#include <cstdlib>
#include <thread>

int g = 0;
int main(int argc, char** argv) {
    const int which = argc > 1 ? std::atoi(argv[1]) : 0;
    switch (which) {
        case 1: { int* p = new int[4]; p[4] = 1; delete[] p; } break;                       // heap overflow
        case 2: { int a[4] = {0, 1, 2, 3}; volatile int i = 4; a[i] = 1; std::printf("%d\n", a[0]); } break;  // stack overflow
        case 3: { int* p = new int(5); delete p; std::printf("%d\n", *p); } break;           // use after free
        case 4: { volatile int x = INT_MAX; std::printf("%d\n", x + 1); } break;             // signed overflow
        case 5: { std::thread t([] { for (int i = 0; i < 100000; ++i) ++g; });
                  for (int i = 0; i < 100000; ++i) ++g;
                  t.join(); std::printf("%d\n", g); } break;                                 // data race
        case 6: { int* p = new int[100]; p[0] = 1; std::printf("%d\n", p[0]); } break;       // leak
        case 7: { int x; if (argc > 5) x = 1; std::printf("%d\n", x); } break;               // uninitialized read
        default: std::puts("usage: matrix <1-7>");
    }
}
```

Build once with `-g -fsanitize=address,undefined` and once with `-fsanitize=thread`. Observed first report lines:

| Case | Detector | First line observed |
|---|---|---|
| 1 heap overflow | ASan | `ERROR: AddressSanitizer: heap-buffer-overflow` |
| 2 stack array overflow | UBSan (bounds) | `runtime error: index 4 out of bounds for type 'int [4]'` (UBSan fired first; ASan's stack report would be the detector where the bound is not visible, e.g. through a pointer) |
| 3 use after free | ASan | `ERROR: AddressSanitizer: heap-use-after-free` |
| 4 signed overflow | UBSan | `runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'` |
| 5 data race | TSan | `WARNING: ThreadSanitizer: data race`; the ASan build printed a wrong count and no report |
| 6 leak | LSan (in ASan) | `ERROR: LeakSanitizer: detected memory leaks` |
| 7 uninitialized read | none of ASan/UBSan/TSan (silent); `-Wall -Wextra -O2` warned (`maybe-uninitialized`); MSan or valgrind (VERIFY) | - |

Scoring: a reader who expects ASan to find case 5 or 7 has a misconception to log; prediction accuracy matters more than the table being complete.

## D. Challenge 2: profile-driven fix

Hot spot: `contains` (linear scan) called once per input element. Fix: a hash set of seen values, preserving first-occurrence order.

```cpp
// file: prof_demo2.cpp  (C++20)
#include <cstdio>
#include <random>
#include <unordered_set>
#include <vector>

std::vector<int> dedupe(const std::vector<int>& in) {  // same output order as the O(n^2) version
    std::vector<int> out;
    std::unordered_set<int> seen;
    seen.reserve(in.size());
    for (int x : in) if (seen.insert(x).second) out.push_back(x);
    return out;
}
long checksum(const std::vector<int>& v) { long s = 0; for (int x : v) s += x; return s; }
int main() {
    std::mt19937 rng(1);
    std::vector<int> in(60000);
    for (int& x : in) x = static_cast<int>(rng() % 30000);
    const auto out = dedupe(in);
    std::printf("%zu unique, checksum %ld\n", out.size(), checksum(out));
}
```

Observed: the original and the fixed program both printed `25847 unique, checksum 387228006`. Method (you write the numbers yourself): build both with `-O2`, run each 10+ times with a shell loop (`for i in $(seq 10); do ...`) or a chrono harness, take the median, report CPU model and compiler; profile the fixed program and check that the hash-set operations (not `contains`) now lead, or that the total is too small to sample. Tests required by the challenge: empty input (no elements), all duplicates (one output), and five seeds compared byte-for-byte between old and new. Alternatives: a `std::vector<bool>`/bitmap when the value range is small and known (fastest, fragile when the range changes); sort+unique does NOT satisfy the constraint (order changes) unless you track original indexes.

## E. Challenge 3: build script

```sh
#!/bin/sh
# file: build_san.sh   usage: ./build_san.sh prog.cpp     (POSIX sh; tested with g++ 14.2)
set -eu
src=$1
base=${src%.cpp}
CXX=${CXX:-g++}
W="-std=c++20 -Wall -Wextra -Wpedantic -g -pthread"
$CXX $W -O1 -fno-omit-frame-pointer -fsanitize=address,undefined -fno-sanitize-recover=undefined "$src" -o "$base.asan"
$CXX $W -O1 -fno-omit-frame-pointer -fsanitize=thread "$src" -o "$base.tsan"
$CXX $W -O2 -DNDEBUG "$src" -o "$base.rel"
# run_all: stop at the first failing variant (sanitizers exit non-zero on a report)
for v in asan tsan rel; do
    echo "== $base.$v"
    "./$base.$v" || { echo "FAILED: $base.$v exited with status $?"; exit 1; }
done
echo "all variants clean"
```

Observed with the script: `bug1_off_by_one` failed in the `.asan` variant (`heap-buffer-overflow`, script printed `FAILED`, status 1); `bug3_overflow_check` failed in `.asan` through UBSan with `-fno-sanitize-recover` (status 1); `bug5_race` passed `.asan` (printing a wrong counter, exit 0), then TSan reported the race and the script stopped; the fixed program (`fixed_all.cpp`) passed all three variants (`all variants clean`). Lesson: the `.asan` variant alone does not find races, and the `.rel` variant finds nothing; the three are complementary.

## F. Project reference notes

Three original bugs used while preparing these solutions (each verified):

1. `orig_lambda.cpp`: a lambda that captures a local by reference is returned from its function. Observed: ASan reported `stack-use-after-return` in g++ 14.2.
2. `orig_vecbool.cpp`: two threads write `flags[0]` and `flags[1]` of a `std::vector<bool>`. Observed: TSan reported a data race, because `vector<bool>` packs elements into shared words; element-level independence does not hold for it.
3. `orig_logic.cpp`: integer division in an average. Observed: prints `2.00` where the answer is 2.33; no sanitizer objects; `-Wconversion -Wsign-conversion` warned about the conversions at the division line. Diagnosis is by a minimal input and reading the types, not a tool.

```cpp
// file: orig_lambda.cpp  (C++20)
#include <cstdio>
#include <functional>

std::function<int()> make_counter() {
    int count = 0;
    return [&count] { return ++count; };  // captures a local by reference, outlives the function
}

int main() {
    auto next = make_counter();
    std::printf("%d\n", next());
}
```

```cpp
// file: orig_vecbool.cpp  (C++20)
#include <cstdio>
#include <thread>
#include <vector>

int main() {
    std::vector<bool> flags(64, false);  // bits packed into words
    std::thread a([&] { for (int i = 0; i < 1000; ++i) flags[0] = true; });
    std::thread b([&] { for (int i = 0; i < 1000; ++i) flags[1] = true; });  // different element, same word
    a.join();
    b.join();
    std::printf("%d %d\n", static_cast<int>(flags[0]), static_cast<int>(flags[1]));
}
```

```cpp
// file: orig_logic.cpp  (C++20)
#include <cstdio>
#include <vector>

double average(const std::vector<int>& v) {
    int sum = 0;
    for (int x : v) sum += x;
    return sum / v.size();  // integer division, and size_t conversion: no sanitizer objects
}
int main() { std::printf("%.2f\n", average({1, 2, 4})); }  // prints 2.00, correct answer 2.33
```

Policy sketch (policy.md): every PR: warnings at `-O2` with `-Wall -Wextra -Wpedantic` as errors for project code; ASan+UBSan test job (no recover); nightly: TSan job, longer randomized tests, optional clang-tidy with a curated check list (VERIFY); release builds without sanitizers but with symbols stored per release; a sanitizer finding blocks merge unless a written suppression names the root cause and an owner.

Rubric scoring notes: full evidence points require excerpts that are *observed* (compare against your own run; the first line and the line numbers must match your build). Unmarked statements about gdb, perf, MSan or valgrind output are an automatic deduction in the evidence criterion. A regression test that passes on the broken version earns zero for that item. Critical failure examples: fixing bug 5 by `sleep`, or fixing bug 4 by adding `-ftrivial-auto-var-init=zero` alone.
