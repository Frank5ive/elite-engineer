## 1. Engineering problem

You join a team that monitors payment fraud. A screening model flags a transaction as fraudulent with 90% probability when it really is fraud (sensitivity) and wrongly flags 5% of legitimate transactions (false-positive rate). Fraud is 1% of traffic. A product manager says: "The model is 90% accurate, so when it flags something we should auto-block the card." What fraction of flagged transactions are actually fraud?

Most people answer 90%. The correct answer is 15.4% (derived in section 3.3). Blocking on that basis means roughly five of every six blocked customers are innocent. That single error, confusing P(flag | fraud) with P(fraud | flag), is the base-rate fallacy, and it appears in trading signals, medical tests, security alerts and A/B-test readouts.

The same family of mistakes shows up in code: a simulation reporting "probability 1.0, standard error 0" because every trial reused one seed; a test asserting `estimate == 0.1667`; a risk number built on a mean that never settles because the tail is too fat (3.8). Quantitative work is two skills: getting the mathematics right on paper, and building software whose output you can distrust productively (tests with stated tolerances against known answers). This lesson trains both, in that order.

## 3. First-principles explanation

### 3.0 Bridge from algebra: exponents, logs, summation

Exponents: a^m * a^n = a^(m+n); (a^m)^n = a^(mn); a^(-n) = 1/a^n; a^(1/2) = sqrt(a). Growth of 5% a year for n years multiplies by 1.05^n.

Logarithms invert exponents: ln(x) = y means e^y = x, e = 2.71828.... Rules: ln(ab) = ln a + ln b; ln(a/b) = ln a - ln b; ln(a^k) = k ln a. Products become sums, so growth factors multiply but log-returns add. Check: price 100 -> 110 -> 99: ln(110/100) + ln(99/110) = 0.09531 - 0.10536 = -0.01005 = ln(0.99). For small x, ln(1+x) is about x (ln 1.01 = 0.00995; ln 0.99 = -0.01005). A product of 1000 small probabilities underflows to 0.0; the sum of their logs does not.

Summation: sum_{i=1}^{n} x_i means x_1 + ... + x_n. Prove: sum_{i=1}^{n} i = n(n+1)/2 (pair first with last); sum_{k=0}^{inf} r^k = 1/(1-r) for |r|<1 (S - rS = 1). Constants factor out; the mean is xbar = (1/n) sum x_i; a double sum is a nested loop.

### 3.1 Sample spaces and events

A **sample space** S is the set of all outcomes; an **event** is a subset. With equally likely outcomes, P(A) = |A| / |S|. Two fair dice: |S| = 36, the event "sum = 7" has 6 outcomes, so P = 6/36 = 1/6 (simulated, seed 1, N = 200,000: 0.16584 with standard error 0.00083; the truth is inside one standard error).

Axioms (Kolmogorov): P(A) >= 0; P(S) = 1; for disjoint A, B: P(A or B) = P(A) + P(B). Everything else follows. Two you will use constantly:

    P(not A) = 1 - P(A)                 P(A or B) = P(A) + P(B) - P(A and B)

"At least one" problems are usually easiest through the complement. P(at least one six in 4 rolls of a die) = 1 - (5/6)^4 = 0.5177; P(at least one double six in 24 rolls of two dice) = 1 - (35/36)^24 = 0.4914. (The first bet is favourable, the second is not.)

**Independence**: A and B are independent iff P(A and B) = P(A)P(B). It is a statement about numbers, not about causation. Independence is the assumption most often smuggled into financial models and most often false (assets crash together).

### 3.2 Conditional probability

P(A | B) = P(A and B) / P(B), the probability of A inside the world where B happened. Rearranged it is the multiplication rule: P(A and B) = P(A | B) P(B).

Classic trap: two dice, you learn "at least one is a six". P(both sixes | at least one six) = (1/36) / (11/36) = 1/11 = 0.0909, not 1/6. Simulated by rejection (keep only trials satisfying the condition): 0.09058 from 305,688 accepted trials. Notice the cost of rejection sampling: only 30.6% of the 1,000,000 trials were usable. That is a general principle: conditioning on a rare event throws away most of your samples, and your standard error is set by the accepted count, not the total.

### 3.3 Bayes' rule and the base-rate trap

Because P(A and B) = P(A|B)P(B) = P(B|A)P(A):

    P(A | B) = P(B | A) P(A) / P(B),     P(B) = P(B|A)P(A) + P(B|not A)P(not A)

The second line is the **law of total probability**: split the world into cases.

Fraud example, using natural frequencies (the trick that removes the confusion). Imagine 10,000 transactions:

    fraud:        100   -> 90 flagged, 10 missed
    legitimate: 9,900   -> 495 flagged (5%), 9,405 pass
    flagged total = 90 + 495 = 585,  fraudulent among them = 90
    P(fraud | flagged) = 90/585 = 0.1538

Formally: (0.90 x 0.01) / (0.90 x 0.01 + 0.05 x 0.99) = 0.009 / 0.0585 = 0.15385. The posterior is dominated by the base rate: 495 innocent flags swamp 90 true ones. Variations from the same formula: prevalence 0.1% gives 1.77%; a second independent positive result from the same test turns a prior of 0.1538 into 0.7660 (independence of repeated tests is itself an assumption).

What you do with this: report precision (P(fraud | flag)) separately from recall (P(flag | fraud)); never judge a screening signal without the base rate. Alternatives to auto-blocking: raise the threshold, add a second stage, or make the action cheap and reversible (step-up authentication).

### 3.4 Random variables, expectation, variance

A **random variable** X is a numeric function of the outcome. Its **expectation** is the probability-weighted average:

    E[X] = sum_i x_i p_i        (discrete)        E[X] = integral x f(x) dx   (continuous)

It is the long-run average, not the most likely value, and may be a value X never takes (a die has E = 3.5).

Linearity (holds always, even for dependent variables): E[aX + bY + c] = aE[X] + bE[Y] + c. Proof for one term: E[aX+b] = sum (a x_i + b) p_i = a sum x_i p_i + b sum p_i = aE[X] + b.

**Variance** measures spread: Var(X) = E[(X - mu)^2] = E[X^2] - mu^2. Derivation of the second form: E[(X-mu)^2] = E[X^2 - 2 mu X + mu^2] = E[X^2] - 2 mu^2 + mu^2. Standard deviation sigma = sqrt(Var) has the units of X. Var(aX+b) = a^2 Var(X): shifting does nothing, scaling by a scales sigma by |a|.

Fair die: E = 3.5, E[X^2] = 91/6, Var = 91/6 - 12.25 = 35/12 = 2.9167. Sum of two independent dice: variance adds, 35/6 = 5.8333.

A single-number roulette bet (win 35 w.p. 1/37, else lose 1) has E = -1/37 = -0.0270 and sigma = 5.84: the noise of one bet is over 200 times the edge.

### 3.5 Covariance and correlation

For two variables: Cov(X,Y) = E[(X-mu_X)(Y-mu_Y)] = E[XY] - E[X]E[Y]. Positive when they move together. Units are X-units times Y-units, hence hard to read; normalize:

    Corr(X,Y) = Cov(X,Y) / (sigma_X sigma_Y),     always in [-1, 1]

Key facts and their traps:

- Var(X + Y) = Var(X) + Var(Y) + 2 Cov(X,Y). This is the entire basis of diversification: for a portfolio, the covariance term is what you reduce.
- Independent implies Cov = 0. The converse is false. Take X ~ Normal(0,1), Y = X^2: Y is a function of X yet Cov(X, X^2) = E[X^3] - 0 = 0. Simulated sample correlation at 100,000 draws (seed 4): 0.0151. The exact value is 0. The sampling standard error of this sample correlation is sqrt(E[X^2 (X^2-1)^2] / Var(X^2) / n) = sqrt(10/2/100000) = 0.0071 (checked across 30 seeds: mean 0.0013, spread 0.0069), so 0.0151 is 2.1 standard errors from zero, an ordinary draw for one seed.
- Y = X + noise, X and noise independent Normal(0,1): Cov = 1, sigma_Y = sqrt 2, Corr = 1/sqrt 2 = 0.7071 (sample, seed 4, n = 100,000: 0.7062). Correlation measures linear association only.

### 3.6 The named distributions

**Bernoulli(p)**: one yes/no trial. P(1) = p. Mean p, variance p(1-p). Everything below is built from it.

**Binomial(n, p)**: number of successes in n independent Bernoulli trials. P(X = k) = C(n,k) p^k (1-p)^(n-k). Mean np, variance np(1-p) (sum of n independent Bernoulli variances). Example n = 10, p = 0.3, k = 3: C(10,3) = 120, 120 x 0.027 x 0.0823543 = 0.2668. Fails when trials are not independent or p is not constant (defaults cluster in recessions).

**Poisson(lambda)**: count of events in a fixed window when events are rare, independent, and arrive at a steady rate. P(X = k) = e^(-lambda) lambda^k / k!. Mean = variance = lambda. It is the limit of Binomial(n, p) with n -> infinity, np = lambda. Check: n = 100, p = 0.02: P(X=0) = 0.98^100 = 0.1326 vs e^-2 = 0.1353. Practical test of fit: variance/mean of observed counts well above 1 ("overdispersion", typical of bursty traffic) means Poisson is wrong.

**Uniform(a, b)**: density 1/(b-a) on [a,b]; mean (a+b)/2, variance (b-a)^2/12 (Uniform(0,1): 1/12 = 0.08333). `random.random()` approximates it; every other sampler is built from it.

**Normal(mu, sigma^2)**: density (1/(sigma sqrt(2 pi))) exp(-(x-mu)^2/(2 sigma^2)). Standardize z = (x - mu)/sigma. Memorize: P(|Z| < 1) = 0.6827, P(|Z| < 1.96) = 0.9500, P(|Z| < 3) = 0.9973. Phi(1) = 0.8413, Phi(2) = 0.9772. Example: IQ-like Normal(100, 15^2), P(X > 130) = P(Z > 2) = 0.0228. It is common because of the CLT (3.8), not because data "is" normal. Financial returns have heavier tails than Normal (6.4 revisits this); using normal tail probabilities for crash risk understates it.

### 3.7 Sampling from them (how the engine works)

Uniform comes from the PRNG (Mersenne Twister in CPython). Bernoulli: `u < p`. Binomial: count n Bernoulli trials (O(n); fine for teaching). Poisson by Knuth: multiply uniforms until the product drops below e^(-lambda); the count of multiplications minus one is Poisson(lambda). It fails for large lambda because e^(-lambda) underflows (`math.exp(-746)` is exactly 0.0 in double precision): with lambda = 800 the code in section 4 returned values averaging 736 over five draws, not 800 (739, 788, 708, 737, 710; the standard error of a 5-draw mean is about 13, so this is a bug, not noise). Normal by Box-Muller: Z = sqrt(-2 ln U1) cos(2 pi U2) gives a standard normal from two uniforms; guard U1 = 0 (use 1 - random(), which lies in (0,1]).

### 3.8 Law of large numbers and the CLT

**LLN**: the average of n independent draws with finite mean converges to the mean. Running mean of die rolls (seed 11): n = 10 -> 4.000; 100 -> 3.340; 1,000 -> 3.473; 10,000 -> 3.4989; 100,000 -> 3.49777; 1,000,000 -> 3.501446. It converges, but the error shrinks like sigma/sqrt(n), not 1/n. To gain one more decimal digit you need 100 times more samples. This is the single most important scaling law in Monte Carlo (6.3 measures it).

**Standard error**: Var(xbar) = (1/n)^2 n sigma^2 = sigma^2/n, so SE = sigma/sqrt(n); for a hit fraction, SE = sqrt(p(1-p)/n). With p = 0.3, the sample SE was 0.0446 at n = 100 (truth 0.0458), 0.00459 at 10,000 and 0.000458 at 1,000,000.

**CLT**: for iid draws with finite variance, (xbar - mu)/(sigma/sqrt n) approaches Normal(0,1) as n grows, regardless of the original shape. Check: sum 30 Uniform(0,1) variables (mean 15, variance 30/12), standardize, 100,000 trials: P(Z <= 1) = 0.84112 vs Phi(1) = 0.84134; P(Z <= -2) = 0.02224 vs 0.02275. Tail probabilities converge slowest, which is exactly where risk lives.

**Counterexample**: Cauchy has no mean; the average of n Cauchy draws is again Cauchy for every n. Over 2,000 seeds, P(|average| > 1) was 0.4985 at n = 100 and 0.502 at n = 10,000 (exact value 0.5): averaging does not help. LLN and CLT have hypotheses (finite mean; finite variance); check the tail before trusting a mean.

### 3.9 When to use it, when not to

Monte Carlo suits problems whose analytic answer is intractable, and checks on those that have one. Avoid it when a closed form exists (use that as the oracle), when the event is too rare to sample (importance sampling, beyond this volume), or when you cannot defend the distribution assumption.

Agreement between pencil answer and simulation proves your code implements your model. It says nothing about whether the model matches the world.

## 4. Worked example

Goal: a minimal Monte Carlo engine that returns an estimate with its uncertainty, and tests that fail when the code is wrong but not by chance. Design choices first.

1. **Pass `random.Random` explicitly** rather than using the module-level generator: no hidden global state, trivially reproducible, parallel-safe later.
2. **Seed per estimate.** One `seed` argument per call gives reproducibility; different tests use different seeds so one lucky stream cannot hide a bug.
3. **Return an `Estimate` (mean, stderr, n)** not a bare float. A number without uncertainty is not a result.
4. **Welford's update** for variance instead of `E[x^2] - E[x]^2`: the latter subtracts two nearly equal large numbers when the mean is large relative to the spread (catastrophic cancellation; lesson 6.2 quantifies it: variance of 100,000 values near 1e9 with true spread 1 came out as -128.0 by the naive formula, impossible for a variance).
5. **Tolerance = z x stderr** with z = 4. A true correct implementation fails a z = 4 two-sided check with probability about 6.3e-5, so tests are not flaky, but a bug biasing the estimate by more than about 4 standard errors is caught. Increase N to shrink SE; do not widen z to make tests pass.

```python
# probsim.py - Python 3.12+, stdlib only
from __future__ import annotations
import math, random
from dataclasses import dataclass
from typing import Callable

@dataclass(frozen=True)
class Estimate:
    mean: float
    stderr: float
    n: int
    def interval(self, z: float = 1.96) -> tuple[float, float]:
        return (self.mean - z * self.stderr, self.mean + z * self.stderr)
    def consistent_with(self, truth: float, z: float = 4.0) -> bool:
        return abs(self.mean - truth) <= z * self.stderr

def estimate(draw: Callable[[random.Random], float], n: int, seed: int) -> Estimate:
    if n < 2:
        raise ValueError("need n >= 2")
    rng = random.Random(seed)
    mean = m2 = 0.0
    for k in range(1, n + 1):
        x = draw(rng)
        d = x - mean
        mean += d / k
        m2 += d * (x - mean)
    return Estimate(mean, math.sqrt(m2 / (n - 1) / n), n)

def prob(event: Callable[[random.Random], bool], n: int, seed: int) -> Estimate:
    return estimate(lambda r: 1.0 if event(r) else 0.0, n, seed)

# analytic references (the oracles)
def binom_pmf(k, n, p):  return math.comb(n, k) * p**k * (1 - p) ** (n - k)
def poisson_pmf(k, lam): return math.exp(-lam + k * math.log(lam) - math.lgamma(k + 1))
def normal_cdf(x, mu=0.0, sigma=1.0): return 0.5 * math.erfc(-(x - mu) / (sigma * math.sqrt(2)))
def bayes_posterior(prior, sens, fpr):
    num = sens * prior
    return num / (num + fpr * (1 - prior))

# samplers
def binomial(r, n, p): return sum(r.random() < p for _ in range(n))
def poisson(r, lam):                   # Knuth; valid for lam < ~30 (see 3.7)
    L, k, prod = math.exp(-lam), 0, 1.0
    while True:
        prod *= r.random()
        if prod <= L: return k
        k += 1
def normal_box_muller(r):
    u1 = 1.0 - r.random(); u2 = r.random()
    return math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)
```

Why `poisson_pmf` uses logs: `lam**k / factorial(k)` overflows for k near 170 before the exponential can rescue it; `exp(-lam + k ln lam - lgamma(k+1))` stays finite. This is the log trick from 3.0 in action.

Tests (pytest, N = 200,000 unless noted):

```python
import probsim as ps
N = 200_000

def test_two_dice_sum_seven():
    ev = lambda r: r.randint(1, 6) + r.randint(1, 6) == 7
    assert ps.prob(ev, N, seed=1).consistent_with(1 / 6)

def test_binomial_matches_pmf():
    truth = ps.binom_pmf(3, 10, 0.3)             # 0.26683
    assert ps.prob(lambda r: ps.binomial(r, 10, 0.3) == 3, N, 2).consistent_with(truth)

def test_normal_within_1_96():
    truth = ps.normal_cdf(1.96) - ps.normal_cdf(-1.96)   # 0.950004
    assert ps.prob(lambda r: abs(ps.normal_box_muller(r)) < 1.96, N, 6).consistent_with(truth)

def test_same_seed_same_result():
    f = lambda r: r.random() < 0.3
    assert ps.prob(f, 1000, 9) == ps.prob(f, 1000, 9)
```

The full suite (these tests plus Poisson mean/variance, seed reproducibility, parameter validation, and a Bayes-trap test with 1,000,000 trials whose SE uses the roughly 58,500 positives, not 1,000,000) passed: 8 tests, about 1.3 s here. The Bayes test shows 3.2 in code: count only trials with a positive result and compute the SE from that count.

Naive vs improved: storing all draws and doing a second pass for the variance is correct but O(n) memory and cannot report a running standard error; Welford is single pass, O(1) memory, slightly more arithmetic per draw.

## 5. Production perspective

**Correctness.** Separate three questions: Is the mathematical model right (pencil)? Does the code implement the model (tests against closed forms)? Does the model describe reality (not answerable here; 6.5)? A green suite is evidence only for the second.

**Testing with randomness.** Rules: seed explicitly; derive tolerance from SE, never from "looks close"; never assert exact float equality on a probability; assert reproducibility separately (same seed, same output). A test that fails occasionally is not "flaky randomness": it has a mis-specified tolerance or hides a real rare-event bug; calculate which. With fixed seeds results are deterministic per environment, but may change when the Python version changes its stream.

**Performance.** Measure your draws per second with `time.perf_counter` (it depends on your machine; I quote no number). For 10^8 draws vectorize with numpy (6.3) or use C++ (Vol 5). Because error is sigma/sqrt(N), a 10x speedup buys only 3.16x lower error; variance reduction (6.3) can be worth more than any optimization.

**Failure handling.** Validate parameters (p in [0,1], lambda > 0, n >= 2). Fail loudly on impossible input.

**Observability.** Log seed, N, library versions, estimate and SE for any simulation that feeds a decision.

**What a senior engineer does differently.** Writes the analytic answer or a bound first, then code. Looks at the sample, not only the summary: a histogram, the min/max, the fraction of NaNs. Reports an interval. Asks what the base rate is before accepting an accuracy figure. Keeps the oracle (closed form) in the test suite forever.

**Common beginner mistakes and diagnosis.**

- New `Random(seed)` inside the trial: estimate exactly 0 or 1, SE 0. Check the SE; print the first draws.
- "10x more samples gives 10x accuracy": measure error at N, 10N, 100N; expect improvements of 3.16x and 10x.
- Equating P(B given A) with P(A given B): accuracy quoted as precision. Write the frequency table.
- Zero covariance read as independence: correlate X with X^2; plot a scatter.
- `if est == 0.1667`: compare against z x SE instead.
- Knuth Poisson at large lambda: sample mean far below lambda; compare the two.

## 6. Failure laboratory

Here is a "probability estimator" a colleague wrote to estimate P(sum of two dice = 7) with 100,000 trials.

```python
import random

def estimate_seven(n: int) -> float:
    hits = 0
    for _ in range(n):
        rng = random.Random(42)           # "so it is reproducible"
        hits += rng.randint(1, 6) + rng.randint(1, 6) == 7
    return hits / n

print(estimate_seven(1_000), estimate_seven(100_000))
```

**Predict before reading further:** write down (a) the two printed values, (b) whether they would change with n, (c) what a standard error computed from these trials would be, and (d) which unit test (of the style in section 4) would catch this and which would not.

### Reveal (read after predicting)

On the authoring machine (Python 3.13.5) it prints `1.0 1.0`. Every trial constructs the same generator with the same seed, so every trial draws the same two dice: either all trials hit (1.0) or none do (0.0). The only possible outputs are 0.0 and 1.0, never about 0.1667, and increasing n changes nothing. A standard error computed from these data would be exactly 0 - maximum false confidence.

Which tests catch it: `consistent_with(1/6)` fails (good). `0 <= p <= 1` passes. A reproducibility test passes (perfectly reproducible, perfectly wrong). A hard-coded `0.16` with tolerance 0.2 passes for 0.0 but not for 1.0: tolerance must come from the SE.

Diagnosis procedure for any wrong simulation output: (1) Is the output possible for a healthy run? An estimate of exactly 0 or 1 for a non-degenerate event is a red flag. (2) Is the SE plausible? SE = 0 means no variation between trials. (3) Print the first five draws of two consecutive trials; identical streams reveal shared seeding. (4) Run n = 10, 100, 1000: a healthy error shrinks like 1/sqrt(n). (5) Compare with the oracle at z x SE. (6) Fix: create the generator once, outside the loop, and pass it down.

Second flaw: run `poisson(r, 800)` five times and compare with 800; explain using `math.exp(-800)` (seed 1 gave 739, 788, 708, 737, 710).
