## 1. Engineering problem

You join a desk's quant development team. A trader reports that the options pricer "drifts from the vendor by a few cents on some strikes". A risk manager says the daily 99% VaR "looks too small after last week". A colleague's Monte Carlo price of a plain call is 10.46 while the spreadsheet says 10.45, and nobody knows whether that is noise or a bug.

Each complaint is the same failure: not knowing what a number means, what its error bars are, or how to prove an implementation right. A pricer that is "close" is untestable unless you know the analytic value and the tolerance each method deserves (closed form 1e-9; Monte Carlo a few standard errors; finite differences depends on the step). A VaR without confidence, horizon and sign convention is a number without a unit. Simple and log returns get mixed in one column, and volatility is quoted per day in one place and per year in another.

This lesson separates **mathematical correctness** (is it the right formula for the model?), **implementation correctness** (does the code compute that formula?) and **model adequacy** (is the model a fair description of the market?). Tests establish the second; derivation and independent cross-checks the first; the third is never fully established and you must say so in writing. Nothing here is trading advice: a model price is what the model says, not a price at which you can trade.

## 3. First-principles explanation

### 3.1 Market structure in one page

A **market** matches buyers and sellers. Most electronic exchanges run a **central limit order book** (built in 6.5): resting limit orders at price levels, matched by price then time. Key terms:

- **Bid**: highest price someone will pay now. **Ask** (offer): lowest price someone will sell for now. **Spread** = ask - bid. **Mid** = (bid + ask) / 2.
- **Liquidity**: how much you can trade without moving the price. Measured by spread, depth at the touch, and how quickly depth refills.
- **Market order**: trade now at whatever price is available (pay the spread, walk the book). **Limit order**: trade only at the stated price or better (may never fill).
- **Market impact**: your own trading moves the price against you. A buy order larger than the depth at the best ask consumes several levels. Impact has a temporary part (decays) and a permanent part (information). How large it is for a given order is an empirical question; do not assume a formula without measuring.

Instruments you must be able to describe precisely:

| Instrument | What it is | Key risk driver |
|---|---|---|
| Equity (share) | Ownership claim; pays dividends possibly | Company value, market beta |
| Bond | Promise of coupons and principal | Interest rates, credit |
| Future | Standardised contract to buy/sell an asset at a set price on a set date; marked to market daily via margin | Underlying price, basis, roll |
| Option | Right, not obligation. Call: buy at strike K. Put: sell at strike K. European: exercise only at expiry T. American: any time up to T | Underlying price, volatility, time, rates |

### 3.2 Returns

Given prices `P_0, P_1, ...`:

```
simple return    R_t = P_t / P_{t-1} - 1
log return       r_t = ln(P_t / P_{t-1})
relation         r_t = ln(1 + R_t)         R_t = exp(r_t) - 1
```

- **Time aggregation.** Log returns add: `ln(P_T/P_0) = sum r_t`. Simple returns compound: `1 + R_{0..T} = product (1 + R_t)`.
- **Cross-section aggregation.** A portfolio's simple return is the weighted sum of asset simple returns `R_p = sum w_i R_i`. Log returns do **not** aggregate across assets this way (the log of a sum is not the sum of logs).
- **Bounds.** Simple return is >= -100%; log return is unbounded below but a price stays positive, which suits a lognormal model.
- **Example** (running code): prices 100 -> 110 -> 99 give simple returns +10%, -10% (arithmetic mean 0, yet you lost 1%), log returns +0.09531, -0.10536 (sum -0.010050 = ln 0.99). Always state which average you use.

Rule: use log returns for time-series modelling and statistics across time; use simple returns for portfolio P&L and attribution across assets. Say which one every column is.

### 3.3 Volatility, correlation, diversification

**Volatility** is the standard deviation of returns over a stated period. If period returns are independent with equal variance, variance scales with time: `sigma_T = sigma_1 * sqrt(T)`. Annualisation with 252 trading days: `sigma_annual = sigma_daily * sqrt(252)`. That is a convention (252 is common for equities; other markets and desks differ) and it relies on independence that real returns only approximately satisfy (volatility clusters; returns show weak autocorrelation).

**Sample volatility** uses the n-1 denominator; mixing n and n-1 silently changes results by `sqrt((n-1)/n)`.

**Portfolio variance.** With weights `w`, covariance matrix `C`:

```
Var(R_p) = w' C w = sum_i sum_j w_i w_j C_ij,    C_ij = rho_ij sigma_i sigma_j
```

Two assets, 50/50, sigma_1 = 20%, sigma_2 = 30% (running `portfolio_variance`):

| rho | portfolio variance | portfolio volatility |
|---|---|---|
| +1.0 | 0.0625 | 25.00% |
| +0.5 | 0.0475 | 21.79% |
| 0.0 | 0.0325 | 18.03% |
| -0.5 | 0.0175 | 13.23% |

The weighted average of the volatilities is 25%; portfolio volatility equals it only at rho = +1. Correlation is estimated, unstable (it tends to rise in crises) and linear-only.

### 3.4 Payoffs and put-call parity

At expiry T with spot `S_T` and strike K:

```
long call payoff   max(S_T - K, 0)        long put payoff   max(K - S_T, 0)
profit = payoff - premium paid (ignoring financing)
long straddle = long call + long put, same K: payoff |S_T - K|
```

**Put-call parity** (European, no dividends, continuous rate r): 

```
C - P = S_0 - K exp(-rT)
```

Replication argument: portfolio A = long call + cash K exp(-rT); portfolio B = long put + one share. At T, if S_T > K: A = (S_T - K) + K = S_T; B = 0 + S_T. If S_T <= K: A = 0 + K = K; B = (K - S_T) + S_T = K. Equal payoffs in every state, so equal prices today (no-arbitrage). Parity holds model-free, so a pricer that violates it has a bug, not a modelling issue. With dividends, replace S_0 with S_0 minus the present value of dividends; American options satisfy inequalities only.

### 3.5 Black-Scholes: model, derivation sketch, formula

**Assumptions (the model's, not the market's):**

1. The stock follows geometric Brownian motion: `dS = mu S dt + sigma S dW`, constant sigma and mu.
2. Continuous trading, no transaction costs, no bid/ask spread, unlimited shorting and borrowing at one constant risk-free rate r.
3. No dividends (extensions exist), European exercise, no arbitrage.

**Derivation sketch (delta hedging).** Let V(S, t) be the option value. Ito's lemma gives
`dV = (V_t + mu S V_S + 0.5 sigma^2 S^2 V_SS) dt + sigma S V_S dW`. Form the portfolio long one option, short `V_S` shares. The `dW` term cancels, so the portfolio is instantaneously riskless and must earn r:

```
V_t + 0.5 sigma^2 S^2 V_SS + r S V_S - r V = 0
```

mu has disappeared: the price does not depend on the stock's expected return, only on volatility. With terminal condition `V(S,T) = max(S-K,0)` the solution is

```
C = S N(d1) - K exp(-rT) N(d2)
P = K exp(-rT) N(-d2) - S N(-d1)
d1 = [ln(S/K) + (r + sigma^2/2) T] / (sigma sqrt(T))
d2 = d1 - sigma sqrt(T)
```

where N is the standard normal CDF. Equivalent view: `V_0 = exp(-rT) E_Q[payoff]` where under the risk-neutral measure Q the drift of S is r. That view is what justifies Monte Carlo: simulate `S_T = S_0 exp((r - sigma^2/2) T + sigma sqrt(T) Z)` and average discounted payoffs. (The -sigma^2/2 is the Ito correction; omitting it is a classic bug that biases the price by an amount you can compute.)

This is a sketch. A rigorous derivation (Girsanov, martingale pricing, self-financing strategies) is in Shreve or Hull (References).

**Limits of the model (what to say in a design review):**

- **Volatility is not constant.** Implied vol varies with strike and maturity (smile/skew); practitioners quote prices as implied vols. Check this on data you are licensed to use; do not assert a shape from memory.
- **Returns are not lognormal**: fat tails and jumps; BS understates far-out-of-the-money risk relative to fat tails.
- **Hedging is discrete and costly**, so the "riskless" portfolio is not riskless. Rates and dividends are not constant; American exercise has no closed form for puts. **Alternatives**: local volatility, Heston, jump-diffusion, binomial trees.

Use BS for a quick benchmark price/Greek of European vanilla options and as the implied-vol quoting convention; avoid it as a risk-model truth for exotic or tail-sensitive products.

### 3.6 Greeks

Sensitivities of price V:

| Greek | Definition | Meaning |
|---|---|---|
| delta | dV/dS | Shares needed to hedge |
| gamma | d2V/dS2 | How fast delta changes |
| vega | dV/dsigma | Price change per 1.00 (100 vol points) change in sigma; many desks quote per 1 vol point = vega/100 |
| theta | dV/dt (calendar time) | Value decay as time passes; here defined as -dV/dT |
| rho | dV/dr | Sensitivity to the rate |

Closed forms with `phi` the standard normal pdf:

```
call delta = N(d1)        put delta = N(d1) - 1
gamma = phi(d1) / (S sigma sqrt(T))                 (same for call and put)
vega  = S phi(d1) sqrt(T)                           (same for call and put)
call theta = -S phi(d1) sigma / (2 sqrt(T)) - r K exp(-rT) N(d2)
put  theta = -S phi(d1) sigma / (2 sqrt(T)) + r K exp(-rT) N(-d2)
call rho = K T exp(-rT) N(d2)      put rho = -K T exp(-rT) N(-d2)
```

**Finite differences.** Central difference `(f(x+h) - f(x-h)) / (2h)` has truncation error O(h^2); the second difference `(f(x+h) - 2 f(x) + f(x-h)) / h^2` is used for gamma. Round-off grows as h shrinks (a difference of nearly equal floats, divided by h or h^2), so there is a sweet spot; find it by experiment (section 6). Bumping is how you get Greeks when no closed form exists.

### 3.7 Value at Risk and Expected Shortfall

Define **loss** `L = -P&L`. For confidence alpha (say 0.99) over a stated horizon:

- `VaR_alpha` = the alpha-quantile of L: the loss exceeded with probability 1 - alpha.
- `ES_alpha` = `E[L | L >= VaR_alpha]`: average loss in the worst (1 - alpha) tail.

Three estimators:

1. **Historical**: sort observed P&L; with n observations let `k = ceil((1-alpha) n)`; VaR = k-th worst loss, ES = mean of the k worst losses. Assumes the past sample represents the future; sparse in the tail (n = 1000, alpha = 99% gives k = 10 points; see the float-noise trap in section 4).
2. **Parametric (normal)**: P&L ~ N(mu, sigma^2). `VaR = -mu + sigma z_alpha`, `ES = -mu + sigma phi(z_alpha)/(1-alpha)`. For mu=0, sigma=1: VaR99 = 2.3263, ES99 = 2.6652; VaR97.5 = 1.9600, ES97.5 = 2.3378 (computed). Underestimates tail risk when real tails are fatter than normal.
3. **Monte Carlo**: simulate risk-factor scenarios, revalue, apply estimator 1 to the simulated P&L.

VaR fails in specific ways: it ignores losses beyond the threshold; it is not subadditive in general (ES is); it depends heavily on window and sample size. ES is harder to backtest. The Basel market-risk framework (FRTB) moved the regulatory measure to ES at 97.5% (checked: Basel Framework MAR33.3, "a bank must use a 97.5th percentile, one-tailed confidence level"; bis.org/basel_framework).

## 4. Worked example

We build `quantlib/bs.py` incrementally. Full source and the complete test file are in the solutions file (so you can attempt first); here is the reasoning for each step.

### Step 1: validated input type

`Option` is a frozen dataclass `(spot, strike, rate, vol, t, kind)` whose `__post_init__` raises `ValueError` unless `kind in ("call","put")` and spot, strike, vol, t are > 0. Why: `vol = 0` or `t = 0` divides by zero in d1; their limit (intrinsic value) is a separate, deliberate code path, so reject and make the caller decide. Frozen: bump-and-reprice uses `dataclasses.replace`, never mutation, so a reprice cannot corrupt the base case. Full code: solutions file.

### Step 2: closed form

```python
import math
from statistics import NormalDist
_N = NormalDist()

def bs_price(o: Option) -> float:
    sq = o.vol * math.sqrt(o.t)
    d1 = (math.log(o.spot / o.strike) + (o.rate + 0.5 * o.vol**2) * o.t) / sq
    d2 = d1 - sq
    disc = math.exp(-o.rate * o.t)
    if o.kind == "call":
        return o.spot * _N.cdf(d1) - o.strike * disc * _N.cdf(d2)
    return o.strike * disc * _N.cdf(-d2) - o.spot * _N.cdf(-d1)
```

`statistics.NormalDist` (Python 3.8+) provides `cdf`, `pdf`, `inv_cdf` with no dependency. For S=100, K=100, r=5%, sigma=20%, T=1 the code returns call = 10.450584, put = 5.573526.

### Step 3: verify by an independent method, not by the same formula

Testing `bs_price` against `bs_price` proves nothing. Independent check: integrate `exp(-rT) max(S_T - K, 0)` against the lognormal density by trapezoid rule on 200,000 points over z in [-8, 8]. Result: 10.4505836 (agrees with 10.4505836 to 7+ decimals). That integral uses no N(d1) at all, so a typo in d1/d2 would show up. Also check parity: call - put = 4.877058 and S - K exp(-rT) = 4.877058.

Limit check needing no outside source: with r = 0 and S = K, `C = S (2 N(sigma sqrt(T)/2) - 1)`; for sigma = 20%, T = 1 this is 7.965567 (computed), and the implementation agrees.

### Step 4: Monte Carlo with an error bar

```python
import random
def mc_price(o: Option, n_paths: int, seed: int) -> tuple[float, float]:
    rng = random.Random(seed)                # own generator: no global state
    drift = (o.rate - 0.5 * o.vol**2) * o.t
    diff = o.vol * math.sqrt(o.t)
    disc = math.exp(-o.rate * o.t)
    sign = 1.0 if o.kind == "call" else -1.0
    vals = []
    for _ in range(n_paths // 2):
        z = rng.gauss(0.0, 1.0)
        pair = 0.0
        for zz in (z, -z):                   # antithetic pair
            st = o.spot * math.exp(drift + diff * zz)
            pair += max(sign * (st - o.strike), 0.0)
        vals.append(disc * pair / 2.0)
    m = sum(vals) / len(vals)
    var = sum((v - m) ** 2 for v in vals) / (len(vals) - 1)
    return m, math.sqrt(var / len(vals))
```

Design choices: (a) a private `random.Random(seed)` makes runs reproducible and independent of other code. (b) Antithetic variates: pairing Z and -Z lowers variance for monotone payoffs; the standard error is computed over the **pair averages**, which are independent, not over the 2n correlated payoffs (computing it over all payoffs would be wrong). (c) It returns the standard error alongside the estimate: a Monte Carlo number without one is not a result.

Results for the same option (seed 42, running the code):

| n_paths | estimate | std error | (estimate - exact) / SE |
|---|---|---|---|
| 1,000 | 10.3806 | 0.3328 | 0.21 (error = -0.07) |
| 10,000 | 10.4600 | 0.1045 | 0.09 |
| 100,000 | 10.4645 | 0.0329 | 0.42 |
| 1,000,000 | 10.4602 | 0.0104 | 0.93 |

Exact value 10.4506. Note what the table says: at 1,000,000 paths the estimate is 0.0096 above the exact price, which is 0.93 SE: consistent with noise, and an estimate of 10.46 against a spreadsheet's 10.45 is not evidence of a bug. The standard error shrinks by about sqrt(10) per 10x paths (0.3328, 0.1045, 0.0329, 0.0104). Paths needed to halve the error: 4x.

### Step 5: Greeks by central differences, validated

Bump spot by `h = 1e-4 S` (relative), vol by 1e-4, time by 1e-5, rate by 1e-5; gamma uses the second-difference formula. For the call: analytic delta 0.63683065, finite-difference 0.63683064; analytic gamma 0.018762017, finite-difference 0.018762017; vega 37.524035 vs 37.524034; theta -6.4140275 vs -6.4140275; rho 53.232482 vs 53.232482. ### Step 6: risk analyzer

```python
import math
def historical_var_es(pnl: list[float], alpha: float = 0.99) -> tuple[float, float]:
    if not pnl: raise ValueError("empty pnl")
    if not 0 < alpha < 1: raise ValueError("alpha in (0,1)")
    losses = sorted((-x for x in pnl), reverse=True)
    k = max(1, math.ceil((1 - alpha) * len(losses) - 1e-9))   # see float-noise note below
    tail = losses[:k]
    return tail[-1], sum(tail) / k
```

Hand-verifiable test: P&L `[-5,-3,-1,0,1,2,2,3,4,6]`, alpha = 0.8: k = ceil(0.2 * 10) = 2, worst two losses are 5 and 3, VaR = 3, ES = 4. Code agrees. Convergence check on 100,000 synthetic N(0,1) draws (seed 7): historical VaR99 = 2.3311 (parametric 2.3263), ES99 = 2.6512 (2.6652). With only 1,000 further draws: VaR99 = 2.305, ES99 = 2.706. The tail estimate from 1,000 points rests on 10 observations.

**Naive vs improved.** Naive: `pnl.sort(); var = pnl[int(0.01 * n)]` mutates the caller's list, mixes signs, and for small n or float roundoff in `(1 - alpha) * n` lands on an off-by-one index. Improved: no mutation, loss sign convention stated, k computed with `ceil`, ES provided, empty and bad-alpha input rejected. **Float-noise trap, found while writing this lesson.** My first version used `math.ceil((1 - alpha) * n)`. Running it: `(1 - 0.99) * 1000` evaluates to `10.000000000000009`, so `ceil` gives 11, not 10; the 99% tail silently held 11 observations. Same for alpha = 0.95, n = 20 (-> 2) and alpha = 0.7, n = 10 (-> 4). The reference code subtracts 1e-9 before `ceil`, with a regression test pinning k = 10 for n = 1000. A cleaner design takes the tail size as an integer count or alpha in basis points.

**Tests.** Known values to 6 decimals; parity across strikes; bounds; the r=0 closed form; invalid input; monotonicity in vol; MC within 4 SE and bit-identical per seed; SE ratio about 2 when n quadruples; FD vs analytic Greeks; call-put delta difference; risk hand example; ES >= VaR; parametric known values; historical-to-parametric convergence. The reference suite (17 tests for this lesson) passes.

## 5. Production perspective

**Correctness.** Pin each implementation to two independent references; keep "golden" values with provenance and tolerance. Parity, bounds, symmetry and limit cases are property tests that survive refactoring.

**Numerics.** For extreme moneyness or tiny `vol*sqrt(T)`, `N(d1)` saturates and `S N(d1) - K disc N(d2)` subtracts nearly equal terms; a deep OTM price can come out as a tiny negative number. Clamp only after understanding why, and test it (6.2).

**Units and conventions are the real bugs.** Per-day vs per-year vol; vega per 1.00 vs per vol point; theta per year vs per day; continuous vs simple rates; day counts; VaR sign. Put units in names (`vol_annual`) and docstrings.

**Performance and reproducibility.** The pure-Python loop is for correctness; production vectorises or uses C++ (5.x), partitions RNG streams per thread deterministically, and logs inputs + code version + seed for every reported number. Measure before optimising.

**Senior habits.** State tolerances before running tests; derive a limit case by hand; report Monte Carlo with error bars; treat a vendor mismatch as a convention question (dividends? day count? rate type?) before a bug; write the model's assumptions next to the result.

| Mistake | Symptom | Diagnosis |
|---|---|---|
| Omitting `-sigma^2/2` in MC drift | MC biased, bias does not shrink with n | Compare to closed form at n = 10^6; bias >> SE |
| n instead of n-1 in sample std | Vol off by `sqrt((n-1)/n)` | Test with n = 2 by hand |
| SE over individual antithetic payoffs | SE wrong | Compare SE with spread of estimates over 40 reseeds |
| Tiny finite-difference bump | Noisy or zero gamma | Sweep h (section 6) |
| Testing the formula with itself | Tests pass, price wrong | Add independent integral or parity |

### Reveal (read after predicting)

Running the sweep on the ATM call (exact gamma 0.018762017345846895):

| h (dollars) | FD gamma |
|---|---|
| 0.1 | 0.018761994381 |
| 0.01 | 0.018762017078 |
| 1e-4 | 0.018761880938 |
| 1e-6 | 0.028421709431 |
| 1e-8 | 0.0 |

Diagnosis:

- Prices are about 10.45; a double near 10 has resolution about 1.8e-15. At h = 1e-8 the second difference `V(S+h) - 2V(S) + V(S-h)` should be `gamma * h^2 = 1.9e-18`, far below that resolution (the prices differ by about delta * h = 6e-9, but the linear parts cancel), so the numerator is lost in rounding and here comes out exactly 0 (one ulp would instead give garbage of order 10 after dividing by h^2 = 1e-16). At h = 1e-6 the numerator is about 1.9e-14, only about 10 ulps, hence the 51% error.
- At the other end truncation error grows like h^2: h = 0.1 has error about 2.3e-8 (relative 1.2e-6); the best of the sweep is h = 0.01 with error about 2.7e-10.
- "Bigger is safer" is wrong: truncation error grows like h^2, and near expiry or a kink the curvature changes quickly so a large h smears it. The right h depends on the function, its scale and the derivative order.

**Systematic procedure** for any finite-difference Greek: (1) validate on a case with a known answer; (2) sweep h over several decades and look for the V shape on log-log axes; (3) choose h near the bottom, scaled to the variable, and document it; (4) for noisy Monte Carlo prices, reuse the same seed (common random numbers) for the up and down bumps or sampling noise dominates.

## 11. Mastery gate

Pass = 80/100 and no critical failure. Critical failures: (1) tests that compare the implementation to itself with no independent oracle; (2) MC price without SE or not deterministic per seed; (3) parity untested or violated; (4) VaR/ES without a sign convention, or ES < VaR; (5) any claim that the model "predicts" or "is accurate" for real markets; (6) any quoted number not obtained by running code.

Evidence: repository with pasted passing test output, sweep table, NOTES, and a 10-minute Mode A oral defense (derive parity on paper, explain `-sigma^2/2`, explain why 1,000-sample 99% VaR is fragile).

If failed: oracles -> compute the ATM call three ways (formula, trapezoid, MC over 20 reseeds) and write a one-page tolerance comparison. Risk -> compute 99% historical VaR/ES on 40 synthetic N(0,1) samples of size 250 (seeds recorded) and explain the spread. FD -> reproduce the h-sweep for vega and theta.
