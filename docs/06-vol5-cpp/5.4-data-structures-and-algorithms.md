## 1. Engineering problem

A risk service keeps 2 million open positions keyed by instrument id. Each tick finds, updates, and occasionally removes one. One teammate stores them in a `std::list` "because insertion is O(1)" and searches linearly; another uses `std::map` "because it is sorted" though nobody iterates in order; a third wrote a hash table whose delete marks slots empty, and after a week of churn lookups for absent keys hang. The first is slow for a reason Big-O predicts, the second for reasons it does not (pointer chasing, allocation), the third is wrong because an **invariant** was never written down.

Container bugs live in states your three examples never reach: full table, one element, duplicate keys, empty input, overflow in `(lo+hi)/2`. The skill: state the invariant, derive the code from it, test edges against a trusted oracle, and measure before believing any complexity claim.

## 3. First-principles explanation

### 3.1 Big-O and its limits

`f(n) = O(g(n))` means there are constants `c, n0` with `f(n) <= c*g(n)` for all `n >= n0`. It describes growth shape, hiding `c` and ignoring small `n`.

- Two O(n) algorithms can differ many times in wall time (array scan vs linked-list traversal; lesson 5.6 explains why).
- O(n) can beat O(log n) for small n.
- It names a cost model. "O(1) insert" in a list counts pointer writes, not the allocation (`operator new` may lock, touch cold memory, call the OS).
- Worst, average and amortized are different claims. Hash lookup is O(1) *expected* under a hashing assumption and O(n) worst case; attacker-chosen keys can aim at the worst case.

Use Big-O to **eliminate** candidates (O(n^2) on 10^6 items). Use measurement to **choose** among the rest.

### 3.2 Amortized analysis

Doubling array, inserting `n` elements. Growth copies happen at sizes 1, 2, 4, ..., so total copies are below 2n; with n writes the total is below 3n, so the average cost per push is at most 3 = O(1) amortized. The push at a growth point is O(n) and allocates, which amortization does not hide from a deadline. Standard facts: `push_back` must be amortized constant; the growth factor is implementation-defined (observed by printing `capacity()` after 100 pushes: libstdc++ 14 and libc++ 18 both give 1, 2, 4, ..., 128; MSVC is commonly reported as 1.5x; print it for yours). `reserve(n)` removes intermediate reallocations.

### 3.3 Invariants: the working method

An invariant is a property true at defined points (loop entry, between public operations). For each structure: (1) write it, (2) show it holds initially, (3) show each operation preserves it, (4) show invariant plus termination implies the postcondition. Tests then target step 3's weak spots.

### 3.4 Structures

| Structure | Invariant (informal) | Operations | Standard counterpart |
|---|---|---|---|
| Dynamic array | `size <= capacity`; `[0,size)` alive, rest raw | index O(1), push amortized O(1), middle insert O(n) | `std::vector` |
| Singly linked list | chain from head ends in `nullptr`, no cycle | push/pop front O(1), search O(n) | `std::forward_list` (rarely right) |
| Stack, queue | LIFO, FIFO | O(1) ends | `std::stack`, `std::queue` (over `deque` by default); ring buffer when capacity is bounded |
| Hash, chaining | key is in bucket `hash(k) mod B` | expected O(1) | `std::unordered_map` (node-based in practice; the interface's reference stability and bucket API effectively require it - implementation detail otherwise) |
| Hash, open addressing | each key reachable from its home slot with no `Empty` between; an `Empty` always exists | expected O(1) at load <= 0.75 | none in C++20; `std::flat_map` (C++23) is a sorted-vector map, a different design |
| Binary heap | parent never "less" than child; complete tree in an array | top O(1), push/pop O(log n), build O(n) | `std::priority_queue`, `make_heap/push_heap/pop_heap` |
| BST | left < node < right | O(height); height n when unbalanced | `std::map/set` (red-black tree in common implementations; the standard requires O(log n), not a tree type) |
| Graph (adjacency list) | `g[u]` lists all edges out of `u` | BFS/DFS O(V+E); Dijkstra O((V+E) log V) | none |

**Open addressing vs chaining.** Chaining: simple deletion, stable references, tolerates load > 1; costs an allocation and a pointer hop per element. Open addressing: one array, fewer cache misses, no per-element allocation; but deletion needs *tombstones* (writing `Empty` breaks the probe paths through that slot), speed collapses near full, and rehash invalidates references.

**Balanced trees.** A BST fed sorted input degrades into a list. Red-black, AVL and B-trees keep O(log n) with rotations/splits that preserve in-order sequence. You use `std::map`; you must be able to explain why rotation preserves order.

**Graphs.** BFS (queue): fewest edges. DFS (stack): reachability, topological order, cycles. Dijkstra (priority queue): shortest paths for **non-negative** weights; invariant: a vertex popped with its smallest tentative distance is final. A negative edge breaks exactly that argument (use Bellman-Ford).

**Recursion vs iteration.** C++ does not guarantee tail-call elimination; recursion depth is stack memory. Unbalanced trees, long lists destroyed by recursive destructors, and DFS on hostile input overflow the stack (in practice a crash; the language gives no guarantee). Use an explicit stack when depth is not bounded by something like `log n`.

**Paradigms.** *Greedy*: correct only with an exchange argument (interval scheduling by earliest end: yes; arbitrary-coin change: no). *Divide and conquer*: cost from the recurrence (merge sort `T(n) = 2T(n/2) + O(n)` gives `O(n log n)`). *Dynamic programming*: define state, recurrence, base cases, evaluation order, then shrink memory (edit distance needs two rows).

**Sorting.** Comparison sorts need `Omega(n log n)` comparisons worst case. `std::sort` is unstable with O(n log n) worst-case comparisons since C++11 (implementations use introsort-style hybrids); `std::stable_sort` is stable and may allocate. Merge sort: stable, O(n) space. Heap sort: in place, unstable, cache-unfriendly. The comparator must be a **strict weak ordering**; `<=` is undefined behaviour (section 7, question 10).

**When appropriate in real systems.** Write your own only for an interface the standard lacks (intrusive, fixed capacity, lock-free), a *measured* bottleneck, or a platform without the library. Otherwise standard containers are better tested than anything you write this week. This lesson's value is that you can read, review and choose among containers.

### 4.1 `Vec<T>`: growth with the strong guarantee

Design choices: raw storage via `std::allocator<T>`, element lifetime managed with `construct_at`/`destroy`. The *new* element is built in the *new* buffer **before** old elements are relocated, so `v.push_back(v[0])` still reads a live source. Relocation uses `std::move_if_noexcept`: a throwing move constructor makes it copy, so rollback is possible. The copy constructor delegates to the default one so the destructor runs if copying throws midway.

```cpp
// file: vec.hpp  (C++20)
#pragma once
#include <cstddef>
#include <memory>
#include <utility>

template <class T>
class Vec {
    T* data_ = nullptr;
    std::size_t size_ = 0, cap_ = 0;
    // Invariant: [data_, data_+size_) alive, [data_+size_, data_+cap_) raw, size_ <= cap_,
    //            data_ == nullptr iff cap_ == 0.

    static T* allocate(std::size_t n) { return std::allocator<T>{}.allocate(n); }
    static void deallocate(T* p, std::size_t n) { std::allocator<T>{}.deallocate(p, n); }

    void move_into(T* nb) {  // on throw: nb[0..i) destroyed, *this untouched
        std::size_t i = 0;
        try {
            for (; i < size_; ++i) std::construct_at(nb + i, std::move_if_noexcept(data_[i]));
        } catch (...) {
            std::destroy(nb, nb + i);
            throw;
        }
    }
    void adopt(T* nb, std::size_t ncap) noexcept {
        std::destroy(data_, data_ + size_);
        if (data_) deallocate(data_, cap_);
        data_ = nb;
        cap_ = ncap;
    }

public:
    Vec() noexcept = default;
    Vec(const Vec& o) : Vec() {
        reserve(o.size_);
        for (const T& x : o) emplace_back(x);
    }
    Vec(Vec&& o) noexcept
        : data_(std::exchange(o.data_, nullptr)),
          size_(std::exchange(o.size_, 0)),
          cap_(std::exchange(o.cap_, 0)) {}
    Vec& operator=(Vec o) noexcept { swap(o); return *this; }  // copy-and-swap
    ~Vec() {
        clear();
        if (data_) deallocate(data_, cap_);
    }

    void swap(Vec& o) noexcept {
        std::swap(data_, o.data_);
        std::swap(size_, o.size_);
        std::swap(cap_, o.cap_);
    }
    std::size_t size() const noexcept { return size_; }
    std::size_t capacity() const noexcept { return cap_; }
    bool empty() const noexcept { return size_ == 0; }
    T& operator[](std::size_t i) noexcept { return data_[i]; }
    const T& operator[](std::size_t i) const noexcept { return data_[i]; }
    T* begin() noexcept { return data_; }
    T* end() noexcept { return data_ + size_; }
    const T* begin() const noexcept { return data_; }
    const T* end() const noexcept { return data_ + size_; }

    void clear() noexcept { std::destroy(data_, data_ + size_); size_ = 0; }
    void pop_back() noexcept { std::destroy_at(data_ + --size_); }  // precondition: !empty()
    void push_back(const T& x) { emplace_back(x); }
    void push_back(T&& x) { emplace_back(std::move(x)); }

    void reserve(std::size_t n) {
        if (n <= cap_) return;
        T* nb = allocate(n);
        try { move_into(nb); } catch (...) { deallocate(nb, n); throw; }
        adopt(nb, n);
    }

    template <class... A>
    T& emplace_back(A&&... a) {
        if (size_ == cap_) {
            const std::size_t ncap = cap_ ? cap_ * 2 : 1;
            T* nb = allocate(ncap);
            try {
                std::construct_at(nb + size_, std::forward<A>(a)...);  // before touching old data
                try { move_into(nb); } catch (...) { std::destroy_at(nb + size_); throw; }
            } catch (...) {
                deallocate(nb, ncap);
                throw;
            }
            adopt(nb, ncap);
        } else {
            std::construct_at(data_ + size_, std::forward<A>(a)...);
        }
        return data_[size_++];
    }
};
```

Naive version: allocate `2*cap`, move old elements, *then* construct the new element from `x`, which dangles if `x` pointed into the old buffer, with no rollback. What changed: construction order, `move_if_noexcept`, try/catch rollback (about ten lines). Limits: no middle insert/erase, no allocator support, no overflow check on `cap_ * 2`.

### 4.2 Open-addressing hash table (linear probing, tombstones)

Invariants: **I1** capacity is a power of two. **I2** `used_*4 <= capacity*3` after every insert (`used_` = Full + Deleted), so at least one `Empty` slot always exists and every probe loop terminates. **I3** every `Full` key is reachable from its home slot by stepping +1 without crossing an `Empty` slot. Erase writes `Deleted`, not `Empty`, to preserve I3. `std::hash<int>` is the identity in libstdc++ (implementation detail; observed in libstdc++ 14 and libc++ 18), which clusters under linear probing and a power-of-two mask, so we mix bits (splitmix64 finalizer).

```cpp
// file: flatmap.hpp  (C++20)
#pragma once
#include <concepts>
#include <cstddef>
#include <cstdint>
#include <functional>
#include <utility>
#include <vector>

template <class K, class V, class Hash = std::hash<K>>
    requires std::default_initializable<K> && std::default_initializable<V> &&
             std::equality_comparable<K>
class FlatMap {
    enum class St : std::uint8_t { Empty, Full, Deleted };
    struct Slot { St st = St::Empty; K key{}; V val{}; };

    std::vector<Slot> slots_ = std::vector<Slot>(8);
    std::size_t size_ = 0;  // Full slots
    std::size_t used_ = 0;  // Full + Deleted slots
    [[no_unique_address]] Hash hash_{};

    static std::size_t mix(std::uint64_t x) noexcept {
        x += 0x9e3779b97f4a7c15ull;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ull;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebull;
        return static_cast<std::size_t>(x ^ (x >> 31));
    }
    std::size_t home(const K& k) const noexcept {
        return mix(hash_(k)) & (slots_.size() - 1);
    }
    void rehash(std::size_t ncap) {  // simplification: assumes K, V moves do not throw
        std::vector<Slot> old = std::exchange(slots_, std::vector<Slot>(ncap));
        used_ = size_;
        for (Slot& s : old) {
            if (s.st != St::Full) continue;
            std::size_t i = home(s.key);
            while (slots_[i].st == St::Full) i = (i + 1) & (slots_.size() - 1);
            slots_[i] = Slot{St::Full, std::move(s.key), std::move(s.val)};
        }
    }

public:
    std::size_t size() const noexcept { return size_; }
    std::size_t slot_count() const noexcept { return slots_.size(); }

    bool insert_or_assign(K k, V v) {  // true if a new key was inserted
        if ((used_ + 1) * 4 > slots_.size() * 3)  // grow if live data is dense, else just purge tombstones
            rehash((size_ + 1) * 2 > slots_.size() ? slots_.size() * 2 : slots_.size());
        const std::size_t mask = slots_.size() - 1;
        Slot* tomb = nullptr;
        for (std::size_t i = home(k);; i = (i + 1) & mask) {
            Slot& s = slots_[i];
            if (s.st == St::Full) {
                if (s.key == k) { s.val = std::move(v); return false; }
            } else if (s.st == St::Deleted) {
                if (!tomb) tomb = &s;  // reuse the first tombstone, but keep probing for the key
            } else {  // Empty: key is absent
                Slot& t = tomb ? *tomb : s;
                if (!tomb) ++used_;
                t = Slot{St::Full, std::move(k), std::move(v)};
                ++size_;
                return true;
            }
        }
    }

    V* find(const K& k) noexcept {
        const std::size_t mask = slots_.size() - 1;
        for (std::size_t i = home(k);; i = (i + 1) & mask) {  // terminates: I2 guarantees an Empty slot
            Slot& s = slots_[i];
            if (s.st == St::Empty) return nullptr;
            if (s.st == St::Full && s.key == k) return &s.val;
        }
    }

    bool erase(const K& k) {
        const std::size_t mask = slots_.size() - 1;
        for (std::size_t i = home(k);; i = (i + 1) & mask) {
            Slot& s = slots_[i];
            if (s.st == St::Empty) return false;
            if (s.st == St::Full && s.key == k) {
                s = Slot{St::Deleted, K{}, V{}};
                --size_;  // used_ unchanged: the tombstone still occupies the probe path
                return true;
            }
        }
    }
};
```

Naive version: erase writes `Empty`, and `used_` ignores tombstones. Section 6 shows what breaks.

### 4.3 Binary search from a loop invariant

```cpp
// file: search.hpp  (C++20)
#pragma once
#include <concepts>
#include <cstddef>
#include <span>

// First index i with !(a[i] < x), or a.size(). Requires a sorted ascending.
template <std::totally_ordered T>
std::size_t lower_bound_idx(std::span<const T> a, const T& x) {
    std::size_t lo = 0, hi = a.size();
    // Invariant: every a[j], j < lo, satisfies a[j] < x; every a[j], j >= hi, satisfies !(a[j] < x).
    while (lo < hi) {
        const std::size_t mid = lo + (hi - lo) / 2;  // no overflow, unlike (lo + hi) / 2
        if (a[mid] < x) lo = mid + 1;                // a[0..mid] < x because sorted
        else hi = mid;                               // a[mid] >= x and so is everything right of it
    }
    return lo;  // lo == hi: both halves of the invariant meet at the answer
}
```

`lo + (hi - lo) / 2` avoids `lo + hi` overflow (signed overflow is UB; unsigned wraps). The invariant explains `hi = mid` rather than `mid - 1`: `a[mid]` is `>= x` and may be the answer.

### 4.4 Binary heap

```cpp
// file: heap.hpp  (C++20)
#pragma once
#include <cstddef>
#include <functional>
#include <utility>
#include <vector>

// Max-heap with respect to Less, same convention as std::priority_queue.
// Invariant: for every i > 0, !less(a[(i-1)/2], a[i])  (parent is never "less than" child).
template <class T, class Less = std::less<T>>
class BinaryHeap {
    std::vector<T> a_;
    [[no_unique_address]] Less less_{};

    void sift_up(std::size_t i) {
        T x = std::move(a_[i]);
        while (i > 0) {
            const std::size_t p = (i - 1) / 2;
            if (!less_(a_[p], x)) break;
            a_[i] = std::move(a_[p]);
            i = p;
        }
        a_[i] = std::move(x);
    }
    void sift_down(std::size_t i) {
        const std::size_t n = a_.size();
        T x = std::move(a_[i]);
        for (;;) {
            std::size_t c = 2 * i + 1;
            if (c >= n) break;
            if (c + 1 < n && less_(a_[c], a_[c + 1])) ++c;  // larger child
            if (!less_(x, a_[c])) break;
            a_[i] = std::move(a_[c]);
            i = c;
        }
        a_[i] = std::move(x);
    }

public:
    bool empty() const noexcept { return a_.empty(); }
    std::size_t size() const noexcept { return a_.size(); }
    const T& top() const { return a_.front(); }  // precondition: !empty()
    void push(T x) { a_.push_back(std::move(x)); sift_up(a_.size() - 1); }
    void pop() {  // precondition: !empty()
        if (a_.size() > 1) a_.front() = std::move(a_.back());  // avoid self-move when size is 1
        a_.pop_back();
        if (!a_.empty()) sift_down(0);
    }
};
```

### 4.5 Tests: oracle, seeded randomness, small key space

`CHECK` replaces `assert`, which vanishes under `-DNDEBUG`. Each test targets a weak spot: aliasing and throwing copy (growth), a 300-key space (collision chains and tombstone reuse), absent-key lookup after mass erase (the hang), empty/below/above-range inputs (binary search), duplicates in the heap.

```cpp
// file: ds_test.cpp  (C++20)
#include <algorithm>
#include <cstdio>
#include <cstdlib>
#include <queue>
#include <random>
#include <stdexcept>
#include <string>
#include <unordered_map>

#include "flatmap.hpp"
#include "heap.hpp"
#include "search.hpp"
#include "vec.hpp"

#define CHECK(c) do { if (!(c)) { std::fprintf(stderr, "%s:%d CHECK failed: %s\n", __FILE__, __LINE__, #c); std::abort(); } } while (0)

struct Tracked {  // counts live objects; copying can be made to throw
    static inline int live = 0, budget = -1;  // budget: copies allowed before one throws (-1 = unlimited)
    int v;
    explicit Tracked(int x = 0) : v(x) { ++live; }
    Tracked(const Tracked& o) : v(o.v) {
        if (budget == 0) throw std::runtime_error("copy");
        if (budget > 0) --budget;
        ++live;
    }
    Tracked& operator=(const Tracked&) = default;
    ~Tracked() { --live; }
};

static void test_vec() {
    Vec<std::string> s;
    s.push_back(std::string(40, 'x'));                 // long string: heap-allocated
    for (int i = 0; i < 100; ++i) s.push_back(s[0]);   // aliasing across reallocation
    CHECK(s.size() == 101);
    for (const auto& e : s) CHECK(e == std::string(40, 'x'));

    {
        Vec<Tracked> v;
        for (int i = 0; i < 4; ++i) v.emplace_back(i);
        CHECK(v.capacity() == 4);
        Tracked::budget = 2;  // third copy during relocation throws
        bool threw = false;
        try { v.emplace_back(99); } catch (const std::runtime_error&) { threw = true; }
        Tracked::budget = -1;
        CHECK(threw && v.size() == 4 && v.capacity() == 4);
        for (int i = 0; i < 4; ++i) CHECK(v[static_cast<std::size_t>(i)].v == i);
        CHECK(Tracked::live == 4);  // no leaked or duplicated objects
    }
    CHECK(Tracked::live == 0);

    Vec<int> a;
    a.reserve(10);
    for (int i = 0; i < 5; ++i) a.push_back(i);
    Vec<int> b = a, c;
    c = a;
    a.clear();
    CHECK(b.size() == 5 && c.size() == 5 && a.empty());
}

static void test_flatmap() {
    FlatMap<int, int> m;
    std::unordered_map<int, int> ref;
    std::mt19937 rng(12345);
    for (int i = 0; i < 300000; ++i) {
        const int k = static_cast<int>(rng() % 300);  // tiny key space: constant collisions and churn
        switch (rng() % 3) {
            case 0: {
                const int v = static_cast<int>(rng());
                CHECK(m.insert_or_assign(k, v) == (ref.find(k) == ref.end()));
                ref[k] = v;
                break;
            }
            case 1: CHECK(m.erase(k) == (ref.erase(k) == 1)); break;
            default: {
                int* p = m.find(k);
                auto it = ref.find(k);
                CHECK((p != nullptr) == (it != ref.end()));
                if (p) CHECK(*p == it->second);
            }
        }
        CHECK(m.size() == ref.size());
    }
    FlatMap<std::string, int> sm;  // absent-key lookup on a table full of tombstones must terminate
    for (int i = 0; i < 1000; ++i) sm.insert_or_assign(std::to_string(i), i);
    for (int i = 0; i < 1000; ++i) CHECK(sm.erase(std::to_string(i)));
    CHECK(sm.size() == 0 && sm.find("nope") == nullptr);
}

static void test_search_heap() {
    std::mt19937 rng(7);
    CHECK(lower_bound_idx<int>(std::span<const int>{}, 5) == 0);  // empty input
    for (int t = 0; t < 2000; ++t) {
        std::vector<int> v(rng() % 20);
        for (int& x : v) x = static_cast<int>(rng() % 10);
        std::sort(v.begin(), v.end());
        const int x = static_cast<int>(rng() % 12) - 1;  // below, inside and above the range
        const auto want = static_cast<std::size_t>(std::lower_bound(v.begin(), v.end(), x) - v.begin());
        CHECK(lower_bound_idx<int>(std::span<const int>(v), x) == want);
    }
    BinaryHeap<int> h;
    std::priority_queue<int> ref;
    for (int i = 0; i < 100000; ++i) {
        if (ref.empty() || rng() % 3 != 0) { const int x = static_cast<int>(rng() % 50); h.push(x); ref.push(x); }
        else { CHECK(h.top() == ref.top()); h.pop(); ref.pop(); }
        CHECK(h.size() == ref.size());
    }
    BinaryHeap<int, std::greater<int>> minh;
    for (int x : {5, 1, 4, 1, 3}) minh.push(x);
    CHECK(minh.top() == 1);
}

int main() {
    test_vec();
```

## 5. Production perspective

**Correctness.** Frequent real bugs: iterator/reference invalidation (storing `&v[0]` across `push_back`, or the `V*` from `FlatMap::find` across any insert), off-by-one on half-open ranges, `size() - 1` on an empty container wrapping to a huge value, a comparator that is not a strict weak ordering, `operator[]` on a map inserting by accident, overflow in distance sums.

**Performance.** Every row is a hypothesis to measure, not a result.

| Workload | Default | Why | Experiment |
|---|---|---|---|
| Append, iterate, random access | `vector` + `reserve` | contiguous | iteration and push vs `deque` |
| Middle insert/erase, small to medium | try `vector` first | memmove vs one allocation per node | random-position insert, n = 10^2..10^6, vs `list` |
| Key lookup, no order | `unordered_map`; profile before considering a flat table (e.g. Abseil, `boost::unordered_flat_map`) | fewer cache misses | hit and miss lookups, small and large tables |
| Ordered iteration, ranges | `map`; sorted `vector` + `lower_bound` if built once | tree vs contiguous | build, lookup, iterate |
| Top-K | `priority_queue`, `partial_sort`, `nth_element` | O(n log k) or O(n) | sweep n and k |
| Fixed FIFO between stages | ring buffer (your own is justified) | no allocation, bounded latency | tail latency, not mean |

`std::flat_map`/`std::flat_set` are C++23 (checked: `__cpp_lib_flat_map` undefined in libstdc++ 14.2 and libc++ 18).

**Failure handling.** A table that throws mid-rehash must not lose data, hence `noexcept` moves (ours simplifies this). Recursion on untrusted depth is a denial-of-service bug. Tables keyed by attacker-controlled strings need a seeded hash; the standard does not mandate one.

**Senior habits.** Read the call pattern first (operations, sizes, lifetimes), pick `vector` unless it contradicts, write the oracle test before the optimization, keep the old container behind the same interface until a benchmark justifies the swap, and check team standards before swapping containers in an existing codebase.

**Beginner mistakes.** (1) "List insert is O(1), so faster": run the vector/list experiment. (2) `Empty` on erase: wrong answers after churn; a small-key-space differential test finds it. (3) `(lo+hi)/2`: fails only on huge arrays; found by reading. (4) Relying on `unordered_map` iteration order: unspecified.

## 6. Failure laboratory

Predict first, in writing.

**Flaw A.** Compile and run `bst_lab.cpp`. It inserts 1, 2, ..., 2000 into an unbalanced BST. (a) What does it print? (b) How many node visits for `contains(2000)`? (c) The tree is destroyed by the default recursive `unique_ptr` teardown: what happens for 2,000 keys; for 1,000,000?

```cpp
// file: bst_lab.cpp  (C++20)
#include <algorithm>
#include <cstddef>
#include <cstdio>
#include <memory>

struct Node { int key; std::unique_ptr<Node> l, r; explicit Node(int k) : key(k) {} };

void insert(std::unique_ptr<Node>& root, int k) {  // iterative unbalanced BST insert
    auto* p = &root;
    while (*p) p = k < (*p)->key ? &(*p)->l : &(*p)->r;
    *p = std::make_unique<Node>(k);
}
std::size_t height(const Node* n) { return n ? 1 + std::max(height(n->l.get()), height(n->r.get())) : 0; }

int main() {
    std::unique_ptr<Node> root;
    for (int i = 1; i <= 2000; ++i) insert(root, i);
    std::printf("height = %zu\n", height(root.get()));
}   // root destroyed here: recursion depth == height
```

**Flaw B.** Take `FlatMap::erase` and change `Deleted` to `Empty`. Find a key sequence where, after one erase, `find` misses a present key. Then: if `used_` ignores tombstones, which loop eventually fails to terminate, and under what churn?

### Reveal (read after predicting)

**A.** (a) `height = 2000`: every key goes right; the tree is a linked list. (b) 2000 visits: O(n). (c) Recursive destructor depth equals height. Observed while writing this lesson (g++ 14.2, `-O0`, `ulimit -s 8192`, a bare chain of `unique_ptr<Node>`): n = 2,000 destroyed fine; n = 100,000 and n = 1,000,000 exited with status 139 (SIGSEGV). The threshold depends on compiler, optimization and frame size; repeat it on your machine (lesson 5.5 shows backtraces). An iterative destructor fixes the crash, not the O(n) lookups; a balanced tree fixes both.

**B.** Keys A, B, C with the same home slot h land in h, h+1, h+2. Erasing B as `Empty` leaves a hole; `find(C)` stops at h+1 and returns `nullptr` though C is present: I3 violated. With `used_` ignoring tombstones, insert/erase churn of distinct keys turns `Empty` slots into `Deleted` without raising `used_`; eventually no `Empty` remains and `find` of an absent key loops forever (a hang, not a crash). Diagnosis procedure: (1) shrink the random sequence to the smallest failing one, (2) print slot states, (3) call a debug `check_invariants()` after every operation, (4) find the first operation after which an invariant fails.
