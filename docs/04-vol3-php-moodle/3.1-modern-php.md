## 1. Engineering problem

You join a team that maintains a Moodle plugin. A colleague's pull request adds a "bulk import grades" feature. It works in the demo. In production three things happen in one week:

1. A teacher imports a CSV where a student's id is the string `"0e12345"`; a comparison `if ($row['token'] == $stored)` treats two different tokens as equal because both look like numbers in scientific notation (`0 * 10^12345 = 0`). A student gets another student's grade page. This is the loose-comparison bug family, and it has caused real authentication bypasses in PHP software for years.
2. A function declared `function percent($score, $max)` receives `"85"` and `"0"` from a form and returns `INF`/throws `DivisionByZeroError`, depending on how it is called, because nothing pinned the types.
3. A search box echoes `$_GET['q']` into the page. Someone enters `<script>`. The page now runs attacker JavaScript in a teacher's session.

None of these is exotic. All three come from treating PHP as "Python with dollar signs". PHP has a different execution model (it dies after each request), a different history (loose types by default, strictness opt-in), a different ecosystem (Composer + PSR standards instead of pip + whatever), and a different default security posture (no automatic output escaping).

This lesson gives you the PHP you need to be safe and productive in a Moodle codebase: the request lifecycle, strict types, the comparison traps, the object model, namespaces/autoloading (which Moodle's `classes/` directory depends on), exceptions, input/output security, PDO, Composer, and PHPUnit basics. Moodle has its own wrappers for several of these (its `$DB` API replaces raw PDO; its `required_param()` replaces raw `$_GET`; its Mustache templates escape output). You learn the raw language first so that you know what the wrappers protect you from and when they do not.

By the end you can, without references:

## 3. First-principles explanation

### 3.1 Execution model: one request, one process state, then death

**What.** In the dominant deployment (nginx or Apache with PHP-FPM, or Apache `mod_php`), a PHP worker handles one HTTP request at a time. For each request the engine builds fresh global state, runs your script from the entry point to the end, sends the response, and discards the state. **[runtime]** This is called "shared-nothing" architecture: two requests do not share variables, objects, or open DB connections (unless you use persistent connections explicitly).

```
Browser                nginx            PHP-FPM worker                 Database
   | GET /grades.php?id=7  |                |                              |
   |---------------------->|--FastCGI------>| 1. request startup           |
   |                       |                | 2. OPcache: compiled bytecode|
   |                       |                |    for grades.php (cached    |
   |                       |                |    across requests)          |
   |                       |                | 3. execute: superglobals     |
   |                       |                |    $_GET/$_POST/$_SERVER set |
   |                       |                | 4. open DB connection ------>|
   |                       |                | 5. build output              |
   |<----------------------|<---response----| 6. request shutdown:         |
                                            |    free all variables,       |
                                            |    close connection          |
```

**What survives between requests:** compiled bytecode (OPcache, shared memory), files, the database, external caches (APCu, Redis, Memcached), the session store (files/DB/Redis), and anything in `static` class members only within one request. **What does not:** every variable, object, static property, `define()`d constant.

**Why this matters (consequences):**

- No memory leaks that outlive a request; crashing a request does not corrupt the next. This is why PHP is operationally forgiving.
- No in-process shared state: you cannot keep a "current user list" in a static array. In Moodle this is why `$USER`, `$COURSE`, `$PAGE`, `$DB` are rebuilt on every request in `config.php`/`lib/setup.php`, and why Moodle's caching API (MUC) stores data in external stores.
- Startup cost is paid each request: loading many files is expensive, which is why autoloading (load a class file only when first used) and OPcache matter.
- Long-running work does not belong in a web request (timeouts, `max_execution_time`). Moodle uses cron/adhoc tasks for this (lesson 3.5).

**Difference from Python (FastAPI).** A FastAPI process (uvicorn) is long-lived: imports happen once, module-level objects are shared by all requests, a global dict is shared state (and a race condition). PHP-FPM re-runs your script top-to-bottom each request. In Python you worry about shared mutable state between requests; in PHP you worry about the opposite: forgetting that nothing persists. (PHP can also run long-lived under Swoole/RoadRunner/FrankenPHP worker mode; Moodle does not.)

### 3.2 Types, `strict_types`, and coercion

PHP has scalar types `int`, `float`, `string`, `bool`, compound `array`, `object`, `callable`, `iterable`, `mixed`, nullable `?T`, unions `A|B`, intersections `A&B` (8.1), and return-only `void`, `never` (8.1), `static`. **[language]**

By default PHP runs in **coercive mode**: passing the string `"5"` to an `int` parameter is silently converted. With `declare(strict_types=1);` as the **first statement of a file** (before the namespace), calls *made from that file* to functions with scalar type declarations must pass exactly the declared type (one exception: `int` is accepted where `float` is declared) or a `TypeError` is thrown. **[language]** Important subtleties:

- `strict_types` is per file and applies to calls **made in** that file, and to return statements in that file. It does not make the *callee's* file strict for callers in other files. Built-in functions are covered too when you call them from a strict file.
- It does not affect comparisons, array keys, or string interpolation. It only governs scalar type declarations of function/method parameters, returns, and (since 7.4) typed properties.
- Moodle core files do **not** all use `declare(strict_types=1);`. Moodle's coding style page (moodledev.io) does not mandate it (checked: it mentions `strict_types` only in the definition of side effects), and in the 5.3 source about 1,700 PHP files under `public/` declare it (e.g. `public/mod/choice/classes/dates.php`). [opinion] In your own libraries, use it. In Moodle plugins, follow the surrounding code's convention and test the boundary where Moodle passes strings (e.g., ids from the database layer arrive as strings in many cases).

Typed properties (7.4) are initialized-or-uninitialized: reading an uninitialized typed property throws `Error`. **[language]**

```php
<?php
declare(strict_types=1);

function percent(int $score, int $max): float {
    return $score / $max * 100;
}

echo percent(85, 100), "\n";   // 85
try {
    echo percent("85", 100);   // strict mode: TypeError
} catch (TypeError $e) {
    echo "TypeError caught\n";
}
```

Python comparison: Python is strongly typed at runtime (`"5" + 5` raises) but ignores type hints. PHP's declarations are **enforced by the engine** at call time (for scalar/class types) but there is no static checker in the engine; use PHPStan/Psalm for that (ask which one the team uses).

### 3.3 Comparison: loose `==` vs strict `===`

`===` compares type and value. `==` converts operands first. PHP 8 changed string-to-number comparison: if the string is **numeric** (including leading/trailing whitespace allowed in 8.0+, and exponent forms like `1e3`), compare as numbers; otherwise convert the number to a string and compare strings. **[language]** I ran these on PHP 8.4.27:

| Expression | Result | Why |
|---|---|---|
| `0 == "a"` | `false` | PHP 8: "a" non-numeric, so `0` becomes `"0"`, compare strings. (PHP 7: `true`.) |
| `"1" == "01"` | `true` | both numeric strings, compared as numbers |
| `"10" == "1e1"` | `true` | both numeric: 10 == 10 |
| `100 == "1e2"` | `true` | numeric string in exponent form |
| `null == false` | `true` | both convert to bool false |
| `[] == false` | `true` | empty array is falsy |
| `"abc" == 0` | `false` | PHP 8 behavior (was `true` before 8.0) |
| `"0" == false` | `true` | `"0"` is falsy |
| `in_array("abc", [0])` | `false` | PHP 8; loose comparison |

Still dangerous in PHP 8: two **different** strings that both look numeric compare equal: `"0e123" == "0e456"` is `true`. Hash comparison with `==` (`md5($a) == md5($b)`) is the classic "magic hash" bypass. **Rules [opinion, but near-universal]:**

1. Use `===`/`!==` everywhere. Use `in_array($x, $list, true)` and `array_search(..., true)`.
2. Compare secrets (tokens, MACs, password hashes' verify results) with `hash_equals($known, $user)` (constant time; both args must be strings) or `password_verify()`.
3. `switch` uses loose comparison; `match` uses strict comparison (and throws `UnhandledMatchError` if no arm matches). Prefer `match`.
4. Beware truthiness: `if ($x)` is false for `0`, `"0"`, `""`, `[]`, `null`, `0.0`. `empty("0")` is `true`. Use `isset`, `=== null`, or `=== ''` deliberately.

### 3.4 Arrays: PHP's one collection type

A PHP `array` is an ordered hash map; lists, dicts, sets and stacks are all arrays. **[language]** Keys are `int` or `string` (`"5"` normalizes to int `5`). Arrays are **value types with copy-on-write**: `$b = $a; $b[] = 3;` leaves `$a` unchanged (verified: counts 2 and 3). Objects are handles: assigning copies the handle, like Python references. `array_filter` preserves keys (use `array_values` to reindex); `isset($a['k'])` is false for a null value, `array_key_exists` is not. `foreach ($a as &$v)` leaves `$v` a dangling reference to the last element: always `unset($v)` afterwards (Lab C).

### 3.5 Functions

Named arguments (8.0) `f(max: 100, score: 85)`; variadics `...$args`; arrow functions `fn($x) => $x * $k` capture the enclosing scope by value automatically, while `function () use ($k)` captures explicitly; first-class callable syntax `strlen(...)` (8.1); return type `never` for functions that always throw or exit. Avoid by-reference parameters in new code.

### 3.6 Classes, interfaces, traits, enums, readonly

```php
<?php
declare(strict_types=1);

interface Gradeable {
    public function score(): int;
}

enum Status: string {
    case Draft = 'draft';
    case Published = 'published';

    public function isVisible(): bool {
        return $this === self::Published;
    }
}

trait HasTimestamps {
    private ?int $createdAt = null;
    public function touch(int $now): void { $this->createdAt ??= $now; }
    public function createdAt(): ?int { return $this->createdAt; }
}

final class Submission implements Gradeable {
    use HasTimestamps;

    public function __construct(
        public readonly int $id,
        private int $score,
        public readonly Status $status = Status::Draft,
    ) {
        if ($score < 0) {
            throw new InvalidArgumentException('score must be >= 0');
        }
    }

    public function score(): int { return $this->score; }
}
```

Facts **[language]**:

- **Constructor promotion** (8.0) declares and assigns properties from constructor parameters.
- **`readonly` properties** (8.1) can be initialized once, from inside the class scope, and require a type; modifying afterwards throws `Error` ("Cannot modify readonly property ..."; I ran this). `readonly` classes arrived in 8.2 (`readonly class Money {}`). Readonly is shallow: an object held in a readonly property can still mutate internally. Since PHP 8.3 readonly properties can be reinitialized inside `__clone()`; from 8.4 taking a reference to one there is forbidden (checked on php.net, Properties page). Outside `__clone()` the `with`-er pattern `$c = clone $this; $c->a = 2;` still throws (I ran this on 8.4.27).
- **Enums** (8.1): pure (`enum A { case X; }`) or **backed** (`enum A: string`). Backed enums give `from()` (throws `ValueError` for an unknown value) and `tryFrom()` (returns `null`). Cases are singletons: compare with `===`. Enums can implement interfaces and have methods and constants but no properties and cannot be instantiated or extended.
- **Interfaces** declare contracts; a class can implement many. **Abstract classes** share state/implementation with single inheritance. **Traits** copy methods/properties into a class at compile time: horizontal reuse without inheritance. Trait conflicts require `insteadof`. [opinion] Prefer composition (inject a collaborator) over traits; traits are fine for small, stateless helpers.
- `final` forbids extension; `static` return type supports fluent subclasses; `__toString`, `__get` and magic methods exist, and are mostly a smell in new code.
- **Visibility:** `public`, `protected`, `private`. There are no "underscore means private" conventions to rely on.
- `new` in initializers (8.1) allows `public function __construct(private Clock $c = new SystemClock())`. `clone` is shallow.

Python comparison: PHP has real access modifiers, interfaces as a first-class construct, no multiple inheritance of state (traits are the substitute), and no `__eq__`-based equality for `==` on objects by default (`==` on two objects compares class and property values recursively; `===` compares identity).

### 3.7 Namespaces and autoloading (PSR-4)

A **namespace** is a prefix on class/function/const names to avoid collisions: `namespace Acme\Gradebook;` then the class's fully-qualified name (FQCN) is `Acme\Gradebook\Submission`. `use Acme\Gradebook\Submission;` imports an alias for the current file; it does **not** load anything. A leading backslash `\PDO` means global namespace; inside a namespace, unqualified `PDO` resolves to `Acme\Gradebook\PDO` and fails: a classic first-day error `Class "Acme\Gradebook\PDO" not found`. (Functions and constants fall back to global; classes do not.) **[language]**

**Autoloading**: PHP calls registered autoloader callbacks (`spl_autoload_register`) the first time an unknown class is referenced. **PSR-4** **[convention, PHP-FIG]** defines the mapping: a namespace prefix maps to a base directory; the remainder of the FQCN maps to subdirectories and the class name maps to `ClassName.php` with **exact case**.

```
composer.json:  "autoload": {"psr-4": {"Acme\\Gradebook\\": "src/"}}

Acme\Gradebook\Submission          -> src/Submission.php
Acme\Gradebook\Repo\SqlRepository  -> src/Repo/SqlRepository.php
```

Case matters on Linux; a class `Submission` in `submission.php` works on macOS/Windows (case-insensitive FS) and breaks in Linux production. Moodle has its own autoloader for `classes/` (lesson 3.2), which follows a PSR-4-like rule (namespace = frankenstyle component name; the exact rules are in `core_component::classloader()` in `public/lib/classes/component.php`, checked in lesson 3.2).

### 3.8 Exceptions and errors

`Throwable` has two branches: `Exception` (application) and `Error` (engine: `TypeError`, `ValueError`, `ArgumentCountError`, readonly violations). Warnings and notices (undefined array key is a `Warning` in PHP 8) are not exceptions unless converted by an error handler; Moodle installs its own. Catch the narrowest type, never swallow `Throwable`, chain causes with `new X('msg', 0, $previous)`. `try/catch/finally` has no `else`; multi-catch is `catch (A | B $e)`. Moodle's own type is `moodle_exception` (lesson 3.3).

### 3.9 Input handling and output escaping

`$_GET`, `$_POST`, `$_COOKIE`, `$_SERVER` (including `HTTP_*`), `$_FILES` are attacker-controlled. Three independent defenses: **validate input at the boundary, parameterize queries, escape output at the sink.** None replaces another.

- **Input:** `filter_var($v, FILTER_VALIDATE_INT)` returns `false` on failure (`0` is valid, so test `=== false`). Casting `(int)` loses error information. In Moodle you never read superglobals directly; you use `required_param`/`optional_param` with `PARAM_*` (lesson 3.3).
- **Output, HTML body and quoted attribute:** `htmlspecialchars($s, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`. Verified: `<a href="x">&'</a>` becomes `&lt;a href=&quot;x&quot;&gt;&amp;&#039;&lt;/a&gt;`. The correct escape depends on **context**: inside `<script>` use `json_encode` with `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT`; in URLs `rawurlencode`; HTML escaping is wrong for both. Template engines (Twig, Mustache) escape HTML by default; raw output is the explicit exception (Mustache `{{{ }}}`).
- **CSRF:** state-changing requests need a session-bound token (Moodle: `sesskey`, lesson 3.3).
- **Passwords:** `password_hash($p, PASSWORD_DEFAULT)` and `password_verify()`. Never `unserialize` untrusted data; use `json_decode`. Never put user input in `include` paths.

### 3.10 PDO and prepared statements

PDO is PHP's database abstraction extension. A **prepared statement** sends the SQL template and the parameter values separately: the DB parses the structure first, so values cannot change the SQL grammar. **[runtime]** Caveat: with the MySQL driver PDO defaults to *emulated* prepares (client-side quoting); set `PDO::ATTR_EMULATE_PREPARES => false` for true server-side prepares (checked on php.net, pdo_mysql page: "PDO_MYSQL uses emulated prepares by default"; I did not verify the other drivers' defaults). Placeholders can bind **values only**, not table or column names or `ORDER BY` directions: for those, choose from an allowlist in code.

```php
<?php
declare(strict_types=1);

$pdo = new PDO('sqlite::memory:', null, null, [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);
$pdo->exec('CREATE TABLE u (id INTEGER PRIMARY KEY, name TEXT)');
$st = $pdo->prepare('INSERT INTO u (name) VALUES (:n)');
$st->execute(['n' => "x'; DROP TABLE u;--"]);   // stored as data
print_r($pdo->query('SELECT * FROM u')->fetchAll());
```

I ran this on PHP 8.4.27 with `pdo_sqlite`; the row is stored verbatim and the table survives. `PDO::ERRMODE_EXCEPTION` matters: the default mode in PHP 8 is already exceptions (changed in 8.0), but set it explicitly. Transactions: `beginTransaction()`, `commit()`, `rollBack()`; catch `PDOException`. Use `IN (...)` by generating `?` placeholders for the list.

In Moodle you will not use PDO. You will use `$DB` (`moodle_database`) with `{tablename}` placeholders and `?`/`:name` parameters (verified on moodledev.io DML page; lesson 3.4). The principle is identical.

### 3.11 Composer

`composer.json` declares requirements and autoload rules; `composer.lock` pins exact versions (commit it for applications); `vendor/autoload.php` is the generated autoloader. Commands: `composer require [--dev] pkg`, `composer install` (honors the lock; use in CI), `composer update` (re-resolves, rewrites the lock), `composer dump-autoload`. `^1.2` means `>=1.2.0 <2.0.0`; `~1.2.3` means `>=1.2.3 <1.3.0`. `composer audit` exists (checked in the getcomposer.org CLI docs; local Composer is 2.10.2). Moodle core has its own `composer.json` in the repository root (verified); plugins normally bundle third-party code with a `thirdpartylibs.xml` entry instead (lesson 3.2). Never add a Composer dependency to a Moodle plugin without team agreement.

### 3.12 PHPUnit introduction

PHPUnit runs `test*` methods (or `#[Test]`-attributed ones, PHPUnit 10+) in `*Test.php` classes. Prefer `assertSame` (strict) to `assertEquals` (loose); use `expectException` and data providers (`#[DataProvider('name')]`; providers must be `public` and `static`; checked in the PHPUnit 11.5 manual). Moodle wraps PHPUnit with `advanced_testcase` and `tests/*_test.php` naming (verified; lesson 3.6).

## 4. Worked example

We build `acme/gradebook-lite` step by step. Design goal: the smallest design that satisfies the requirements, no frameworks.

### Step 1: scaffold

### Step 2: a value object, naive then improved

Naive version (what many beginners write):

```php
<?php
class Grade {
    public $value;      // untyped, mutable, public
    function __construct($v) { $this->value = $v; }
}
$g = new Grade("85");
if ($g->value == "85.0") { /* true: loose */ }
$g->value = -999;       // nothing prevents this
```

Problems: no namespace (collides), no types (`"85"` vs `85`), mutable (any code can corrupt it), invariants unenforced, loose comparison hides representation differences.

Improved, `src/Grade.php`:

```php
<?php
declare(strict_types=1);

namespace Acme\Gradebook;

use InvalidArgumentException;

final class Grade
{
    public function __construct(
        public readonly int $points,
        public readonly int $maxPoints,
    ) {
        if ($maxPoints <= 0) {
            throw new InvalidArgumentException('maxPoints must be positive');
        }
        if ($points < 0 || $points > $maxPoints) {
            throw new InvalidArgumentException("points must be within 0..$maxPoints");
        }
    }

    public function percent(): float
    {
        return $this->points / $this->maxPoints * 100;
    }

    public function equals(self $other): bool
    {
        return $this->points === $other->points && $this->maxPoints === $other->maxPoints;
    }
}
```

What changed and why: `final` + `readonly` -> immutable object, can't be corrupted later; constructor validation -> invalid state is unrepresentable (you can't hold a `Grade(-5, 100)`); typed ints with strict types -> `"85"` rejected at the call site; `use InvalidArgumentException;` -> because we are inside a namespace and need the global class; `equals()` -> explicit strict comparison, no reliance on `==`.

Minimum fraction handling: we deliberately use ints for points to avoid float equality problems. Percent is derived (and floats are compared with tolerance in tests: `assertEqualsWithDelta`).

### Step 3: an enum for state

`src/Status.php`:

```php
<?php
declare(strict_types=1);

namespace Acme\Gradebook;

enum Status: string
{
    case Draft = 'draft';
    case Published = 'published';

    public function isVisibleToStudent(): bool
    {
        return $this === self::Published;
    }
}
```

The alternative, string constants `'draft'`/`'published'`, permits typos (`'publised'`) that PHP accepts silently. An enum makes illegal values unrepresentable and `Status::from($dbString)` throws `ValueError` at the boundary where untrusted/DB data enters the domain.

### Step 4: the persistence contract and implementation

Interface (the domain depends on this, not on PDO), `src/GradeRepository.php`:

```php
<?php
declare(strict_types=1);

namespace Acme\Gradebook;

interface GradeRepository
{
    /** @return int new row id */
    public function save(int $studentId, Grade $grade, Status $status): int;

    /** @return list<array{id:int, studentId:int, grade:Grade, status:Status}> */
    public function findByStudent(int $studentId): array;
}
```

Implementation `src/PdoGradeRepository.php`:

```php
<?php
declare(strict_types=1);

namespace Acme\Gradebook;

use PDO;

final class PdoGradeRepository implements GradeRepository
{
    public function __construct(private readonly PDO $pdo)
    {
        // Fail early if the caller handed us a PDO that swallows errors.
        if ($pdo->getAttribute(PDO::ATTR_ERRMODE) !== PDO::ERRMODE_EXCEPTION) {
            throw new \LogicException('PDO must use ERRMODE_EXCEPTION');
        }
    }

    public function save(int $studentId, Grade $grade, Status $status): int
    {
        $st = $this->pdo->prepare(
            'INSERT INTO grades (student_id, points, max_points, status)
             VALUES (:s, :p, :m, :st)'
        );
        $st->execute([
            's' => $studentId, 'p' => $grade->points,
            'm' => $grade->maxPoints, 'st' => $status->value,
        ]);
        return (int) $this->pdo->lastInsertId();
    }

    public function findByStudent(int $studentId): array
    {
        $st = $this->pdo->prepare(
            'SELECT id, student_id, points, max_points, status
               FROM grades WHERE student_id = :s ORDER BY id'
        );
        $st->execute(['s' => $studentId]);
        $out = [];
        foreach ($st->fetchAll(PDO::FETCH_ASSOC) as $r) {
            $out[] = [
                'id'        => (int) $r['id'],
                'studentId' => (int) $r['student_id'],
                'grade'     => new Grade((int) $r['points'], (int) $r['max_points']),
                'status'    => Status::from($r['status']),
            ];
        }
        return $out;
    }
}
```

Design choices: the constructor takes a `PDO` (dependency injection) so tests pass an in-memory SQLite; `(int)` casts on the way out because drivers may return strings (this is also why strict types needs conversion at the persistence boundary); `Status::from` throws on corrupt data rather than hiding it; there's no `SELECT *`.

## 5. Production perspective

**Maintainability.** Immutable value objects and enums shrink the space of states you must reason about. Interfaces at I/O boundaries (repositories, clocks, mailers) make tests fast. Follow PSR-12/PER-CS for style [convention]; in Moodle, follow Moodle's own coding style instead (lesson 3.6): consistency with the host codebase beats personal preference.

**Correctness.** Turn on `declare(strict_types=1)`, run static analysis (PHPStan/Psalm: use what the team uses), avoid `==`. In `php.ini` development: `error_reporting=E_ALL`, `display_errors=On`; production: `display_errors=Off`, `log_errors=On`. A displayed stack trace can leak paths, queries and credentials.

**Performance.** Enable OPcache in production; PHP is rarely the bottleneck, the database is (N+1 queries). Measure before optimizing; this lesson gives no numbers because none were measured.

**Security.** Every external value is hostile. Remember the three independent defenses (validate input, parameterize SQL, escape output) and CSRF tokens. Do not roll your own crypto: `random_bytes()`, `password_hash()`, `hash_equals()`. Keep dependencies patched (`composer audit`).

**Failure handling.** Throw exceptions for exceptional conditions; return values for expected outcomes. Don't use `@` error suppression. Don't catch and ignore. Log with context, return a generic error to the user.

**Testing.** Unit tests for pure logic (value objects, calculators); integration tests with real SQLite/DB for repositories. In Moodle, DB tests run against the real configured DB inside transaction-reset test infrastructure (lesson 3.6).

**Operations.** PHP-FPM pool sizing (`pm.max_children`), `memory_limit`, `max_execution_time`, `upload_max_filesize`, `max_input_vars` (Moodle 5.2 requires at least 5000, verified on the release page) are operational knobs that cause production symptoms (a truncated form, a 502).

**What a senior engineer does differently**
- Runs the code in the strictest mode and reads the first deprecation notice rather than silencing it.
- Treats "it works for my input" as no evidence; writes the hostile-input test first.
- Adds a type or an invariant instead of a comment saying "must be positive".
- Does not introduce a library, framework, or pattern where five lines of PHP suffice, and does not rewrite working legacy code to match personal taste.

**Common beginner mistakes**

| Mistake | Diagnosis |
|---|---|
| `Class "X\PDO" not found` | FQCN carries your namespace plus a global class name: add `use PDO;` |
| `Class "Acme\Foo" not found` on Linux only | compare namespace, path and **case**; `composer dump-autoload` |
| `foreach ... as &$v` corrupts last element | `unset($v)`; avoid by-reference |
| `if ($x)` for "was provided" | `0`/`"0"` treated as missing: use `isset`/`=== null` |
| float money | `0.1 + 0.2 !== 0.3`: integer minor units |

**Lab D. Strict types scope.** File `lib.php` has no `declare(strict_types=1)` and defines `function half(int $n): float { return $n / 2; }`. File `main.php` has `declare(strict_types=1);` and calls `half("10")`. Then a third file `main2.php` without the declare calls `half("10")`. What happens in each? (Use what you learned in 3.2 of this lesson: whose strictness governs a call?)

### Reveal (read after predicting)

- **Lab A.** Both strings are numeric strings in exponent form with a zero mantissa, so `==` compares `0 == 0` and returns `true`: two different tokens "match". The second call: `"abc" == "ABC"` is `false` (non-numeric strings compare as strings, case-sensitively). Fix: `hash_equals($stored, $given)` (both strings required; constant-time). *Diagnosis procedure:* for any authentication or integrity comparison, grep for `==` and `!=` near the words token, hash, key, password, signature, nonce; review each.
- **Lab B.** `Fatal error: Uncaught Error: Class "App\PDO" not found`. Inside a namespace, unqualified class names resolve relative to the namespace. The return type `\PDO` is fully qualified and fine; the `new PDO` is not. Fix with `use PDO;` or `new \PDO`. *Diagnosis:* read the FQCN in the error; if it has your namespace prefix and a name you expect to be global, it is a missing `use`/backslash.
- **Lab C.** `[2, 4, 6]` becomes `[2, 4, 4]`. After the first loop `$x` is still a reference to `$xs[2]`; the second loop assigns each element into `$x`, overwriting index 2 with 2, then 4, then the (now-overwritten) current value 4. *Diagnosis:* an element duplicated at the end of an array after two consecutive foreach loops using the same variable name. Fix: `unset($x)` after the first loop, or use `array_map`.
- **Lab D.** `main.php`: `TypeError` because the *call site* file is strict. `main2.php`: the call succeeds and returns `5.0`, because the call site is coercive; the callee's file mode is irrelevant. Hence strictness is a property of the caller's file. (Rule from the manual **[language]**; verify by running it.) *Diagnosis:* when a type error "doesn't happen" in one place and does elsewhere, check the `declare` at the top of the **calling** file.
