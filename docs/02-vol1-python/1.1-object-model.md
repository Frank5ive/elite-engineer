## 1. Engineering problem

You join a team that runs a FastAPI service. A ticket says: "Users occasionally see another user's feature flags." Nobody can reproduce it locally. The cause, found after two days, is this:

```python
def load_flags(user_id, overrides={}):
    overrides.setdefault("beta", user_id % 2 == 0)
    return overrides
```

The default dict is created once, when `def` executes. Every call that omits `overrides` receives the same dict. The first user to hit the function sets `beta`; everyone after sees that value. It passes unit tests because each test calls it once, and it fails in production because the process lives for weeks.

The same family shows up as: caches returning internal lists that callers then mutate; shallow `copy()` of nested config; loops registering callbacks that all see the last value; decorators that erase `__name__`; classes that define `__eq__` and become unhashable.

None of these is exotic. All are cheap to prevent once you can say, for any line of code, which objects exist, which names point to them, and who else holds a reference. That is the skill this lesson trains.

## 2. Learning objectives

## 3. First-principles explanation

### 3.1 Names are references; objects have identity, type and value

In Python, a variable is a **name bound to an object**. The assignment `b = a` does not copy anything. It makes a second name refer to the same object. Every object has:

- an **identity** (never changes during its life; `id(obj)`, and in CPython this is the memory address),
- a **type** (`type(obj)`),
- a **value**, which is mutable for some types and not for others.

```text
a = [1, 2]        names            objects
b = a             a ----+
c = [1, 2]        b ----+--->  list@0x...A  [1, 2]
                  c ------->  list@0x...B  [1, 2]
```

`a is b` compares identity. `a == c` calls `a.__eq__(c)`, which for lists compares elements. These are different questions. (Language guarantee.)

```python
# run-check
a = [1, 2]; b = a; c = [1, 2]
print(a is b, a is c, a == c, id(a) == id(b))
```

Output: `True False True True`.

Use `is` only for singletons such as `x is None` and sentinels you created. Never use it for numbers or strings: `256 is 256` is `True` in CPython only because small ints are cached (implementation detail; the compiler warns about `is` with a literal).

### 3.2 Mutable vs immutable

Immutable (value cannot change after creation): `int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None`. Mutable: `list`, `dict`, `set`, `bytearray`, and instances of ordinary user classes.

Consequences:

- `s += "x"` on a `str` **rebinds** `s` to a new object. The old string is unchanged. Anyone else holding the old string is unaffected.
- `lst += [3]` on a `list` calls `list.__iadd__`, which **mutates in place** and then rebinds the name to the same object. Every alias sees the change.
- A tuple is only shallowly immutable. It holds references; the referenced objects can still change.

```python
# run-check
t = ([1], 2)
try:
    t[0] += [3]          # list mutated in place, THEN the tuple item assignment fails
except TypeError as e:
    print("TypeError:", e)
print(t)                 # ([1, 3], 2): the error happened and the mutation still occurred
```

This one is a famous trap: `t[0] += [3]` expands to `tmp = t[0]; tmp = tmp.__iadd__([3]); t[0] = tmp`. The in-place step succeeds; the store into the tuple raises.

### 3.3 Default arguments are evaluated once

`def f(x, acc=[])` evaluates `[]` when the `def` statement runs, stores the result in `f.__defaults__`, and reuses that same object for every call that omits the argument.

```python
# run-check
def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

print(add_tag("a"), add_tag("b"))   # ['a', 'b'] ['a', 'b']
print(add_tag.__defaults__)          # (['a', 'b'],)

def add_tag_fixed(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags

print(add_tag_fixed("a"), add_tag_fixed("b"))   # ['a'] ['b']
```

Note the first line prints the same list twice because both calls returned the same object, and by the time `print` runs it holds both tags.

Use `None` as the sentinel when `None` is not itself a valid argument. When it is, create a private sentinel: `_MISSING = object()` and test `is _MISSING`. Immutable defaults (`0`, `""`, `()`, `None`, `frozenset()`) are safe.

### 3.4 Shallow vs deep copy

| Operation | Copies | Shares |
|---|---|---|
| `b = a` | nothing | everything (same object) |
| `a.copy()`, `list(a)`, `a[:]`, `copy.copy(a)`, `{**a}` | the outer container | all contained objects |
| `copy.deepcopy(a)` | the outer container and, recursively, contained objects | only things that cannot or should not be copied (it keeps a memo to preserve cycles and shared substructure) |

```python
# run-check
import copy
orig = {"users": [{"n": "a"}], "n": 1}
sh = orig.copy()
dp = copy.deepcopy(orig)
orig["users"][0]["n"] = "X"
print(sh["users"][0]["n"], dp["users"][0]["n"])   # X a

rows = [[0] * 2] * 3          # three references to ONE inner list
rows[0][0] = 9
print(rows)                    # [[9, 0], [9, 0], [9, 0]]
rows = [[0] * 2 for _ in range(3)]
rows[0][0] = 9
print(rows)                    # [[9, 0], [0, 0], [0, 0]]
```

`deepcopy` is slow on big structures, can fail on locks/sockets/files, and honours `__deepcopy__`. Often the better design is not to share mutable state at all: build new values or use immutable types (frozen dataclasses, Lesson 1.3).

### 3.5 Scope: LEGB

Name lookup inside a function searches, in order: **L**ocal, **E**nclosing function scopes, **G**lobal (module), **B**uilt-in. (Language guarantee.)

Two rules cause most confusion:

1. Whether a name is local is decided **at compile time**: if the function body assigns to it anywhere, it is local for the whole function.
2. `global x` and `nonlocal x` declare that assignment should rebind a name in the module or nearest enclosing function scope. Reading never needs them. Mutating an object through a name (`lst.append`) never needs them either.

```python
# run-check
x = 10
def f():
    try:
        print(x)          # x is local (assigned below), and not yet bound
    except UnboundLocalError as e:
        print("UnboundLocalError:", e)
    x = 5
f()
```

### 3.6 Closures and late binding

A closure is a function plus references to variables (cells) of its enclosing scope. It captures the **variable**, not the value at definition, and reads it when called.

```python
# run-check
import functools
fs = [lambda: i for i in range(3)]
print([f() for f in fs])                                  # [2, 2, 2]
fs = [lambda i=i: i for i in range(3)]                    # fix 1: bind via default argument
print([f() for f in fs])                                  # [0, 1, 2]
fs = [functools.partial(lambda i: i, i) for i in range(3)]  # fix 2: partial binds the value now
print([f() for f in fs])                                  # [0, 1, 2]

def counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

c = counter(); c()
print(c(), c.__closure__[0].cell_contents)                # 2 2
```

Binding via a default argument works because defaults are evaluated at definition (3.3). A factory function taking `i` is a third fix. Prefer a class when closure state is non-trivial.

### 3.7 Decorators

`@d` above `def f` means `f = d(f)`. A decorator is an ordinary function returning a replacement callable. A decorator with arguments, `@d(3)`, is `f = d(3)(f)`: one more layer.

Without `functools.wraps`, the wrapper replaces the original's `__name__`, `__doc__`, `__module__`, `__qualname__`, and `__annotations__`, and loses `__wrapped__`. Debuggers, tracebacks, framework routing, documentation tools and `inspect.signature` all rely on that metadata. (FastAPI inspects signatures to build parameters: a decorator that hides the signature breaks dependency resolution. See Lesson 2.2.)

```python
# run-check
import functools

def nowraps(fn):
    def wrapper(*a, **k):
        return fn(*a, **k)
    return wrapper

def timed(fn):
    @functools.wraps(fn)
    def wrapper(*a, **k):
        return fn(*a, **k)
    return wrapper

@nowraps
def h1(): "doc one"
@timed
def h2(): "doc two"
print(h1.__name__, h1.__doc__)               # wrapper None
print(h2.__name__, h2.__doc__, h2.__wrapped__.__name__)  # h2 doc two h2
```

### 3.8 Choosing among tuple, list, dict, set

`tuple`: fixed record, hashable if its elements are. `list`: growable ordered sequence (amortised O(1) append, O(n) membership and front insertion). `dict`: key lookup, average O(1), insertion-ordered since 3.7 (language guarantee). `set`/`frozenset`: membership and uniqueness, elements must be hashable, no meaningful order. `collections.deque`: O(1) at both ends. The complexities are CPython average cases (VERIFY: Python wiki TimeComplexity page before quoting numbers).

### 3.9 The hash/eq contract

Dict keys and set members must be **hashable**. The contract:

1. If `a == b` then `hash(a) == hash(b)`.
2. The hash of an object must not change while it is in a dict or set. In practice: hash only on immutable state.
3. Defining `__eq__` without `__hash__` sets `__hash__` to `None`, making instances unhashable. This is deliberate and protects rule 1.

```python
# run-check
class P:
    def __init__(self, x): self.x = x
    def __eq__(self, o): return isinstance(o, P) and self.x == o.x

print(P.__hash__)                  # None
try:
    {P(1)}
except TypeError as e:
    print(e)                        # unhashable type: 'P'

class Q:
    __slots__ = ("x",)
    def __init__(self, x): self.x = x
    def __eq__(self, o): return isinstance(o, Q) and self.x == o.x
    def __hash__(self): return hash(self.x)

print(len({Q(1), Q(1)}))            # 1
print(hash(1) == hash(1.0), {1: "a"}.get(1.0), 1 == True)  # True a True
```

The last line shows the contract at work: `1 == 1.0 == True`, so they collide as dict keys. `Q` is still mutable, so mutating a `Q` inside a set can make it unfindable; prefer frozen dataclasses (Lesson 1.3).

Return `NotImplemented` (do not raise) from `__eq__` for unknown operand types so Python can try the reflected operation.

### 3.10 CPython memory management, practically

(CPython implementation detail; PyPy and others differ. Free-threaded builds of 3.13 change internals; VERIFY with `python3 -VV` and the docs for your interpreter.)

- Every object has a **reference count**. Binding a name, adding to a container, passing as an argument each add one; unbinding removes one. At zero, the object is freed immediately and deterministically. This is why `with open(...)` closing is predictable in CPython but must not be *relied on* as a language guarantee.
- Reference counting cannot free **cycles** (`a.o = b; b.o = a`). A **cyclic garbage collector** (`gc` module) periodically finds unreachable cycles. It is generational and automatic; `gc.collect()` forces a full pass.
- `sys.getrefcount(obj)` reports one more than you expect because the argument itself is a reference. The exact numbers vary by version (3.12+ has immortal objects such as `None` and small ints, whose counts do not behave normally).
- `weakref.ref(obj)` refers without keeping alive; use it for caches and observer lists.
- `__del__` is a poor cleanup mechanism (timing not guaranteed); use context managers (Lesson 1.2).

```python
# run-check
import sys, gc, weakref
l = []
print(sys.getrefcount(l))          # 2 on CPython 3.13: the name l + the call argument
alias = l
print(sys.getrefcount(l))          # 3

class Node: pass
n1, n2 = Node(), Node()
n1.o, n2.o = n2, n1                # cycle
r = weakref.ref(n1)
del n1, n2
print(r() is not None)             # True: refcounts never reached zero
gc.collect()
print(r())                         # None: the cycle collector freed it
```

Practical consequence: steady memory growth in a service is usually a *reachable* object (a module-level dict or cache), not a leak the GC missed. Find who holds the reference.

## 4. Worked example: a TTL cache decorator

Requirement: cache the result of an expensive function for N seconds, per distinct arguments, testable without sleeping.

### 4.1 Naive version

```python
# run-check
_cache = {}

def naive(fn):
    def wrapper(*args, **kwargs):
        if args in _cache:
            return _cache[args]
        _cache[args] = fn(*args, **kwargs)
        return _cache[args]
    return wrapper

@naive
def f(x, scale=1): return x * scale
@naive
def g(x): return -x

print(f(2), f(2, scale=10), g(2))      # 2 2 2   (expected 2 20 -2)
```

What is wrong, in order:

1. One module-level dict is shared by every decorated function: `g(2)` returns `f(2)`'s result.
2. The key ignores `kwargs`: `f(2, scale=10)` hits the entry for `f(2)`.
3. No expiry at all, so it is not a TTL cache.
4. The wrapper loses the function's metadata (3.7).
5. It returns the stored object itself. If the function returns a list, a caller who appends to it corrupts the cache.
6. Unbounded growth (a size bound is a project extension).

### 4.2 Improved version

```python
# run-check
import copy
import functools
import time
from collections.abc import Callable, Hashable
from typing import Any

def ttl_cache(seconds: float, clock: Callable[[], float] = time.monotonic):
    """Cache results per (args, kwargs) for `seconds`. Python 3.12+."""
    def decorator(fn):
        store: dict[Hashable, tuple[float, Any]] = {}      # per decorated function

        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            key = (args, tuple(sorted(kwargs.items())))    # TypeError if unhashable: fail loudly
            now = clock()
            hit = store.get(key)
            if hit is not None and now - hit[0] < seconds:
                return copy.deepcopy(hit[1])
            value = fn(*args, **kwargs)
            store[key] = (now, copy.deepcopy(value))
            return value

        wrapper.cache_clear = store.clear
        return wrapper
    return decorator

now = [0.0]
calls = []

@ttl_cache(10, clock=lambda: now[0])
def load(user_id: int, *, fields: tuple[str, ...] = ("name",)) -> list[str]:
    calls.append(user_id)
    return list(fields)

r = load(1); r.append("corrupt")
print(load(1), calls)                   # ['name'] [1]
now[0] = 11; load(1); print(calls)      # [1, 1]
try:
    load([1])
except TypeError as e:
    print(e)                            # unhashable type: 'list'
print(load.__name__)                    # load
```

Design decisions and why:

- **State inside `decorator`**: each decorated function gets its own `store`. That fixes bug 1 using a closure instead of a global.
- **Key includes sorted kwargs**: `f(1, a=1, b=2)` and `f(1, b=2, a=1)` are the same call. Positional vs keyword spellings of the same call still differ (`f(1)` vs `f(x=1)`): `functools.lru_cache` has the same limitation (documented). Accept and document it.
- **`clock` injected**, defaulting to `time.monotonic` (not `time.time`, which can jump when the system clock is adjusted). Tests pass a fake clock: no `sleep`. This is the pattern Lesson 1.4 generalizes.
- **Unhashable arguments raise `TypeError`** rather than falling back to `str(args)`, which would silently conflate distinct values.
- **`deepcopy` on the way in and out** trades CPU for safety. It is the right default for a teaching version; in production decide per use case: return immutable results (tuples, frozen dataclasses) and delete the copying, which is what a senior engineer usually does.
- **Not thread-safe.** The check-then-set sequence can run twice under threads; the project adds a lock.

Prefer `functools.lru_cache`/`functools.cache` when you do not need expiry; do not hand-write what the standard library provides without a requirement that justifies it.

## 5. Production perspective

**Correctness.** These are state bugs; they depend on process lifetime and call order, so call twice with different inputs and mutate the returned value in tests.

**Class attributes are shared defaults too.** `class A: items = []` shares one list among all instances. Create per-instance state in `__init__`. Dataclasses reject mutable defaults and require `field(default_factory=list)` (Lesson 1.3).

**Maintainability.** Prefer returning new objects over mutating arguments, and say so when you must mutate. Convention: `list.sort()` mutates and returns `None`; `sorted()` returns a new list.

**Performance.** `deepcopy` is often the hidden hot spot in "defensive" code; measure with `cProfile` (5.1) before and after.

**Security.** Mutable state shared between requests is a cross-tenant data leak (the opening scenario): treat it as a vulnerability class.

**What a senior engineer does differently.**

- Reads a signature and asks: does it mutate inputs? does it return internal state?
- Uses immutable data for values that cross boundaries and mutable data only inside one function's local scope.
- Writes the aliasing test (mutate result, call again) before calling a cache correct.
- Does not "fix" a shared-state bug with `deepcopy` sprinkled everywhere; fixes ownership.

**Common beginner mistakes and diagnosis.**

| Symptom | Likely cause | Diagnose |
|---|---|---|
| State from one call visible in another | Mutable default, class attribute, module-level container | Print `f.__defaults__`, `vars(Class)`, `id()` of the object in both calls |
| Editing a "copy" changes the original | Shallow copy of nested data, `[[0]*n]*m` | `a is b`, `a["k"] is b["k"]` |
| All callbacks see the last value | Late-binding closure | `fn.__closure__[0].cell_contents` |
| `UnboundLocalError` on a name you only "read" | Assigned later in same function | Search the function body for any assignment, `import`, `for` target, or `with ... as` using the name |
| `TypeError: unhashable type` | `__eq__` without `__hash__`, or mutable key | `type(obj).__hash__` |
| Memory grows steadily | Reachable container or cache growing | `tracemalloc` snapshots; `gc.get_referrers(obj)` on a sample |

### 5.1 Optional: concurrency and profiling orientation

Vocabulary only, before Lessons 2.6 and 4.4. **GIL**: in the standard CPython build one thread runs Python bytecode at a time, so threads help I/O-bound work, not CPU-bound Python (3.13 has an experimental free-threaded build; VERIFY with `sys._is_gil_enabled()`). **Threads** share memory and need locks around check-then-act code like the cache above. **Processes** have separate memory, give CPU parallelism, and pickle arguments and results: aliasing does not cross the boundary. **asyncio** is one thread with cooperative switching at `await`; a blocking call stalls everything. **Profiling**: `python3 -m cProfile -s cumulative script.py`; profile first, optimize second. No numbers are claimed here.

## 6. Failure laboratory

Mode A. Predict the output **before running** it. Write your prediction for the three print lines.

```python
# run-check
handlers = {}

def register(name, tags=[]):
    def deco(fn):
        tags.append(name)
        handlers[name] = (fn, tags)
        return fn
    return deco

for name in ("a", "b"):
    @register(name)
    def h():
        return name

print(handlers["a"][0](), handlers["b"][0]())
print(handlers["a"][1] is handlers["b"][1])
print(handlers["a"][1])
```

Questions to answer in writing: What does each handler return? Is `tags` shared? Which two separate lessons from Section 3 does one snippet violate? Give two different fixes for each.

### Reveal (read after predicting)

Output:

```text
b b
True
['a', 'b']
```

Two bugs, independent:

1. **Late binding.** Both `h` functions read the module-level `name` when called, after the loop ended, so both return `"b"`. Fix A: `def h(name=name): return name`. Fix B: a factory `def make(name): def h(): return name; return h`.
2. **Mutable default.** `tags=[]` was created once at `def register`; both decorators append to it. Fix A: `tags=None` then `tags = [] if tags is None else tags` inside `register`. Fix B: if registration order is the intent, then make the shared list an explicit module-level `_registered_names` so the sharing is visible.

Systematic diagnosis procedure for "values are shared or wrong":

1. State the expectation in terms of objects: "each handler should have its own list."
2. Test identity: `a is b` for the suspicious pair. `True` means aliasing; stop looking at values.
3. Find where each object was **created** (the `[]` literal, the `def`, the module-level assignment). If creation happened at definition time and use happens per call, you have found an evaluated-once bug.
4. For callbacks/lambdas: print `fn.__closure__` and `cell_contents`; if the cell holds the final loop value, it is late binding.
5. Write the failing test first, then fix, then confirm the test passes.

## 8. Independent implementation challenge

Mode A (closed-book, no AI). 60-90 minutes.

Implement `once_per_key(window: float, clock=time.monotonic)`: a decorator **factory** for functions whose **first positional argument** is a string key (for example a user id). The decorated function runs at most once per key per window; calls within the window for the same key return `None` without calling the function. Requirements:

- Per-decorated-function state (two decorated functions do not interfere).
- The decorated function keeps `__name__`, `__doc__` and `__wrapped__`.
- `.reset(key=None)` clears one key or all keys.
- Raises `TypeError` with a clear message if the first argument is not a `str` (do not use `assert`).
- Time is injected; your tests use a fake clock and never sleep.
- No module-level mutable state. No `global`.

Write pytest-style tests (plain `assert`; you may run them as plain functions if pytest is not installed) covering: first call runs, second within window suppressed, call after the window runs, two keys independent, two decorated functions independent, `reset`, metadata preserved, wrong-type key. Then add one test that would fail if someone replaced your per-function dict with a module-level dict.
