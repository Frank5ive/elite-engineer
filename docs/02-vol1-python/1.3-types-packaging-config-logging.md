## 1. Engineering problem

Monday, 09:30. You clone the service, run `pip install -r requirements.txt`, and the tests fail with an import error nobody else has. The file came from `pip freeze` on a laptop six months ago, and an unpinned transitive dependency has since broken. Meanwhile production crashes at startup because `DEBUG = bool(os.environ.get("DEBUG", False))` is `True` for the string `"false"`. The crash log says `ERROR something went wrong`, with no traceback and no request id. And last week's refactor made a function return `None` on a new path; the failure surfaced 400 lines away as `AttributeError: 'NoneType' object has no attribute 'id'`.

Each of these has a standard fix: a pinned and reproducible environment, configuration parsed and validated once at startup, structured logs with correlation ids, and static types that turn the `None` case into an editor warning.

## 3. First-principles explanation

### 3.1 What type hints are

Annotations are metadata stored in `__annotations__`. **Python does not enforce them at runtime** (language guarantee). Their consumers are static checkers (mypy, pyright), editors, and libraries that read them deliberately (dataclasses, Pydantic, FastAPI). The checker reasons about your code without running it and reports contradictions.

This is *gradual typing*: you can type part of a codebase. `mypy --strict` turns on the strictest practical set (no untyped defs, no implicit `Any`, no unused ignores, and more: VERIFY the exact flag set with `mypy --help`).

```python
# run-check
from __future__ import annotations
from collections.abc import Callable, Sequence
from typing import Final, Literal, Protocol, TypedDict

def first[T](xs: Sequence[T]) -> T:            # PEP 695 syntax, Python 3.12+
    if not xs:
        raise IndexError("empty")
    return xs[0]

type Handler = Callable[[str], int]            # 3.12+ type alias statement

class Row(TypedDict):
    id: int
    name: str

Mode = Literal["r", "w"]
MAX: Final = 3

class Repo(Protocol):                          # structural: no inheritance needed
    def get(self, id: int) -> Row | None: ...

class MemRepo:
    def __init__(self) -> None:
        self.rows: dict[int, Row] = {}
    def get(self, id: int) -> Row | None:
        return self.rows.get(id)

def name_of(repo: Repo, id: int) -> str:
    row = repo.get(id)
    if row is None:                            # narrowing: after this, row is Row
        raise LookupError(id)
    return row["name"]

h: Handler = len
print(first([1, 2]), h("abc"), MAX)            # 1 3 3

y: str = first([1, 2])                         # mypy: Incompatible types in assignment ...
def bad(m: Mode) -> None: ...
bad("x")                                       # mypy: incompatible type "Literal['x']" ...
try:
    name_of(MemRepo(), "1")                    # type: ignore[arg-type]  # mypy rejects; runtime does not
except LookupError:
    print("runtime accepted a str id: hints are not enforcement")
```

Running `mypy --strict` on this block (with the ignore comment removed from the last call) reports three errors: the `y` assignment, `bad("x")` and `name_of(..., "1")`; with the comment it reports the first two. The `type: ignore` here is a demonstration; real ones need a reason and an error code (strict mode flags unused ones).

Key tools:

- **`X | None`** (3.10+) instead of `Optional[X]`. The checker forces you to handle `None` before attribute access: this alone prevents the production bug in Section 1.
- **Generics** (`list[int]`, `dict[str, Row]`, `Sequence[T]`). Accept the most general type you actually need for **parameters** (`Sequence`, `Mapping`, `Iterable`), return the most specific for **results**.
- **`Protocol`**: structural typing (any object with the right methods satisfies it), the typed form of duck typing. Use it for the seams you will fake in tests (Lesson 1.4). Prefer `Protocol` for "what I need from a collaborator"; use an ABC when you want shared implementation or explicit registration.
- **`TypedDict`** for dict-shaped data at boundaries (JSON). It is checked statically only; validate untrusted data at runtime (Pydantic, Lesson 2.2).
- **`Literal`, `Final`, `Self`, `Callable`, `ParamSpec`** for finer contracts (the `objkit.ttl_cache` in Lesson 1.1's solution uses `ParamSpec`).
- **`TYPE_CHECKING`** guards imports needed only for hints and can break import cycles; `from __future__ import annotations` makes annotations lazy strings (Pydantic and dataclasses have rules about that: VERIFY in their docs before enabling it in model modules).
- **`Any`** switches checking off for that value and is contagious. Prefer `object` (must narrow before use) or a precise type. **`cast`** and **`# type: ignore`** are promises you make to the checker: each should have a comment saying why it is true.

**mypy vs pyright**: both implement the typing spec with differences in inference and defaults; pyright powers Pylance, mypy is the long-standing reference implementation. Use your team's, and agree which is authoritative. Static types find None handling, wrong arguments and missing cases, not logic errors, and they do not validate external data.

Worth the cost: public interfaces, module boundaries, `None`-returning paths, refactoring zones. Skip: throwaway scripts. In a legacy repo, adopt strict typing per module with team agreement, never in one giant change.

### 3.2 Dataclasses

`@dataclass` generates `__init__`, `__repr__`, `__eq__` (and `__hash__` rules) from annotated fields.

```python
# run-check
from dataclasses import dataclass, field, replace

@dataclass(frozen=True, slots=True)
class Money:
    cents: int
    currency: str = "USD"
    def __post_init__(self) -> None:
        if self.cents < 0:
            raise ValueError("cents must be >= 0")

m = Money(5)
print(m, hash(m) == hash(Money(5)), replace(m, cents=7))
try:
    m.cents = 1                                   # type: ignore[misc]
except Exception as e:
    print(type(e).__name__)                       # FrozenInstanceError
try:
    @dataclass
    class Bad:
        xs: list[int] = []
except ValueError as e:
    print(e)        # mutable default <class 'list'> for field xs is not allowed: use default_factory

@dataclass
class Good:
    xs: list[int] = field(default_factory=list)
print(Good().xs is Good().xs)                    # False
```

- `frozen=True` makes instances immutable (assignments raise) and, with the default `eq=True`, generates a `__hash__`: this is the safe value-object pattern from Lesson 1.1's hash/eq contract. `slots=True` (3.10+) removes the per-instance `__dict__`.
- Mutable defaults are rejected for `list`, `dict`, `set` fields: you must use `default_factory` (Lesson 1.1, 3.3 and "class attributes are shared defaults").
- `__post_init__` is the validation hook. Dataclasses do **not** validate types at runtime. Pydantic models do (Lesson 2.2): use dataclasses for trusted internal values, Pydantic for untrusted input.
- `NamedTuple` suits tiny records returned from functions; plain classes when behaviour dominates.

### 3.3 Modules, packages and imports

`import a.b` finds a module, executes it **once**, stores the module object in `sys.modules`, and binds a name. Later imports return the cached object. Consequences: module top-level code runs at import time (so do not open connections or read config at import time), module-level state is a singleton (Lesson 1.1 on shared state), and reloading is not automatic.

The import system searches `sys.path`, whose first entry is the directory of the **script** you ran (or the current directory with `python -m`); this is the source of "works in one place, not another".

```text
repo/
  pyproject.toml
  src/
    billing/              <- the importable package
      __init__.py
      config.py
      logging_setup.py
      cli.py
  tests/
    test_config.py
```

Why the **src layout**: the package is not importable from the repo root unless installed, so tests exercise the *installed* package, which catches packaging mistakes (missing files, missing `__init__.py`) that a flat layout hides. Install it in **editable** mode during development (`uv sync` does this for the project itself; with pip: `pip install -e .`).

Rules: use absolute imports (`from billing.config import Settings`), relative only for close siblings. Run code as `python -m billing.cli` or the console script, never `python src/billing/cli.py` (that puts `src/billing` first on `sys.path`, so a local `logging.py` would shadow the standard library). Do not name modules after stdlib modules (`logging.py`, `json.py`, `types.py`).

**Circular imports**: `a` imports `b` and `b` imports `a` at top level; the second import finds a partially initialised module in `sys.modules`, giving `ImportError: cannot import name ...`. Fixes by preference: move the shared piece to a third module (the cycle is a design smell); import inside the function that needs it (comment why); `TYPE_CHECKING` for type-only imports. Keep `__init__.py` small.

### 3.4 `pyproject.toml`, environments, installers, lockfiles

`pyproject.toml` is the standard project file (PEP 517/518/621): build system, project metadata and tool configuration in one place.

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "billing-svc"
version = "0.1.0"
description = "Example service"
requires-python = ">=3.12"
dependencies = []                      # runtime dependencies, with ranges, e.g. "httpx>=0.27,<1"

[project.scripts]
billing = "billing.cli:main"           # creates a `billing` command on install

[dependency-groups]                    # PEP 735: development-only groups (not published)
dev = ["pytest>=8", "mypy>=1.10"]

[tool.hatch.build.targets.wheel]
packages = ["src/billing"]             # REQUIRED here: project name (billing-svc) != package dir (billing)

[tool.pytest.ini_options]
testpaths = ["tests"]

[tool.mypy]
strict = true
python_version = "3.12"
```

This file was parsed with `tomllib` and used with `uv lock`, `uv sync --locked`, `uv run billing` and `uv run pytest` locally. Before the `[tool.hatch.build.targets.wheel]` table was added, `uv sync` **failed** with hatchling's "Unable to determine which files to ship" error because the distribution name `billing-svc` normalizes to `billing_svc`, which is not a directory under `src/`. That is a real packaging error worth recognizing; the fix is the explicit `packages` line (or naming the project `billing`).

**Virtual environments.** A venv is a directory with its own interpreter link and `site-packages`, isolating a project's dependencies. Create with `python3 -m venv .venv` or `uv venv`; use `.venv/bin/python` or activate. Never `sudo pip install`; never commit `.venv`.

**pip vs uv.** `pip` is the standard installer; `uv` is a fast resolver, installer and project manager with a cross-platform lockfile `uv.lock`. Both read `pyproject.toml`. Which one your employer uses (pip, uv, Poetry...) is a team decision: learn theirs first; the concepts transfer.

**Reproducibility, in layers:**

| Layer | What pins it | Weakness |
|---|---|---|
| Your direct dependencies | Ranges in `pyproject.toml` (`>=,<`) | Ranges are intentions, not reproducible installs |
| Transitive dependencies and exact versions | **Lockfile** (`uv.lock`; `pip-compile` output; Poetry's `poetry.lock`) | Must be committed and refreshed deliberately |
| Integrity | Hashes in the lock/requirements (`--require-hashes`) | Slight friction |
| Interpreter | `requires-python`, `.python-version`, base image tag | Patch versions drift unless pinned |
| OS libraries | Container image digest | Out of scope here |

Workflow (run locally): `uv lock` writes `uv.lock`; `uv sync --locked` installs exactly the lock and **fails if the lock is stale** (it did, after I changed the project version without re-locking); `uv sync --frozen` installs without the freshness check; `uv lock --check` verifies; `uv add pkg` edits `pyproject.toml` and the lock; `uv run cmd` runs inside the project environment. CI and Docker builds use `--locked`. `pip freeze > requirements.txt` records whatever is installed, with no hashes and no dependency structure: a weak lock. Libraries publish ranges; applications commit lockfiles.

### 3.5 Configuration (12-factor)

The 12-factor rule (https://12factor.net/config): configuration that varies between deploys (database URL, credentials, timeouts, feature toggles) lives in the **environment**, not in code or committed files. Operational rules:

1. Read the environment **once**, at startup, into a typed, immutable settings object; pass it down. Do not call `os.environ` from deep inside business logic (untestable, scattered, un-validated).
2. Environment variables are strings. Parse explicitly. `bool("false")` is `True`, because any non-empty string is truthy.
3. Validate at startup and **fail fast** with a message listing every problem, not the first.
4. Secrets: never log them, never put them in `repr`, never commit them (`.env` in `.gitignore`; commit `.env.example` with fake values). Prefer injection by the platform's secret manager (Lesson 2.5).
5. Defaults are for non-secret, safe values only. A missing secret must be an error, not a default.
6. Make the loader take a `Mapping` so tests pass a dict.

### 3.6 Logging

`logging` has four concepts: **loggers** (named, hierarchical: `billing.worker` is a child of `billing`), **handlers** (where records go), **formatters** (how they look), **filters** (add or drop data). Records flow from the logger up through ancestors' handlers unless `propagate=False`; the **root** logger's handlers usually do the output.

Rules that matter in production:

1. **Libraries** create `log = logging.getLogger(__name__)` and never configure handlers (at most a `NullHandler`). **Applications** configure logging exactly once, at the entry point.
2. `logging.basicConfig` does nothing if the root logger already has handlers (unless `force=True`); the module-level helpers `logging.info(...)` call `basicConfig()` implicitly the first time (Section 6 lab).
3. Use lazy formatting: `log.info("user=%s n=%d", user, n)`. The string is only built if the record is emitted. Never `log.info(f"...")` with expensive values (and f-strings defeat grouping by message template).
4. `log.exception("msg")` inside an `except` block logs at ERROR **with the traceback**. `log.error(e)` logs only the message text and loses the stack.
5. Levels: DEBUG (diagnosis), INFO (normal state changes), WARNING (unexpected but handled), ERROR (operation failed), CRITICAL (process cannot continue). Log an error **once**, at the boundary that handles it (Lesson 1.2).
6. **Structured logs**: one JSON object per line, with stable keys, so a log system can filter on `request_id` or `charge_id` instead of regexes. Attach per-request context with `contextvars` (works across `await` and does not leak between concurrent requests, unlike a module global; Lesson 1.1).
7. Never log secrets, tokens or full card numbers; logs are copied to many systems. `print` is not logging: no levels, destinations or context.

## 4. Worked example: settings and JSON logging for `billing`

The following is a complete module: validated settings, a request-id context variable, a filter, a JSON formatter and `dictConfig` setup. It type-checks under `mypy --strict` (verified) and its `__main__` block demonstrates failure reporting, secret hiding and structured output.

### 4.1 Naive version

```python
# not runnable as-is: illustrative
import os, logging
DEBUG = bool(os.environ.get("APP_DEBUG", False))        # "false" -> True
DB = os.environ["APP_DATABASE_URL"]                       # KeyError traceback, first missing only
logging.basicConfig(level=logging.INFO)                   # at import time; no-ops if already configured
logging.info(f"starting with {DB}")                       # leaks the password; eager f-string
def charge(user):
    try:
        ...
    except Exception as e:
        logging.error(e)                                  # no traceback, no context
```

### 4.2 Improved version

```python
# run-check
# file: config_logging.py
import contextvars
import json
import logging
import logging.config
import os
import sys
from collections.abc import Mapping
from dataclasses import dataclass, field
from typing import IO


class ConfigError(Exception):
    """One or more settings are missing or invalid (message lists all of them)."""


@dataclass(frozen=True, slots=True)
class Settings:
    database_url: str = field(repr=False)          # secret-bearing: never printed by repr
    log_level: str = "INFO"
    http_timeout_s: float = 5.0
    debug: bool = False

    @classmethod
    def from_env(cls, env: Mapping[str, str] | None = None) -> "Settings":
        env = os.environ if env is None else env
        errors: list[str] = []

        def get(name: str, default: str | None = None) -> str | None:
            value = env.get(name, default)
            if value is None:
                errors.append(f"{name} is required")
            return value

        db = get("APP_DATABASE_URL")
        level = (get("APP_LOG_LEVEL", "INFO") or "").upper()
        if level not in {"DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL"}:
            errors.append(f"APP_LOG_LEVEL invalid: {level!r}")
        try:
            timeout = float(get("APP_HTTP_TIMEOUT_S", "5.0") or "")
            if timeout <= 0:
                raise ValueError
        except ValueError:
            errors.append("APP_HTTP_TIMEOUT_S must be a positive number")
            timeout = 0.0
        raw_debug = (get("APP_DEBUG", "false") or "").lower()
        if raw_debug not in {"true", "false", "1", "0"}:
            errors.append("APP_DEBUG must be true/false/1/0")
        if errors or db is None:
            raise ConfigError("; ".join(errors))
        return cls(db, level, timeout, raw_debug in {"true", "1"})


request_id: contextvars.ContextVar[str] = contextvars.ContextVar("request_id", default="-")


class RequestIdFilter(logging.Filter):
    def filter(self, record: logging.LogRecord) -> bool:
        record.request_id = request_id.get()
        return True


_STANDARD = set(logging.makeLogRecord({}).__dict__) | {"message", "asctime"}


class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        payload = {
            "ts": self.formatTime(record, "%Y-%m-%dT%H:%M:%S%z"),
            "level": record.levelname,
            "logger": record.name,
            "msg": record.getMessage(),
        }
        payload.update({k: v for k, v in record.__dict__.items() if k not in _STANDARD})
        if record.exc_info:
            payload["exc"] = self.formatException(record.exc_info)
        return json.dumps(payload, default=str)


def configure_logging(level: str, stream: IO[str] | None = None) -> None:
    logging.config.dictConfig({
        "version": 1,
        "disable_existing_loggers": False,
        "filters": {"rid": {"()": RequestIdFilter}},
        "formatters": {"json": {"()": JsonFormatter}},
        "handlers": {"out": {"class": "logging.StreamHandler", "stream": stream or sys.stdout,
                              "formatter": "json", "filters": ["rid"]}},
        "root": {"level": level, "handlers": ["out"]},
    })


log = logging.getLogger("billing.worker")

if __name__ == "__main__":
    try:
        Settings.from_env({"APP_LOG_LEVEL": "LOUD", "APP_HTTP_TIMEOUT_S": "abc"})
    except ConfigError as e:
        print(e)
    s = Settings.from_env({"APP_DATABASE_URL": "postgresql://u:secret@h/db", "APP_DEBUG": "1"})
    print(s)
    configure_logging(s.log_level)
    request_id.set("req-42")
    log.info("charge created", extra={"charge_id": 7, "amount_cents": 1250})
    try:
        1 / 0
    except ZeroDivisionError:
        log.exception("charge failed", extra={"charge_id": 7})
    log.debug("not shown at INFO")
    logging.getLogger("billing.worker").info("user=%s n=%d", "ann", 3)
```

Observed output when run (timestamp and traceback path vary):

```text
APP_DATABASE_URL is required; APP_LOG_LEVEL invalid: 'LOUD'; APP_HTTP_TIMEOUT_S must be a positive number
Settings(log_level='INFO', http_timeout_s=5.0, debug=True)
{"ts": "...", "level": "INFO", "logger": "billing.worker", "msg": "charge created", "charge_id": 7, "amount_cents": 1250, "request_id": "req-42"}
{"ts": "...", "level": "ERROR", ..., "msg": "charge failed", "charge_id": 7, "request_id": "req-42", "exc": "Traceback (most recent call last): ..."}
{"ts": "...", "level": "INFO", ..., "msg": "user=ann n=3", "request_id": "req-42"}
```

What changed and why:

| Naive | Improved | Reason |
|---|---|---|
| Parse at import time | `Settings.from_env(mapping)` called once | No import side effects; tests pass a dict |
| `bool(os.environ.get(...))` | Explicit allowed values | `bool("false")` is `True` |
| First `KeyError` | All errors in one `ConfigError` | One deploy attempt shows every problem |
| URL in logs | `field(repr=False)` | `repr` hides the secret |
| `basicConfig` at import | `dictConfig` in `configure_logging` | One explicit configuration; library loggers keep working |
| `logging.error(e)` | `log.exception(..., extra=...)` | Traceback and structured fields |
| Global request id | `ContextVar` plus `Filter` | Per-request, concurrency-safe |

Design notes and limits:

- `_STANDARD` is computed from a blank `LogRecord`, so any other attribute on the record (from `extra=`) is emitted. Keys in `extra` must not collide with record attributes such as `message` or `name` (logging raises `KeyError`).
- `json.dumps(..., default=str)` prevents a non-serialisable value from crashing logging, at the cost of lossy output.
- Intentionally small: `structlog` or `python-json-logger` exist; choosing one is a team decision (VERIFY maintenance status). Understand the stdlib mechanics first.
- The sketch logs to stdout, the 12-factor convention for containers; the platform collects it.

## 5. Production perspective

**Maintainability.** Types, settings objects and logging conventions decay unless enforced: run `mypy` and tests in CI (Lesson 2.7).

**Correctness.** Types do not replace tests; a typed `Protocol` boundary keeps test fakes checked against the real interface (Lesson 1.4).

**Security.** Env vars are the *delivery mechanism*, not a vault: same-user processes and crash reporters can read them (`/proc/<pid>/environ`). Supply chain: pin, review, use hashes, run an audit tool such as `pip-audit` (VERIFY availability), and do not add a dependency to save ten lines. Never log request bodies by default.

**Operations.** Commit the lockfile; use `--locked` in the Dockerfile; pin the Python version; log to stdout; make `LOG_LEVEL` configuration. Startup validation makes bad deploys fail during rollout, not on the first request.

**What a senior engineer does differently.**

- Makes the environment rebuildable from the repo alone, and proves it by cloning into an empty directory.
- Treats `# type: ignore`, `cast` and `Any` as debt with a comment.
- Fails at startup for configuration errors and logs the *names* of invalid settings, never their values.
- Asks "what will I search for at 3 a.m.?" when designing logs.
- Matches the team's existing tools and conventions before proposing new ones.

**Common beginner mistakes.**

| Symptom | Cause | Diagnose |
|---|---|---|
| `ModuleNotFoundError` only in CI or on another machine | Package not installed, wrong venv, undeclared dependency | `which python`, `python -c "import sys; print(sys.path)"`, `pip list`, diff against the lock |
| Imports work in IDE, fail via CLI | `sys.path` differs; script run by path | Run `python -m package.module` from the repo root; print `sys.path[0]` |
| Shadowed stdlib module | Local file named `logging.py`, `types.py` | `python -c "import logging; print(logging.__file__)"` |
| `ImportError: cannot import name` | Circular import | Read the traceback from the bottom; draw the import cycle |
| Log lines missing | Handler/level misconfigured, `basicConfig` no-op, `propagate` | `logging.getLogger().handlers`, `.level`, `logger.propagate`, `logger.getEffectiveLevel()` |
| Duplicate log lines | Handler added twice (config function called twice) or both logger and root handlers | Count handlers up the hierarchy |
| mypy passes but production fails with bad data | Types do not validate external input | Validate at the boundary |
| Flaky install over time | Unpinned transitives | Install with `--locked` and compare the lock |

## 6. Failure laboratory

Mode A. This program is meant to run with debug logging off when `APP_DEBUG=false` and to enable debug output on request. Predict the printed `DEBUG` value, every line that appears on stderr, and the final print line, **before running**.

```python
# run-check
import logging
import os

os.environ["APP_DEBUG"] = "false"
DEBUG = bool(os.environ.get("APP_DEBUG", False))
print("DEBUG =", DEBUG)

log = logging.getLogger("app")
logging.warning("startup")                 # module-level helper
logging.basicConfig(level=logging.DEBUG)   # intended to enable debug output
log.debug("this is a debug message")
log.warning("this is a warning")
logging.getLogger().info("root info")
print(logging.getLogger().handlers, logging.getLogger().level)
```

Write your prediction. Then answer: (a) why is `DEBUG` what it is, (b) why does the debug line never appear, (c) how would you restructure to make logging configuration deterministic, and (d) how would you make the boolean parse safe?

### Reveal (read after predicting)

Output (stderr lines may be interleaved differently with stdout when both are redirected):

```text
DEBUG = True
WARNING:root:startup
WARNING:app:this is a warning
[<StreamHandler <stderr> (NOTSET)>] 30
```

(a) `bool("false")` is `True`: any non-empty string is truthy. (b) The first `logging.warning("startup")` call saw no handlers on the root logger and implicitly ran `basicConfig()` with defaults (WARNING level, stderr handler). The later `basicConfig(level=DEBUG)` found a handler already present and did **nothing**: the root level stays 30 (WARNING), so `debug` and `info` records are dropped. (c) Configure logging exactly once, early, at the entry point, with `dictConfig` (or `basicConfig(..., force=True)` in a script); never call module-level `logging.*` helpers before that; libraries must not call `basicConfig`. (d) Parse against an explicit set of strings as in `Settings.from_env`.

Systematic diagnosis for "my log line does not appear":

1. Is the logger level enabled? `log.isEnabledFor(logging.DEBUG)`, `log.getEffectiveLevel()`.
2. Walk the hierarchy: for `a.b.c`, inspect `a.b.c`, `a.b`, `a`, root: `.level`, `.handlers`, `.propagate`, `.disabled`.
3. Does at least one handler on that path have a level that passes the record? Does any filter drop it?
4. Was configuration applied twice or before another library configured the root? Print `logging.getLogger().handlers` at the start and end of startup.
5. Did `disable_existing_loggers` (default `True` in `dictConfig`) disable loggers created earlier? Set it to `False` explicitly.

## 10. Engineering review

Checklist:

- **Reproducibility.** Fresh clone, empty directory, documented commands, real output pasted; lock current (`uv lock --check`).
- **Types.** Strict-clean; every ignore justified; `Any` only at true boundaries; `Protocol` seams are the ones tests fake.

- **Logging.** One configuration point; no `print`, no f-strings in log calls; `exception` inside handlers; request id present; no secrets or PII.
- **Imports and tests.** No cycles or shadowing; isolation (no real environment or clock); error cases covered.

## 11. Mastery gate

Pass = 80/100 with **no critical failure**.

Critical failures:

- Any secret value appearing in `repr`, a log record, a test output or an exception message.
- Project not reproducible from a fresh clone (shown by `REPRODUCE.md` with real output).
- `mypy --strict` errors remaining, or blanket `# type: ignore` / `Any` used to silence them.
- Configuration read from `os.environ` outside the single startup point.
- Logging configured at import time, or by a library module.
